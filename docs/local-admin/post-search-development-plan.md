# 搜索交付后的开发计划：R7 会话配置核对

日期：2026-10-17（Asia/Shanghai）。源码基线：master `7f321a8c`。状态：设计完成，功能待开发。本次交付开发文档；下列页面、接口和测试用例均为实施契约，不表示已上线。

## 1. 当前基线与本轮目标

N1/N2、R1～R6、N3 已实现并合并部署。R5 提供命名模型独立参数，R6 提供 GPT/群总结独立入口，N3 提供 DeepSeek 搜索；搜索真实 QQ 验收及后续表单修正的验证范围见[自测](self-test.md)。已有电量提醒继续保留。历史记录中的“未部署”仅表示当次状态。

下一阶段延续原候选 R7：在一个已加载会话里核对影响 AI 使用的已保存配置，减少在响应、插件、人物、模型和搜索页面之间反复查找。此优先级来自现有页面分散的事实，不是使用频率统计。现有能力不重做，确切故障按实际影响插入修复。

交付目标：用户加载会话后点击一次，即看到范围明确、来源可解释的配置摘要，并能进入已有设置页修改。摘要只能解释配置，不能保证某条消息一定收到回复。

## 2. 范围与非目标

首批只做 R7，只读核对现有配置。纳入 N3 的搜索开关与角色列表，避免沿用搜索尚未实现时的旧设计。搜索配置读取不发起搜索，角色列表不等于某个发言者的实际授权结论。

不增加会话模型覆盖、自动选模、失败换模型、重试队列、向量库、定时发言、多 Agent、档案清理或新的备份体系。没有第二个实际使用点时，不抽象通用诊断框架。后续功能须有具体使用问题和独立验收条件，再进入下一批。

## 3. 用户流程与显示契约

1. 登录后台，进入“Agent 会话”，成功读取机器人和群/私聊。
2. 点击拟新增“核对会话配置”；目标取已加载范围，不取尚未读取的输入草稿。编号全程使用字符串。
3. 页面显示读取时间、明确的机器人及会话范围和下面的摘要。手动刷新重新读取，不轮询。
4. 需要修改时使用已有 AI、插件、人物及会话参数导航。保存仍在原页面显式完成，草稿沿用原提示。
5. 配置在别处修改后，用户重新读取核对结果；结果不声称实时同步。

| 摘要项 | 显示内容 | 来源及限制 |
| --- | --- | --- |
| 响应 | 全局/会话响应状态、运行时适用规则 | 群保持全局或群响应任一开启的规则；私聊按现有运行时核对，不能套用同号群 |
| 插件 | 普通聊天/Agent、GPT/群总结的注册及有效开关、默认或覆盖来源 | 不由模型配置推测插件状态；未注册与关闭分开 |
| 会话参数 | Agent 模式、@规则、概率、聊天温度、LLM 温度 | 会话参数由本实例机器人共享；GPT/群总结沿用现有 LLM 参数 |
| 模型 | 聊天、GPT、群总结、Agent、识图的模式、模型标识、继承及参数来源、本地配置问题 | 复用 R5/R6 解析；私聊的群总结标为不适用；不显示地址、密钥或提供商响应 |
| 人物 | 全局继承或当前机器人会话覆盖 | 按机器人与群/私聊隔离，仅显示来源，不展开人物正文 |
| 搜索 | 全局开关、当前会话开关、允许角色、密钥是否已配置 | 按机器人与群/私聊隔离；不展示密钥，不查询额度、不调用 Search |

读取中禁用重复读取按钮。失败显示已有简短错误，旧内容清除或明确失效，不能冒充新目标。切范围或退出后忽略迟到结果，复用页面现有请求生命周期。保留原时间线与未提交草稿，不建立全局状态容器。

## 4. 实现设计与代码落点

### 4.1 先核对真实读取语义

以 `internal/localadmin/ai.go` 的 `AIStore.Get` 和会话 ID 转换、`ai_persona.go`、`ai_models.go`、`ai_search.go` 以及 `third_party/zbputils/modelconfig/` 为现有配置来源。响应与插件状态沿当前后台和控制层读取路径追踪到运行时，先列出群/私聊对应关系，再写聚合接口；旧候选中的文件名不能代替实际源码定位。

人物和搜索按机器人隔离，原 AI 会话参数按会话共享，两者必须分开标注。读取不能调用会初始化配置、建表或保存默认值的路径。若已有读取器缺少所需信息，只在现有模块补小型只读方法，不模拟消息执行 Handler 来判断状态。

### 4.2 一个薄的只读接口

拟新增 `GET /api/agent/conversation-check`，由 `internal/localadmin/server.go` 注册并沿用后台认证。参数仅为 `botId`、`type`（group/private）、`id`，复用 `archiveID`、已连接机器人及会话校验规则。HTTP 边界解析一次，内部使用已解析类型。

拟新增 `internal/localadmin/conversation_check.go` 组装摘要。返回分区为 scope、observedAt、response、plugins、conversation、models、persona、search；确切字段名在实现时与现有结构统一。复用已有读取修订号，按来源返回，不把多个存储伪装为统一原子快照。

身份未认证、非法范围、机器人未连接及存储读取失败沿现有 HTTP 错误约定。显式坏模型引用在模型区显示配置问题，不能悄悄改用默认模型；真正的读取失败不伪装为关闭、零值或缺省。来源不适用与读取失败须能区分。

接口不保存、不创建备份、不读取会话正文或记忆、不请求 OneBot/模型/Search。只用已有内存连接状态与配置读取器，不为核对在线状态额外联网。复用现有缓存响应头策略，不引入聚合缓存、后台任务或跨存储事务。

### 4.3 页面接入

在 `internal/localadmin/assets/agent-archive.js` 和 `assets/index.html` 接入按钮及结果区，沿用现有纯文本渲染、范围冻结和 R2 导航。模型列表最多显示现有五个业务入口，搜索说明沿用现有角色名称。后台导航不自动触发 R3 模型诊断。

模型/人物显示来源即可；避免重复整张设置表。错误仍可见，320px 宽度和深浅主题可读，键盘能到达读取和跳转按钮。无需新增前端依赖。

## 8. 避免过度防御性编程的具体约束

- 只在 HTTP 和持久化读取边界做必要校验，内部复用类型与已有错误；不重复解析或层层判空。

- 优先使用现有存储及解析器，只为已证实的复用提取小函数；不新增表、不迁移数据、不构建通用诊断平台。
