## 2 用户行为与范围

在FTB工具页的最近任务区域加入“刷新任务状态”按钮。登录并已成功读取FTB配置后可用；每次点击只发起一次GET /api/ctb，用返回的busy和last更新任务展示。按钮处于配置表单之外，不能触发表单提交或浏览器必填校验。

刷新时保留全部表单输入、未保存提示和原配置修订号；允许用户继续编辑输入。刷新返回的config与revision不替换ctbState，也不参与后续保存。这样其他会话改过配置时，本地旧草稿保存仍会触发现有修订冲突，不能因为刷新状态绕过冲突保护。

“重新加载 / 放弃草稿”仍是显式读取配置并覆盖输入的操作；保存仍按现有校验、备份及修订逻辑执行。切换页面保留草稿。状态刷新按钮不执行搜索、下载、ZIP修复、文件投递、额度预留或配置保存，不增加后台API。

### 任务状态读法

| 返回情况 | 页面行为 |
| --- | --- |
| busy为true | 显示执行中及现有last文本；不编造进度或剩余时间 |
| busy为false且last有内容 | 显示空闲及最近任务摘要，保留后端原文含义 |
| busy为false且last为空 | 显示本次启动尚未执行任务；不推断历史任务失败或丢失 |
| 刷新失败 | 保留上次任务内容并提示“刷新失败，显示上次读取结果”，允许手动重试 |
| 未登录或已退出登录 | 不发送新的请求；清空本次页面会话状态，迟到响应不恢复旧内容 |

最近任务摘要反映核心任务执行状态，不是QQ上传或收件人下载确认。此限制放在任务区域和使用说明中，不改写历史实机结论。

实现以现有ctbGeneration和ctbBusy为基础，最多增加一个状态请求进行中标记及一个失效代次，不引入通用状态机或跨页面导航框架。配置读取、保存与状态刷新互斥：请求期间禁用对应操作按钮，代码入口也拒绝重复点击；状态刷新期间不锁定表单输入。串行化处理消除保存/刷新乱序，不新增自动重试或轮询。

离开FTB页时使未完成的状态刷新失效，返回页面不自动重复该请求；沿用现有首次进入读取配置的行为。退出登录使用resetCTB清理状态，请求结束时只有仍属于当前代次的finally才能恢复按钮。只在页面切换处接入最小清理逻辑，不改变其他页面的草稿行为。接口业务busy表示后台任务正在执行，前端请求busy只表示HTTP在途，不能混用。

错误交给现有api认证处理；刷新错误和提示写在任务区域，不覆盖配置保存错误、未保存文案或已加载配置。用textContent显示服务端摘要，不作为HTML插入。不要为可信响应再建立多层校验或自动补默认配置。

## 5 验收标准

| 编号 | 操作或条件 | 通过标准 |
| --- | --- | --- |
| A01 | 已加载页面点击刷新 | 恰好一次GET /api/ctb，无POST、无其他业务请求；busy/last按返回展示 |
| A02 | 修改所有输入后刷新成功 | 所有输入值、未保存提示及原ctbState.revision保持；任务摘要更新 |
| A03 | 刷新返回不同revision后保存旧草稿 | POST仍携带旧revision，服务端409时保留草稿；不把刷新收到的config写回 |
| A04 | 表单存在空值或非法数值 | 状态刷新仍可使用；不触发保存或浏览器表单校验 |
| A05 | 连点与操作互斥 | 状态刷新在途不重复请求，保存/重读不能并发；配置请求在途不能刷新；输入仍可编辑 |
| A06 | 网络或接口错误 | 保留上次任务内容，明确不是新结果；配置草稿、配置错误提示不被改写，可手动重试 |
| A07 | 离开页面或退出后返回迟到响应 | 旧响应不覆盖当前状态、不恢复旧会话内容、不错误启用新请求按钮 |
| A08 | 空状态、运行中、完成与失败摘要 | 各状态可区分；不把核心完成解释为QQ投递或用户收到；文本安全显示 |
| A09 | 已有保存与重读 | 成功保存、修订冲突保留草稿、显式重读覆盖草稿以及切页保留草稿原回归均通过 |
| A10 | GET只读 | 配置内容/修订、备份目录、群使用次数无变化；不启动本机下载进程，不调用OneBot或付费服务 |
| A11 | 桌面及手机 | 1280px和320px、明暗主题无横向溢出，按钮与反馈可见，键盘可操作 |
| A12 | 文档与上传 | 全量文档检查零错误；使用、计划、进度、验收和交付一致，远端SHA一致，不上传私有证据 |

A01～A09及A11通过现有离线浏览器测试验证，包含有控制的延迟响应和不同revision快照，不通过固定等待时间碰运气。A10通过隔离配置/备份/额度快照及模拟调用断言验证，沿用现有Go测试，不触碰日常实例。
