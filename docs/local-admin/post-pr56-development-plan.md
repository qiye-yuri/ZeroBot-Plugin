# PR56之后的开发计划：按请求类别筛选任务

日期：2026-10-28（Asia/Shanghai）。设计基线为codex/task-identity-filter的9da23f5c456c948ada9e7cfcac4b76d3092dd926，已核对origin一致。[PR #56](https://github.com/qiye-yuri/ZeroBot-Plugin/pull/56)为开放草稿，base codex/task-usage-table，依赖#55。两批已完成部署独立检查，真实非空及QQ收件待集中验收，当前2/5。本轮仅规划，不实现、不部署、不增加计数。

## 1 目标和范围

当前概览已区分GPT／群总结、普通聊天、Agent和识图的请求统计，但任务视图尚不能按类别缩小范围。下一批增加“任务包含的请求类别”，让用户在当前窗口查找包含某类请求的任务，并与标识、风险、结果、次数、关联和输出已知情况组合。

直接使用已有g.requests中的kind和分组结果，不修改采集字段、不重新分组、不增加接口、存储、费用估算、类别汇总表或报告字段。类别按接口请求记录解释，不推断QQ业务成功或任务完整性；历史预算900000及[其他待验收/暂缓项](remaining-acceptance.md)保持。

## 2 操作及匹配契约

未来入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量。沿用后台登录权限，实施并部署后刷新页面生效，无需保存配置。本轮说明入口只链接计划，不将新控件写成已上线。

新增原生select，标签“任务包含的请求类别”，ID为model-task-kind，位于风险筛选之后、请求结果之前，默认all、初始disabled。

| 值 | 显示文字 | 组级匹配规则 |
| --- | --- | --- |
| all | 全部类别 | 不增加类别限制 |
| gpt | 包含GPT／群总结请求 | 组内至少一条kind为gpt |
| chat | 包含普通聊天请求 | 组内至少一条kind为chat |
| agent | 包含Agent请求 | 组内至少一条kind为agent |
| vision | 包含识图请求 | 组内至少一条kind为vision |
| unknown | 包含未知类别请求 | 组内至少一条kind不属于上述四个已知值 |

已知值严格按既有小写枚举比较，不把GPT或不识别的新字符串自动归为gpt；缺失、null或其他未识别值按未知。这里是分类语义，不新增输入验证或清理原记录；原有数据合法性检查保持职责。一次组内some判断即可，不建立类别索引或缓存。

类别与标识及原有五类条件按组取交集，再排序。类别、请求结果和风险可以分别由同组不同请求命中，仍保留整个任务的所有窗口请求；不得先裁剪请求再计算次数、known或四字段小计。一个任务可同时包含多种类别，选任何命中类别只显示一次，不把它拆成多个任务。

追加帮助：“按任务内是否包含该类别请求筛选，仍保留整组请求；类别、结果和风险可由不同请求命中。”输入查询清空仅移除标识条件，类别保持；切换类别也不改标识或其他条件。不因组合无匹配自动恢复all或禁用选项。

## 3 固定样例与显示口径

A、B为有效关联组；C、D为独立请求。kind仅使用合成枚举，统计值不代表真实费用。

| 组 | 请求 | 输出 | 其他条件 |
| --- | --- | --- | --- |
| A | agent接口完成；vision失败 | 10；未知 | agent请求输入100命中大输入，vision请求输入1 |
| B | gpt接口完成 | 0 | 输入1 |
| C | chat接口完成 | 20 | 输入1 |
| D | kind缺失、结果未知 | 未知 | 输入1 |

全窗口4组5次，已知输出30 Token、已知3/5次。风险样例应用大输入阈值100。

| 条件 | 匹配组/请求 | 匹配输出小计 | 全窗口输出 |
| --- | --- | --- | --- |
| all | A/B/C/D，4/4组、5/5次 | 30 Token、已知3/5次 | 30 Token、已知3/5次 |
| agent或vision（分别选择） | A，1/4组、2/5次 | 10 Token、已知1/2次 | 保持 |
| gpt | B，1/4组、1/5次 | 0 Token、已知1/1次 | 保持 |
| chat | C，1/4组、1/5次 | 20 Token、已知1/1次 | 保持 |
| unknown | D，1/4组、1/5次 | 未知、已知0/1次 | 保持 |
| agent + failed + large | A，1/4组、2/5次 | 10 Token、已知1/2次 | 保持 |
| vision + independent | 无匹配，0/4组、0/5次 | 未知、已知0/0次 | 保持 |

补充：A的标识查询+agent保留A，B的标识查询+agent无匹配；single+vision无匹配，multiple+vision保留A；complete+vision无匹配，partial+vision保留A。输入/缓存三字段始终统计相同完整组且各自known，不能仅检查输出行。

未知类别测试同时覆盖缺失、null、不同大小写和未来未知字符串；同组同时含已知与未知类别时，两个条件各自都可命中该组，不修改原kind。组内多条同类别请求不重复计组。有效空窗口和无效窗口沿用现有提示；非空无匹配保留汇总表，匹配列未知0/0，全窗口不变。

## 4 生命周期、布局与导出

change事件只调用现有renderModelTaskView，不增加网络或模型请求。手动/自动刷新保留类别，按新快照重算；新增或淘汰请求改变类别命中时立即更新结果，不缓存旧分类。当前窗口最多256条，跨启动不沿用旧请求；仍可见同键任务保留展开和summary焦点，筛掉再出现默认收起。

阈值草稿不改变风险范围，应用/恢复默认阈值后保留类别及标识查询。重置任务视图恢复类别all、清空标识及其他默认条件/顺序并收起明细，保留阈值和草稿。读取失败清理结果并禁用控件，保留类别选择；恢复后继续筛选。离页、退出、认证失效及整页刷新恢复all，迟到响应不能恢复旧内容。

复用model-task-field布局及既有select样式，不增加CSS，除非实测有裁剪。键盘顺序：标识 → 风险 → 类别 → 结果 → 次数 → 关联 → 输出已知情况 → 排序 → 重置。检查320/640/768/1280px明暗主题，最长选项、44px高度、焦点边框和表格长整数；不隐藏标签或缩小点击范围。

完整JSON导出仍是整个快照、已应用阈值和taskBreakdown，version=1，不附加类别筛选状态，不裁剪请求。固定快照下类别/组合筛选/重置前后报告除exportedAt外一致；真实刷新造成checkedAt变化单独说明，用独立校验器核对实际下载。页面筛选不改变分类累计统计或历史预算。
