# 命名模型配置与入口选择

后台「AI 设置」中的「读取命名模型配置」用于管理可复用的模型配置，并为聊天/GPT/群总结、Agent、识图分别选择配置。需要本机后台登录权限及 AI 配置插件。

入口需要运行包含 N2 的新构建；源码上传不会自动升级日常服务。先按[运行维护](operations.md)准备升级与备份。

1. 点击「读取命名模型配置」。旧配置尚未迁移时，页面按原有字段生成预览；读取不写库、不调用模型。
2. 点击「新增模型配置」，填写名称、协议类型、接口地址、模型名与密钥。已有条目的密钥默认保留，可显式替换或确认清除；明文密钥不回传。
3. 在三个入口下拉框选择配置。聊天/GPT/群总结共用一个选择；Agent 与识图可以选择「不启用」。一个配置可以被多个入口共用，修改该配置会影响所有引用它的入口。
4. 点击「备份并保存命名模型」。配置列表和三个引用一次保存，先创建控制数据库备份。删除配置前须将所有引用改到其他配置或停用；改名称不会改变稳定编号。
5. 保存后新任务使用所选配置。进行中的 Agent 任务沿用现有设置代次检查，在下一检查点结束，不在多轮执行中静默换模型或重放动作。模型故障按现有错误流程返回。

非 OLLaMA 的在用配置需要密钥，清除前须将其入口改到其他配置或停用；未被引用的已有配置可以确认清除。模型表单草稿的新增、删除和密钥操作可整体放弃，恢复最近读取/保存的列表。

首次保存完成迁移；旧配置未迁移时继续按原字段运行。预览会按协议、地址、模型名与密钥的完整组合复用相同项，只有模型名相同不会合并。未配置的 Agent 或识图不生成有效入口引用。命名配置须有模型名、有效 HTTP/HTTPS 地址；非 OLLaMA 需要密钥。旧地址若嵌有认证参数，迁移前请将凭据移入独立密钥字段并更新地址。

启用命名配置后，模型类型、地址、模型名和密钥通过命名模型表单管理；原全局表单继续管理采样参数、系统提示词和全局人物。主人聊天命令仍可修改这些通用参数；旧模型字段命令会提示使用后台命名配置，避免修改无效的旧字段。

各表单独立保存。它们共用配置修订，另一个窗口或表单保存后遇到版本冲突时，重新读取并核对再保存。新密钥只保留在当前页面内存，退出或会话过期清空。

配置保存无需重启，也不会发起连通性测试或收费模型请求。页面基础检查只能验证字段，实际协议兼容和识图能力需要实际调用确认。显式引用丢失会报告配置错误，不会改用第一项或其他模型。

接口为 `GET /api/ai-models` 和同路径 `POST`。读取返回 `named`、`revision`、不含明文密钥的 `profiles` 及 `routes`。写入提供完整列表和路由，条目包含稳定 `id`、`name`、`type`（0/1/2）、`model`、`api`，以及 `key` 操作对象；保留为 `{"action":"keep"}`，替换附 `value`，清除附 `confirm:true`。路由键为 `chat`、`agent`、`image`，值是配置编号，后两项可为空。POST 沿用来源、CSRF 和修订检查。

回退旧程序前，在新程序后台预览并恢复迁移前的控制数据库，然后停止服务，换回旧程序再启动核对；恢复整个控制数据库会影响其中其他设置，先核对预览。步骤见[运行维护](operations.md)。
