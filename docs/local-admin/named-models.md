# 命名模型配置与入口选择

R6 开发分支提供 GPT 与群总结独立入口。升级到含 R6 的构建后，在命名模型表单分别选择它们的配置；默认“继承聊天模型”，使用聊天配置及其 R5 参数。显式选择后只影响对应入口，空值表示继承，不表示停用；Agent/识图空值仍表示停用。保存权限、修订、写前备份与新请求生效规则沿用原流程，温度与30秒额度仍由原LLM会话共用。

R5 开发分支增加每个命名模型的独立请求参数。升级到包含 R5 的构建后，在模型卡片展开“请求参数”，分别选择继承全局或自定义最大输出长度、TopP、推理设置；保存前仅为草稿，保存后新请求生效。同一配置的所有引用入口共用其参数，需要不同参数时新增配置。

最大输出长度可自定义为 1～131072，TopP 须大于 0 且不超过 1；这是程序校验范围，提供商仍可能有更严格限制。推理设置自定义为空表示使用现有协议的模型默认行为，选择继承则沿用全局文字。协议是否支持该值沿用现有适配，不自动纠正参数。温度仍由原会话参数决定。未设置或恢复继承无需迁移旧配置，不修改全局值；旧配置模式保持原规则。手动诊断输出长度仍固定 128，其 TopP 和推理设置跟随所选模型。

保存后可在同页“手动模型测试”分别核对聊天、GPT、群总结和 Agent 入口。每次点击发出一条可能计费的固定文字请求，使用保存版本，不使用表单草稿；配置修订变化后旧结果标为历史。工具循环、识图和 QQ 收发继续单独验证，见[手动测试说明](model-probe.md)。

主人私聊实机已验证：三个独立编号的临时配置保存后，GPT、Agent 与识图真实调用及平台回复通过，配置读取不回传明文密钥。三者沿用同一已配置提供商；测试后已恢复原来的旧字段模式及原模型选择，首次显式保存才迁移。见[实机验证](self-test.md#n1n2-主人私聊实机验证)。

后台「AI 设置」中的「读取命名模型配置」用于管理可复用的模型配置，并为聊天、GPT、群总结、Agent、识图分别选择配置。需要本机后台登录权限及 AI 配置插件。

本机日常服务已于 2026-10-16 部署 N2，重新登录后台后可使用入口；日常配置未自动迁移，原模型选择保持。首次“备份并保存命名模型”才迁移。其他安装需运行包含 N2 的新构建，先按[运行维护](operations.md)准备升级与备份。

1. 点击「读取命名模型配置」。旧配置尚未迁移时，页面按原有字段生成预览；读取不写库、不调用模型。
2. 点击「新增模型配置」，填写名称、协议类型、接口地址、模型名与密钥。已有条目的密钥默认保留，可显式替换或确认清除；明文密钥不回传。
3. 在五个入口下拉框选择配置。GPT与群总结分别可选择「继承聊天模型」或指定配置；Agent 与识图可以选择「不启用」。一个配置可以被多个入口共用，修改该配置会影响所有引用它的入口。
4. 点击「备份并保存命名模型」。配置列表和五个引用一次保存，先创建控制数据库备份。删除配置前须将所有引用改到其他配置或停用；改名称不会改变稳定编号。
5. 保存后新任务使用所选配置。进行中的 Agent 任务沿用现有设置代次检查，在下一检查点结束，不在多轮执行中静默换模型或重放动作。模型故障按现有错误流程返回。

非 OLLaMA 的在用配置需要密钥，清除前须将其入口改到其他配置或停用；未被引用的已有配置可以确认清除。模型表单草稿的新增、删除和密钥操作可整体放弃，恢复最近读取/保存的列表。

首次保存完成迁移；旧配置未迁移时继续按原字段运行。预览会按协议、地址、模型名与密钥的完整组合复用相同项，只有模型名相同不会合并。未配置的 Agent 或识图不生成有效入口引用。命名配置须有模型名、有效 HTTP/HTTPS 地址；非 OLLaMA 需要密钥。旧地址若嵌有认证参数，迁移前请将凭据移入独立密钥字段并更新地址。

启用命名配置后，模型类型、地址、模型名、密钥及独立请求参数通过命名模型表单管理；原全局表单继续管理默认采样/推理参数、系统提示词和全局人物。模型卡片显示读取版本的参数来源和有效值，修改后标为表单草稿；其他窗口修改全局值后需重新读取。主人聊天命令仍可修改全局默认参数；自定义覆盖保持，只有选择继承的模型字段随全局改变。旧模型字段命令会提示使用后台命名配置，避免修改无效的旧字段。

各表单独立保存。它们共用配置修订，另一个窗口或表单保存后遇到版本冲突时，重新读取并核对再保存。新密钥只保留在当前页面内存，退出或会话过期清空。

配置保存无需重启，也不会发起连通性测试或收费模型请求。页面基础检查只能验证字段，实际协议兼容和识图能力需要实际调用确认。显式引用丢失会报告配置错误，不会改用第一项或其他模型。

配置后的显式验证可使用[真实模型测试脚本](real-model-test.md)：只读预检及 `-run` 已支持当前命名引用，测试开始固定选择，不再只读取遗留字段。Agent/识图未选择时，对应测试用例会在请求前拒绝；普通聊天用例可单独选择。该工具使用隔离实例与合成 OneBot，真实提供商请求可能消耗额度，不等于真实 QQ 客户端验收。

接口为 `GET /api/ai-models` 和同路径 `POST`。读取返回 `named`、`revision`、不含明文密钥的 `profiles` 及 `routes`。写入提供完整列表和路由，条目包含稳定 `id`、`name`、`type`（0/1/2）、`model`、`api`，以及 `key` 操作对象；保留为 `{"action":"keep"}`，替换附 `value`，清除附 `confirm:true`。路由键为 `chat`、`gpt`、`summary`、`agent`、`image`，值是配置编号。`chat`必选；`gpt`/`summary`缺失或空值继承聊天，`agent`/`image`空值停用。GET的`entries`返回五入口实际`profileId`、`inherited`和有效`parameters`，不包含密钥。POST 沿用来源、CSRF 和修订检查。

R5 条目新增可选 `parameters` 对象：`maxN`、`topP`、`reasoningEffort`。对象或字段缺失/null 表示继承，`{"reasoningEffort":""}` 表示明确的空推理设置，不能替换为 null。POST 提交完整列表，省略原覆盖即恢复继承。GET 同时返回每条 `effectiveParameters` 和全局 `parameterDefaults`；结合覆盖字段是否为空可核对来源，所有数值按一次配置读取解析。示例：`{"parameters":{"maxN":8192,"topP":0.7,"reasoningEffort":""}}`。

回退旧程序前，在新程序后台预览并恢复迁移前的控制数据库，然后停止服务，换回旧程序再启动核对；恢复整个控制数据库会影响其中其他设置，先核对预览。步骤见[运行维护](operations.md)。
