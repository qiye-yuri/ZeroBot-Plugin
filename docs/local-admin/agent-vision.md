# Agent 识图输入与等待限制

## 配置与使用

登录本机后台，在“AI设置”填写识图接口类型、地址、模型名和对应密钥，并保存；已有 Agent 接口也须完整配置。后台密码持有者可以修改全局配置，QQ 全局配置仍仅机器人主人私聊可改，群主/管理员不能因此修改接口或密钥。后台保存后，后续任务使用新设置，无需新增开关。

在已响应且 aichat 插件、Agent 模式已启用的群或私聊，同时发送实际 QQ 图片段和文字提问。群聊沿用 @ 与概率触发规则，例如 @机器人并说“请描述图片中的形状”。纯图片可能不满足已有文字触发条件；本机路径文字和网页后台上传图片不会成为 QQ 图片输入。普通 `/gpt` 和纯文字聊天沿用原流程，本次没有新增其识图处理。

程序先生成简短图片描述，再把描述放入当前机器人、当前会话的 Agent 上下文，由 Agent 决定后续动作。识图不增加发送或群管理权限，仍使用已有角色白名单；它不占用三次历史与记忆查询额度。图片内容会提交到配置的识图服务，可能计费；后台基础配置检查不代表模型实际支持图片或已验证描述准确性。

## 新构建的输入限制

| 项目 | 实际限制 |
| --- | --- |
| 来源 | QQ 图片段中的 HTTP/HTTPS 地址或 `base64://` 数据；本机文件路径不读取 |
| 下载等待 | 每次 HTTP 下载最多 10 秒，包含重定向、连接、响应头与正文读取；正常网络客户端更短的限制仍可先触发 |
| HTTP 响应 | 仅处理状态 200；失败、空正文或读取不完整时跳过当前图片 |
| 图片数据 | 每张最多 8 MiB，即 8,388,608 字节；HTTP 透明解压后的正文也受限制，未提供长度或分块传输不能绕过 |
| base64 输入 | 解码前限制编码文字长度，解码后仍检查 8 MiB 上限；无效或空数据跳过 |
| 解码尺寸 | 完整解码前先读取尺寸，宽高须为正且各不超过 8,192 像素，面积不超过 16,777,216 像素 |
| 模型输入 | 合格图片仍按原流程缩放至最多 1,024×1,024，再生成描述；不是精确 OCR 承诺 |
| 识图 HTTP 响应 | 当前宿主最多向解析器提供 256 KiB，即 262,144 字节，包含协议 JSON；未知长度最多额外探测 1 字节以识别超限。声明长度、分块传输和透明解压后的响应都受限，错误响应同样有界 |
| 图片描述 | 先去除首尾空白；空白、非法 UTF-8 或含 NUL 的结果不附加且不缓存。每张最多 4,000 UTF-8 字节，超长内容只保留完整字符组成的开头片段 |

下载超时、超限、解码失败或不支持的来源不会调用当前图片的识图模型，也不会为失败图片缓存描述。其余图片及文字继续按原 Agent 流程处理，因此收到文字回复不能证明所有图片都已识别。多张图片及上下文中的历史图片分别处理，10 秒不是整个任务或停止请求的总时限。

相似图片描述缓存仍沿用原逻辑。需要先加载及解码图片计算相似度，缓存命中可以减少识图模型请求，不能保证省掉图片下载；后续准备上下文也可能重新加载保留的历史图片。模型识图请求另沿用 30 秒客户端超时，后台停止仍不能立即撤回在途下载、模型或平台动作，边界见[任务控制](agent-tasks.md)。

新构建先在 256 KiB 上限内完整收取未知长度的模型响应，再交给协议解码；分块响应不得仅凭开头合法 JSON 提前采用描述。等待结束仍受原 30 秒客户端超时限制，超限或读取/关闭错误均跳过本次描述，不附加或缓存，也不自动重试。该行为无需新增配置，HTTP 完整结算与内容有效性分别核对，见[模型统计](model-request-statistics.md#统计口径)。

新构建会在图片下载和识图调用前后检查当前任务及设置代次。准备期间已登记停止时，当前在途请求结束后不再处理后续图片或调用 Agent 模型；识图请求在途返回后发现停止，不为该结果新增描述缓存。检查点不立即中断当前请求，也不构成任务总超时，具体步骤和计数限制见[准备期间停止](agent-tasks.md)。

## 描述片段与失败恢复

识图模型返回多个纯文本片段时，新构建按协议输出顺序直接拼接，再执行空白、字符和 4,000 字节描述检查；不会插入协议标签或额外分隔符。多段超长中文也只保留完整字符，并在缓存中保留截断标记。入口、权限和保存后生效规则与上述配置相同，无新增开关。

缺失输出、未知类型、文本与图片等非文本混合输出，以及响应解析或内容提取阶段的 panic，均跳过本次图片描述；即使前段有正常文字也不附加、不缓存。下一次需要识图时仍可重新请求，成功后正常缓存；本次 HTTP 不自动重试。响应适配器共享纯文本检查和合计 1 MiB 的 SDK 保护，当前宿主更早受 256 KiB HTTP 上限约束，最终描述上限仍为 4,000 字节。此保护仅覆盖响应解析与提取，不捕获其他业务阶段异常。

超长描述会附带截断标记，缓存同时保留该标记，后续相似图命中时仍明确为片段。模型提示会说明省略部分不能当作已识别事实；这不保证模型回答一定正确，细节仍需核对。已有描述也重新检查空白、字符有效性及长度，原来已标为截断的片段不会被当作完整描述。

空白或无效结果不会占用成功描述缓存；后续图片或新任务仍可再次识图。超过响应读取上限时跳过本次图片描述，不把截到一半的 JSON 当作有效结果，其余图片和文字继续按原规则处理。未新增同一次 HTTP 的自动重试；准备历史图片本来就可能重新下载或识图，不能把这些请求当作新重试策略。正常描述恢复后仍可按原相似缓存复用。

HTTP 200 返回空白描述时，模型统计仍可能记为 HTTP 完成，但不表示取得有效识图结果；响应超限则计为请求失败，不伪装成完成。识图失败不自动等于整个 Agent 任务失败，正常文字流程仍可能完成，任务动作/查询次数也不会把识图准备算为本地动作。每张描述上限不是完整上下文或 token 上限，历史正文计数仍按识图前记录测量，详见[任务摘要](agent-tasks.md)。

当前宿主传给模型的图片段使用 __agent_desc__ 保存描述，截断时另有字符串 __agent_desc_truncated__=true；正常描述不保留旧截断标记。这些结果用于本轮输入与进程缓存，不改写持久档案原图记录，也不落为长期记忆。修改全局 AI 配置或重启后缓存按原规则重新建立。识图请求失败的调试日志只显示失败类别，不输出接口返回正文。

## 失败后核对

如果任务长时间停留在“等待模型（含上下文准备）”，先手动读取任务状态，核对[阶段开始及停止请求时间](agent-tasks.md)。减少图片数量，换用较小图片，并确认 QQ 图片地址仍可访问、识图模型支持图片。超大分辨率须先缩小原图，单纯压缩文件到 8 MiB 以下可能仍超过像素限制。不要从模型的文字猜测推断图片已成功识别。

输入失败的内部错误类别不携带下载地址、HTTP 错误正文或 base64 数据；会话档案仍沿用原有脱敏和保留规则，不表示磁盘清理。此功能随新构建生效，未增加后台上传、重试按钮、自动重发或新权限；日常服务已于 2026-10-16 部署。合成纯色图片的[真实识图链路](self-test.md#真实模型链路验证)已通过，其他真实图片的识别效果尚未验收。
