# R5：命名模型独立请求参数

本批基于已合并 R1～R4 的主分支开发，范围来自[下一批规划 PR #7](https://github.com/qiye-yuri/ZeroBot-Plugin/pull/7)。本文记录R5批次；R6的GPT/群总结独立入口已在本分支后续实现，见[R6说明](r6-model-routes.md)，R7会话只读核对仍待后续开发，N3 联网搜索继续暂缓。当前分支提供此功能，上传不代表已经部署日常服务。

## 使用范围

后台登录后，在“AI 设置”读取命名模型，展开模型卡片的“请求参数”。最大输出长度、TopP、推理设置分别选择继承全局或自定义，显示读取版本的来源与有效值。保存前是草稿，使用现有整体放弃、修订冲突及写前备份流程；保存后新请求生效，无需重启。

| 字段 | 自定义 | 继承 |
| --- | --- | --- |
| 最大输出长度 | 1～131072 | 全局 MaxN，0 按原规则使用 4096 |
| TopP | 大于 0 且不超过 1的有限数值 | 全局 TopP，0 按原规则使用 0.9 |
| 推理设置 | 保留原协议文字；自定义空字符串使用现有协议默认行为 | 全局 ReasoningEffort |

一个配置被多个入口引用时，这些入口共用覆盖。需要不同参数就新增命名配置，不增加多层继承。聊天、GPT和群总结仍共用聊天入口；温度仍来自各自原会话参数。识图响应/描述上限、Agent动作和上下文额度、HTTP期限、提示词及人物不因覆盖改变。参数范围不代表提供商接受所有取值，不自动重试或更换模型。

旧配置模式继续使用全局参数，无自动迁移。旧命名条目缺少参数也全部继承；对象或字段 null 与缺失等价，自定义空推理字符串保留区别。删除覆盖后重新继承。具体操作、接口格式和升级回退见[命名模型](named-models.md)及[运行维护](operations.md)。

## 实现落点

| 工作包 | 实现 |
| --- | --- |
| R5-01 | `modelconfig.Parameters` 保存可选覆盖，`Resolve` 合并为值快照；`chat.ModelProfile`及仓库复用原整组保存、校验、修订和备份 |
| R5-02 | `/api/ai-models` 返回覆盖、全局默认及有效参数；原模型卡片增加原生折叠区与逐项来源选择 |
| R5-03 | 聊天、Agent、识图、GPT/群总结使用所选参数；保存沿用原 Agent 设置代次与缓存清除，不重放在途任务 |
| R5-04 | R1 预检显示有效参数，隔离实例分别保存各入口参数；R3 诊断保留128输出上限，TopP及推理设置跟随入口 |

不新增模型客户端、第三方SDK、任意JSON参数或厂商能力表。数值及文字检查集中在配置输入边界，内部使用已解析的值快照。

## 验证与交付

专项核对缺省/null继承、显式空推理、共享配置、三个入口不同参数、全局值保持、撤销覆盖、非法数值/类型、版本冲突、写前备份恢复及重启重读。三种协议使用本地模拟提供商核对实际请求；最终构建的隔离流程核对GPT、聊天、Agent和识图参数。离线Chrome覆盖保存、冲突草稿、放弃、键盘折叠及320px深浅布局。

统一入口仍为 `pwsh -File scripts/test-agent.ps1 -OutputName zerobot-r5-validation.exe`，包含纯参数包测试。最终结果、已测和未测范围见[自测记录](self-test.md#r5-模型独立参数验收)。真实服务调用、真实QQ及正式部署均需分别记录，不能以模拟测试替代。
