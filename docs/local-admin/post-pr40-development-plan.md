核对日期：2026-10-27（Asia/Shanghai）。基线为master `c1990629`。PR #40已完成开发、部署验收及合入，范围见[最终验收清单](pr40-deployment-acceptance.md)。本批实现、相关回归、最终构建、部署验收及PR #41合入已完成，最终状态见[验收清单](task-outcome-acceptance.md)。下文保留设计契约与规划阶段记录。历史预算900000、其他待验收及暂缓项保持。

## 1 目标与源码依据

任务视图已有风险筛选、精确小计排序、摘要与按需展开，但用户查找失败或提前关闭的请求时仍需逐项阅读正文。下一批增加一个“任务包含的请求结果”筛选器，快速缩小任务范围，同时保留任务内的完整窗口上下文。

| 已核对位置 | 当前职责 | 本批处理 |
| --- | --- | --- |
| [stats.go](../../internal/modelstats/stats.go) | 已结束请求写入completed、failed、incomplete三类outcome | 只使用现有数据，不修改采集和后端 |
| [overview.js](../../internal/localadmin/assets/overview.js)中的selectModelTaskGroups | 风险筛选和小计排序 | 增加请求结果条件，与原风险条件组合 |
| 同文件renderModelTaskView、resetModelTaskView及change处理 | 重绘、控件可用性、选择和展开状态清理 | 接入一个select，沿用原生命周期 |
| 同文件modelTaskUsage、modelTaskRequestsText、buildModelUsageReport | 分组、正文及完整导出 | 保持数据、正文和报告契约 |
| [index.html](../../internal/localadmin/assets/index.html) | 任务风险筛选与排序入口 | 在两者之间加入请求结果筛选和简短组合规则说明 |

本批不增加错误原因推断、失败重试、任务成功判断、请求级隐藏、结果计数面板、搜索或状态持久化。接口完成不等于回复正确、QQ收到或整个任务成功；风险提示与接口传输结果是两个独立维度。

## 2 产品与筛选契约

入口保持“运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量”，沿用原登录权限。新控件标签为“任务包含的请求结果”，默认“全部结果”，仅处理已读取的最近最多256条已结束业务请求；没有“进行中”选项，不把累计请求统计当作任务窗口数据。

| 值 | 选项文字 | 匹配任务的条件 |
| --- | --- | --- |
| all | 全部结果 | 不限制结果 |
| completed | 包含接口完成请求 | 组内至少一个outcome严格等于completed |
| failed | 包含失败请求 | 组内至少一个outcome严格等于failed |
| incomplete | 包含提前关闭请求 | 组内至少一个outcome严格等于incomplete |
| unknown | 包含未知结果请求 | 组内至少一个outcome不在上述三个已知值中，包括缺失或空值 |

“未知”不自动归入失败；不修改原字段，不为未知值补造结果。提前关闭与失败分开，不从耗时、Token缺失、风险标签或QQ回复统计反推结果。每组选中后仍展示该组全部窗口内请求，包括其他结果的请求；摘要小计不变，不能把它误写成仅匹配请求的小计。

### 与风险筛选组合

两项条件在任务级取交集：任务既包含符合风险条件的请求，也包含符合结果条件的请求即可入选，两次命中可以来自不同请求。这个选择保持原风险筛选“任一请求命中就显示整个任务”的含义，不引入隐含的请求级裁剪。

例如合成任务内请求A是大输入且接口完成，请求B是小输入且失败：选择“大输入”及“包含失败请求”仍显示该任务，展开同时显示A和B。界面说明须明确“两个条件分别在任务内判断，可能由不同请求命中；展开保留全部请求”，不能声称A就是失败的大输入请求。没有有效关联标识的独立请求只包含自身，因此自然要求同一请求满足两项条件。

排序在组合筛选后进行，复用原整数比较、同量稳定顺序和未知排后规则。匹配任务数使用组合后的组数，分母保持当前窗口总组数；原无匹配、空窗口、数据不可用三种状态保持。

## 3 生命周期与实现约束

控件沿用原生select、明确label和键盘操作，不增加自定义下拉组件。默认值、禁用和重置与现有风险/排序控件一起维护。

| 操作 | 预期结果 |
| --- | --- |
| 初次进入或重登 | 结果为全部，任务默认收起 |
| 更改结果、风险或排序 | 用当前快照立即重算；不发起新请求；仍可见的同键任务保持展开 |
| 阈值草稿 | 不重算结果或风险，不改变展开 |
| 应用阈值或恢复默认阈值 | 重算风险组合；结果选择保持，与现有风险选择保持行为一致 |
| 同页刷新成功 | 使用新快照，保留三个选择及仍可见的展开状态；自动刷新摘要焦点保持 |
| 任务被筛掉后再返回 | 默认收起，复用PR40行为 |
| 跨启动 | 选择沿用同页刷新规则，旧展开键不继承；统计窗口不累加 |
| 读取失败或无效数据 | 清空正文并禁用结果控件，保留当前选择；恢复有效数据后重新计算 |
| 离页、退出、认证失效 | 结果重置全部，旧明细和展开状态清除 |

优先在selectModelTaskGroups内增加一个简单结果谓词；如扩展参数，放在现有settings参数之后并默认all，避免破坏现有调用。结果值集合是页面内固定选项，不建立通用过滤表达式、注册表、数据迁移或版本兼容层。模型/结果文本继续按原方式安全渲染，不增加HTML拼接。

buildModelUsageReport、格式version=1及离线校验器不变：结果筛选、风险筛选、排序和折叠只影响视图。requests与taskBreakdown始终导出完整快照，阈值仍为已应用值；结果选择不进入报告。最多256条记录直接遍历，不添加缓存、索引、预取、重试或全局异常兜底。必要校验沿用现有边界，不扩展到无关模块。

## 5 验收矩阵

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| B01 | completed、failed、incomplete混合任务 | 各条件按包含关系匹配，选中组保留所有请求；不推断任务成功 |
| B02 | 缺失、空值、未知字符串与有效结果 | 未知单独匹配，已知结果不误归未知，原字段不修改 |
| B03 | 大输入完成请求与小输入失败请求同组 | 组合筛选仍命中；分开到不同组则不能交叉拼出匹配任务 |
| B04 | 跨会话同任务号、独立项、小计精度 | 分组隔离和精确小计保持；独立项按自身条件匹配 |
| B05 | 组合筛选、排序及空状态 | 匹配数准确、同量稳定、未知排后；无匹配不等于无请求 |
| B06 | 阈值草稿、应用及恢复默认 | 草稿不生效；应用重算风险；结果选择不被意外重置 |
| B07 | 新快照、跨启动、失败、恢复、离页和认证失效 | 三控件遵循上表规则，无旧明细和跨启动展开残留 |
| B08 | 鼠标、键盘、自动刷新、窄宽屏及明暗外观 | 新控件可访问、焦点不被抢走、仍可见任务保持展开；隐藏后重现收起，无溢出 |
| B09 | 筛选/排序/折叠前后真实浏览器下载 | 相同快照除exportedAt外报告相同，独立校验通过；切换条件不增加网络请求 |
| B10 | 最终程序及部署身份 | 最终构建和完整隔离测试通过；备份可核对，程序与静态资源对应验收源码 |
| B11 | 实际后台非空窗口操作与下载 | 复用日常已有请求完成结果选择、组合筛选、无匹配、恢复、刷新和下载校验；确认默认恢复 |
| B12 | 审查、上传与合入 | 只提交本批源码/测试/公开说明；源码一致性与远端SHA核对通过，验收清单明确证据边界 |

失败、提前关闭及未知样本用本地合成数据覆盖，不在日常服务故意制造断流或改配置。实机优先复用自然请求；只有完成请求也能验证包含/不包含、风险组合与导出，但不能据此声称真实失败链路已经验收。非空实机部分没有可用样本时保持待验收，不用离线回放代替；需要用户配合时遵守[空闲时段要求](../../AGENTS.md#真实模型测试时间与费用约束2026-10-23)，发送QQ消息须另有明确授权。
