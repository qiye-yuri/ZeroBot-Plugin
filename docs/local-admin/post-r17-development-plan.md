## 1 当前状态与问题

两页目前在input事件中直接写“有未保存更改”，没有与已加载表单比较。把值改回原值后仍显示有更改；查看状态虽已不会覆盖草稿，但恢复表单只能使用“重新加载 / 放弃草稿”，需要一次GET，在更新监控忙碌时还可能失败。

R18提供准确的未保存字段摘要，以及恢复到最近成功读取/保存后页面基线的本地操作。目标是帮助用户判断和撤销当前编辑，不确认服务端是否已被其他会话修改，也不替代revision冲突检查。

依据：[FTB脚本](../../internal/localadmin/assets/ctb.js)、[更新监控脚本](../../internal/localadmin/assets/updatewatch.js)、[页面结构](../../internal/localadmin/assets/index.html)。已有[AI未保存字段摘要](ai-draft-fields.md)提供“仅字段名称、与页面基线比较”的产品约定；本批不复用其密钥、作用域和多表单框架。R17部署结果见[验收](self-test.md#r17-合并部署验收)。

## 2 用户行为与作用范围

每页配置表单显示“无未保存更改”或“未保存字段：N项”，并按固定顺序列出名称。只显示字段名称，不显示旧值、新值、路径、账号、公告正文或差异内容。没有成功加载配置时显示“读取配置后可编辑”，不创建空配置基线。

在表单附近增加type=button的“撤销本页更改”，说明“恢复到本页最近读取或保存成功的值，不读取服务器、不保存配置”。仅已登录、有基线、有改动且无本页请求时可用。点击立即恢复本页全部可编辑字段；不增加确认弹窗、后台写入或浏览器刷新保护。此操作不是逐步撤销历史，也不恢复上一次未保存草稿。

“重新加载 / 放弃草稿”继续请求服务器并覆盖表单；本地撤销不替代该入口。服务器可能已有更新，本地撤销后仍使用原revision，保存冲突依旧要求用户核对并显式重读。

| 操作 | 表单基线与摘要 | 请求与运行状态 |
| --- | --- | --- |
| 首次配置读取成功 | 完整渲染后记录表单基线，摘要清空 | 原GET；正常显示运行摘要 |
| 编辑字段或改回原值 | 实时比较，改回后移除对应字段，全部改回则清空 | 无新增请求 |
| 保存成功 | 按响应渲染后的表单重新记录基线 | 原POST和写前备份保持 |
| 保存失败或409冲突 | 保留旧基线、输入及改动摘要 | 原错误反馈保持 |
| 独立状态刷新成功或失败 | 不改基线、摘要、revision或配置选项 | 仍仅更新运行区域及其反馈 |
| 撤销本页更改 | 恢复本页基线值并清空摘要，保留原revision及选项 | 零请求；最近运行结果与刷新反馈保持 |
| 配置重读失败 | 旧基线、输入和摘要保持 | 不提前清空草稿 |
| 切页或退出 | 切页保持；退出清除输入、基线与摘要 | 沿用R16/R17迟到失效规则 |

本地撤销不清除配置错误来暗示已经解决服务端问题；用独立草稿反馈说明已恢复输入。服务端冲突或忙碌提示仅在后续原读取/保存流程中更新。不同页面的草稿互不影响。

## 3 字段比较与实现落点

基线记录成功响应完整渲染后的DOM值，而不是原始JSON：这样现有默认选项、唯一机器人自动填入等渲染行为不会在首次读取时产生假改动。复选框比较checked布尔值，其余控件比较value原始字符串；不先trim、Number转换、排序、去重或规范化换行之外的内容。保存请求仍沿用现有转换规则。空字符串、非法数值输入和空白编辑也能被提示并撤销。

使用静态字段表定义控件ID及中文名称，顺序按表单排布；每个控件只计一次。仅记录可编辑值，不比较按钮、帮助文案、运行状态、下拉显示名称或候选列表。日期时间等控件比较浏览器实际value，不实现跨浏览器的自定义输入格式。

| 页面 | 纳入比较的字段 |
| --- | --- |
| FTB | 启用、群权限、群发送位置、每日群次数、程序路径、下载目录、下载超时、并行数、禁用代理、自动发送 |
| 更新监控 | 启用、每日时间、间隔、模型入口、主人、机器人、三个来源开关、关联仓库、公告链接 |

| 源码落点 | 实施内容 |
| --- | --- |
| internal/localadmin/assets/ctb.js | 页面内字段表、读取/比较/恢复值和渲染摘要；成功读取/保存后更新基线，reset时清空 |
| internal/localadmin/assets/updatewatch.js | 同样处理本页字段，保留选项和原revision；不把运行刷新视为配置加载 |
| internal/localadmin/assets/index.html | 两页草稿摘要、独立反馈和本地撤销按钮；沿用现有布局样式 |
| scripts/test-ctb-ui.mjs、scripts/test-updatewatch-ui.mjs | 扩展既有离线测试，断言摘要、原始值、请求数和另一页/运行状态保持 |
| docs/local-admin/ctb.md、updatewatch.md、user-guide.md、README.md | 实施后增加操作、比较基准、撤销范围及冲突限制 |
| progress.md、self-test.md、github-delivery.md及本计划 | 更新实现、验证、上传、合并与部署记录 |

每页仅保存一份表单基线；使用现有busy、generation和认证状态。配置请求期间保留摘要，但撤销按钮不可用；状态刷新时输入仍可编辑，摘要随输入更新，撤销按钮暂不可用。直接调用撤销函数也应遵守这几个现有边界。网络结果过期时不能更新基线或清空新会话摘要。

不新增后端接口、数据库、localStorage、跨页面通用框架、自动保存、撤销栈或草稿导出。不改变服务端校验、修订、权限、备份、调度或下载额度。只抽取各页面实际需要的少量函数，避免把同样简短的字段比较扩展成可配置组件系统。

## 5 验收矩阵

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 初次读取含默认回填和唯一机器人候选 | 基线取最终DOM，零改动，撤销不可用，无重复GET |
| A02 | 逐项修改两页全部字段并改回 | 字段名称及数量准确且顺序固定；改回自动移除，全部还原后零改动 |
| A03 | 空白、多行、无效数值或空账号 | 以DOM原始值比较，可提示和撤销；不触发保存校验或自动规范化 |
| A04 | 本地撤销 | 所有值恢复基线、摘要清空、零GET/POST，revision和选项保持，运行内容与反馈保持 |
| A05 | 另一页也有草稿 | 撤销当前页不修改另一页输入或摘要，切页仍保留 |
| A06 | 状态刷新含不同config/revision | 不更新基线，编辑摘要保持；状态刷新结束后撤销仍回到原基线 |
| A07 | 保存/重读成功及失败 | 成功采用响应渲染值并重建基线；409/网络/忙碌失败保留原基线和草稿，错误不被本地撤销虚假清除 |
| A08 | 撤销后服务端已经改过配置 | 保存仍携带旧revision；现有模拟409保留本地数据，不把本地恢复称为服务器最新值 |
| A09 | 在途、离页、退出及迟到响应 | 操作按钮与入口限制一致；输入可编辑的状态刷新期间摘要实时更新；退出清空，旧响应不更新新基线 |
