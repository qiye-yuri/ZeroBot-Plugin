# PR49之后的开发计划：按窗口内已知输出量排序

日期：2026-10-28（Asia/Shanghai）。设计基线为master `aa35924ddadb918eae4fff1f305b9cc70b82f15a`，已核对origin/master一致。PR #46～#49已完成集中验收并依次合入，当前QQ配合队列0/5，见[最终记录](task-request-coverage-acceptance.md#四项合入收尾2026-10-28)。本轮仅交付设计文档，下述功能尚未实现，不计入待验收队列。

## 1 目标与优先级

现有任务视图支持风险、结果和次数筛选，以及原顺序、请求次数、输入量和未命中量排序。输出Token已在每组摘要中汇总，但需要人工逐组比较。下一批增加“窗口内已知输出量降序”，帮助定位输出较多的任务，复用已有数据，不增加模型调用。

优先完成这一项的开发、独立验证和部署。需要用户单条QQ配合的部分进入累计队列，等待满5项统一验收；后续经用户授权的开发可继续累计。不要为了凑满5项把测试、文档、主题或窗口宽度拆成独立验收项，也不预先虚列其余四项功能。

历史预算900000及[既有待验收和暂缓项](remaining-acceptance.md)保持原状。输出量不是费用、耗时、任务完成度或回复质量，不新增这些推算。暂不安排持久化排序、多字段排序、报表变更或后台接口扩展。

## 2 操作与行为契约

未来实现入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量 → 排序。沿用后台登录权限，无额外角色配置。嵌入资源需重新构建部署，刷新页面后生效；本计划不提前将新选项写成现有使用步骤。

- 新选项值使用`output`，显示“窗口内已知输出量降序”。默认仍为原顺序。
- 从已完成筛选的任务组中，按`g.totals.output.value`降序排列。沿用已有十进制字符串与BigInt比较，避免转Number损失精度。
- 数值为0是已知值，排在全部未知之前；null表示整组没有已知输出，排在已知值之后。两个未知组以及数值相同的组保持原有相对顺序。
- 部分请求缺失输出时使用已有已知部分合计，不补零，不估算；摘要继续保留“已知k/n次”。已知部分合计相同则保持原序，不增加完整度次级排序。
- 排序只重排任务组，不重排组内请求，不修改原快照或原始分组数组。风险、结果、次数条件继续按既有组级交集计算。
- 匹配任务数与匹配任务内窗口请求数不变。独立请求、跨会话任务隔离、重复请求id及最近最多256条窗口继续使用现有分组语义。
- 输出Token缺失不会让请求退出计数，结果为失败也不必然表示输出为0；排序不按outcome推造用量。

固定样例按原序排列A、B、C、D、E：A输出10（已知1/2），B输出0（1/1），C输出未知（0/1），D输出20（1/1），E输出10（1/1）。输出降序应为D、A、E、B、C；筛选掉D后为A、E、B、C。并列的A和E不因完整度不同而换位。

## 3 生命周期及兼容范围

选择排序立即在本地重绘，不新增网络请求。手动和自动刷新用新快照重新排序；同键仍可见任务沿用现有展开及焦点保持。任务消失或失去有效关联键时遵循现有行为，不新增跨快照缓存。

费用阈值草稿不改变筛选结果；应用阈值后按新匹配组重新排序，输出合计本身不因阈值变化。重置任务视图恢复原顺序、全部筛选并收起任务，保留已应用阈值及草稿。

读取失败、恢复、跨启动、离页、退出和认证失效沿用既有生命周期。未知窗口继续禁用现有任务控件，有效空窗口保持当前空态；不为新增选项另设错误页或重试机制。

JSON报告继续导出完整快照，不随页面排序或筛选裁剪，也不新增排序状态字段、格式版本或导出类型。对固定快照，除导出时间外报告内容应一致。
