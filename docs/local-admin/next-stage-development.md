## 3. R1：真实模型测试跟随当前配置

### 行为与边界

默认预检继续只读、不发模型请求，显示旧配置/命名配置模式、各入口实际模型及是否启用，地址沿用脱敏方式，密钥不输出。显式 `-run` 才运行原有用例，继续使用合成 OneBot 和隔离实例。

命名模式按稳定配置 ID 解析聊天、Agent、识图入口，复用 `third_party/zbputils/chat` 已有模型解析逻辑。旧配置保持原行为；显式选中的用例缺少所需入口时，在开始请求前报告缺项，不回退到遗留字段，不把跳过记为通过。

测试开始时解析一次实际配置，固定为本次快照。隔离实例可将解析结果映射到原测试格式，但报告须说明这验证的是实际提供商链路；命名列表保存和路由绑定仍由现有 N2 隔离整机覆盖。七类用例和原有 CLI 参数保持。

### 工作包与验收

| 编号 | 工作与代码位置 | 完成条件 |
| --- | --- | --- |
| R1-01 | 核对 `scripts/test-real-model.go`、chat 模型解析、`internal/adminqa/`，替换配置读取/解析路径 | 旧模式、命名模式、入口停用均正确；不写日常控制库 |
| R1-02 | 构造旧字段与命名字段故意不同的测试配置，模拟三个入口服务 | 实际请求使用命名地址、模型和凭据，旧字段对应服务零请求 |
| R1-03 | 更新预检和报告，脚本测试接入 `scripts/test-agent.ps1` | 预检零外部请求；失效引用、缺项有明确退出码；文档移除过时限制 |

必须覆盖旧配置、命名配置、入口停用、引用缺失、只读预检及配置快照；日志与报告不泄露凭据，读取不创建备份。真实提供商验证单列实际范围，不把模拟 OneBot 写成真实 QQ 收发通过。

同步[真实模型测试说明](real-model-test.md)、[命名模型说明](named-models.md)。只有确实出现第二个调用点时才提取小函数，不为脚本引入配置框架。

## 4. R2：从会话直接进入配置

### 最小使用流程

“Agent 会话”成功加载机器人及群/私聊后，提供“设置此会话人物”和“设置此会话 AI 参数”。点击进入现有 AI 设置页面，填入并读取该目标；表单标题显示实际范围，保存由用户点击原保存按钮完成。

目标绑定已加载会话，不能取尚未提交的输入；QQ ID 使用字符串。目标页存在相关未保存草稿时复用放弃提示，取消跳转保留草稿。快捷入口仅导航与读取，不增加保存接口。

准确展示作用范围：人物覆盖按机器人 + 群/私聊隔离；现有 AI 会话参数按群/私聊保存，并非机器人独享。不能因为选了机器人就将共享参数展示为账号专属。私聊只提供现有支持的参数，不扩展响应开关或插件权限编辑。

### 工作包与验收

| 编号 | 工作与代码位置 | 完成条件 |
| --- | --- | --- |
| R2-01 | `assets/agent-archive.js`、`assets/index.html` 为已加载范围加入入口 | 未加载不可用；选择草稿不改变跳转目标 |
| R2-02 | `assets/ai.js`、`assets/app.js` 复用页面切换、`loadAI` 与人物读取 | 正确传递机器人及群/私聊；草稿提示一次，无自动保存 |
| R2-03 | Chrome 用例、相关 API 回归和使用说明 | 同号群/私聊、不同机器人、取消跳转、失败及窄屏均通过 |

完成标准：已加载会话到可编辑表单只需一次点击；范围可核对，保存请求目标准确。读取失败不以旧会话内容冒充新目标；复用现有退出和迟到响应处理，不建跨页状态框架。

无需数据库迁移、新聚合接口、会话收藏或浏览器持久化。同步[会话人物](conversation-persona.md)、[AI 会话参数](ai-conversations.md)、[会话档案](agent-archive.md)与[使用指南](user-guide.md)。

## 5. R3：后台手动测试已保存模型

### 首版范围与使用行为

AI 设置的配置检查旁提供“测试聊天模型”和“测试 Agent 模型”，按钮明确标注会调用提供商、可能消耗额度。只发送固定短文字并验证返回可解析且非空；Agent 入口也只测基础文字调用，不执行动作。识图、完整工具循环和 QQ 收发沿用原专项测试。

只测试已保存入口，复用旧/命名配置解析。表单草稿不进入请求；显示测试入口、模型、配置版本、时间和耗时。配置更新后旧结果标为历史结果；结果仅保留当前页面，不新增数据库表、日志正文或长期报表。

### 请求与实现约定

拟增加受后台认证、来源及 CSRF 保护的 POST 测试接口。输入仅为入口 chat/agent 和已读取配置修订，不接收任意 URL、密钥、自由提示词或聊天正文。服务端读取并核对修订，再固定本次快照；版本不符提示重读。

复用已有协议构造与 HTTP 封装，使用 30 秒期限、协议支持的短输出参数，并在解析边界限制响应体 256 KiB。返回脱敏模型标识、耗时与简短结果；区分网络失败、HTTP 拒绝和解析失败，不回传提供商原始错误正文。

每个后台实例最多一个测试在途，重复操作提示等待。优先复用现有请求门控，确需新增时只加一个在途门控，不建队列或自动重试。退出页面清除结果，在途请求按原期限结束，不声称费用被撤销。

测试使用独立短生命周期客户端，不计入现有四类业务模型累计统计；本卡片明确这是诊断调用。无需为此扩大统计分类或观察报表，后续有实际需要再规划历史诊断记录。

### 工作包与验收

| 编号 | 工作 | 完成条件 |
| --- | --- | --- |
| R3-01 | 后台测试接口与最小调用实现，复用 R1 核对后的解析 | 旧/命名模式一致；停用、缺项、失效引用和修订冲突不发请求 |
| R3-02 | AI 页面加入显式按钮、请求中提示和结果卡片 | 保存/读取不触发测试；草稿不进入调用；重复点击不重复发起 |
| R3-03 | 模拟三类既有协议成功、错误、超时与非法响应 | 单次请求准确，失败如实显示；业务统计、控制库、备份数量保持 |
| R3-04 | 新增使用文档并纳入统一回归 | 隔离整机完成界面/API到模拟服务验证；实机按实际范围记录 |

一次成功仅证明本次基础模型调用可用，不以固定措辞判成功，不给“Agent 全功能正常”的结论。预计修改 `internal/localadmin/`、`assets/ai.js`，必要的小请求函数放在已有 `internal/modelrequest/`；不修改业务调度或自动模型选择。

## 7. 执行顺序与测试出口

第一批：R1-01～03 → R2-01～03 → 最终构建与统一验收 → 文档和上传。第二批：R3-01～04 → R4-01～03 → 相同交付流程。R4 可独立提前交付，真实服务等待不阻塞其他离线实现。

| 测试层 | 重点 | 执行时机 |
| --- | --- | --- |
| Go/脚本 | 模型实际解析、失败退出、只读行为；R3 请求与修订 | 对应模块完成后 |
| 浏览器 | R2 范围与草稿；R3 显式调用；R4 操作入口 | 对应页面完成后 |
| 隔离整机 | 合成配置对应实际请求，原聊天/Agent/备份回归 | 每批最终构建后 |
| 真实接口 | 实际提供商兼容与测试体验 | 明确现有凭据和用例后，仅执行约定范围 |
| 文档 | 文件引用、标题锚点、规划/实现状态及差异 | 每批提交前 |

功能批次统一入口：

```powershell
go generate main.go
pwsh -File scripts/test-agent.ps1 -OutputName zerobot-usability-validation.exe
git diff --check
```

R1 的新脚本测试及新增页面用例须接入统一入口，不能用旧数量冒充本次覆盖。记录命令、退出码、构建身份及未测范围。自动化使用合成资料与模拟服务；真实 QQ、提供商调用和部署分别记录，已取消的历史验收不自动重开。

## 8. 范围控制与完成标准

1. 第一批完成即可交付，第二批或新想法不变成首批门槛。
2. 外部输入和持久化边界校验一次，内部使用已有类型；保留权限、修订与会话隔离，不重复解析或吞掉错误。
3. 只抽取已有两个调用点的小函数；不新增配置中心、事件总线、任务编排、插件框架或复杂缓存。
4. 不做联网搜索、定时发言、向量知识库、自动模型切换、多 Agent 或档案物理清理；本阶段不设计数据库迁移。
5. 每项使用行为变化同步说明和索引；本规划不能作为已上线指南。
6. 按[GitHub 交付规则](github-delivery.md)显式暂存，用中文提交推送用户 origin 并核对远端。功能分支使用 `codex/model-test-routing`、`codex/conversation-shortcuts` 等；上传不自动部署或合并。

初次规划仅修改文档；R1/R2 功能交付执行对应脚本、页面、最终构建及隔离整机验证。真实提供商调用、真实 QQ 和日常部署分别记录，不能以模拟或文档完成替代。
