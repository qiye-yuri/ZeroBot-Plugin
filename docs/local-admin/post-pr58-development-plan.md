## 1 目标与边界

现有任务明细能查看单次接口耗时，但查找当前窗口最慢的请求所在任务仍需逐组展开。下一批增加“窗口内最慢请求耗时降序”，并在每个任务摘要展示相同口径的最慢已知值和已知次数，使排序依据可见。

只使用已有g.requests中的milliseconds；不新增采集、后端接口、存储、慢请求阈值、任务时长求和、均值/百分位、首字节或QQ延迟指标。最大单次耗时不代表任务墙钟时间、完整任务耗时或费用；历史预算900000及[其他待验收/暂缓项](remaining-acceptance.md)保持。

## 2 入口与数据契约

未来入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量 → 任务排序。沿用后台登录权限，实施并部署后刷新页面生效，无保存动作。本轮只增加规划入口，不宣称新选项可用。

在原有排序选项之后新增value=slowest，文字“窗口内最慢请求耗时降序”；默认仍为原记录顺序，其他五种排序保持。先应用现有标识、类别、风险、结果、次数、关联和输出已知情况筛选，再对匹配完整组排序，不删除组内请求。

组级耗时摘要返回最慢已知milliseconds、known及count：

- 有效单值沿用PR #58和完整报告口径：Number.isFinite(value)且value>=0。有效0计为已知，不用truthy判断，不将字符串或null转换成数值。
- known为有效耗时请求数，count为组内完整请求数；至少一条已知时取其中最大原始值。全部未知时milliseconds为null，known为0。
- 非负有限小数合法，最大值从原值比较，不先舍入；极大有限值也保留，不通过相减比较以免产生无穷大差值。
- 失败、提前关闭及结果未知的请求，只要耗时有效也参与；耗时有效与Token字段完整性互相独立。不按结果或命中类别先裁剪请求。

排序为已知最大值从大到小；全部未知组置于末尾。相等原值保持原分组顺序，全部未知之间也保持原顺序；已知0排在全未知之前。只排列新选出的数组，不修改源groups或请求顺序，不按任务ID、结果或已知次数打破同值并列。

## 3 摘要与显示口径

在任务摘要的结果统计行之后、用量提示计数之前增加一行：“窗口内最慢已知接口耗时：N ms（已知k/n次）。”；全未知显示“窗口内最慢已知接口耗时：未知（已知0/n次）。”。每个任务固定显示，方便切换不同排序时仍能核对；不把耗时加入四字段Token汇总表。

显示与单次明细一致，toFixed(0)四舍五入到整数毫秒，原始值不变。有限极大值可使用JavaScript原生科学计数法表示，不封顶、不转BigInt。小于0.5的已知值显示0 ms属于舍入；两个组显示同样整数仍可能因未舍入值不同而排序不同。

追加简短帮助：“按组内最慢的已知单次接口耗时排序，使用未舍入原值；未知排最后，不代表任务总耗时或QQ延迟。”保持单次明细既有口径。筛选无匹配时不显示任务摘要；有效空/无效窗口沿用原提示，不生成0 ms占位。

### 固定样例

A～F按原顺序出现，关联身份仅使用合成标识：

| 组 | 原始耗时ms | 最慢已知值 | 已知次数 | 摘要显示 |
| --- | --- | --- | --- | --- |
| A | 1200、未知 | 1200 | 1/2 | 1200 ms |
| B | 0 | 0 | 1/1 | 0 ms |
| C | 1200、20 | 1200 | 2/2 | 1200 ms |
| D | 未知、未知 | null | 0/2 | 未知 |
| E | 1199.6 | 1199.6 | 1/1 | 1200 ms |
| F | 0.4 | 0.4 | 1/1 | 0 ms |

slowest期望顺序A、C、E、F、B、D。A/C同原值保持原顺序；E虽显示1200仍排在它们之后；F虽显示0仍排在B之前。另补两个全未知组保持原顺序、两组有限极大值比较和负数/字符串/NaN/Infinity不计known的用例。

A的一条请求命中类别/风险，另一条命中结果时，仍按A完整两条请求求最大值及known。标识、关联、次数和输出已知情况不改变口径。排序前后匹配组数/请求覆盖、四字段匹配与全窗口小计、原组内明细顺序全部保持。

## 4 生命周期、布局及完整报告

沿用现有select/change/render流程，切换排序只本地重绘，不新增网络或模型请求。手动/自动刷新保留选择并按新快照重算最大值；同键仍可见组保持展开和summary焦点，即使组位置变化也不丢焦点。当前最多256条窗口，早期最慢请求被淘汰后必须重新排序，跨启动不保留旧值。

阈值草稿不改变匹配范围，应用/恢复默认阈值后保留排序及查询。重置视图恢复原顺序、清空查询及默认筛选并收起明细，保留阈值和草稿。读取失败清理旧摘要并禁用控件，恢复后用新快照重排；离页、退出、认证失效及整页刷新恢复默认，迟到响应不能恢复旧排序。

沿用原生select和summary分行样式，无新增控件或Tab位置。验证320/640/768/1280px明暗主题，最长新选项、摘要新增一行、长标识/模型及极大值；保持44px操作区域、可见焦点和数字完整换行。仅在实际裁剪时局部调整，不整体改版。

完整JSON报告保持version=1及现有requests/taskBreakdown，不新增最大耗时、known或排序字段。固定快照与阈值下排序/筛选/重置前后除exportedAt外一致，真实刷新checkedAt变化单独说明；用独立校验器核对实际下载，不把摘要舍入值写回报告。
