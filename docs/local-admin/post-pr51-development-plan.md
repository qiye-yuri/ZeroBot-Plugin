## 1 目标与范围

已有任务视图能按风险、结果、次数和关联类型筛选，也能按已知输出量排序，但查看匹配范围的输出总量仍需逐组相加。下一批在匹配任务数、请求覆盖统计之后，增加“匹配任务已知输出”和“全窗口已知输出”两行摘要，分别显示Token小计和有有效输出值的请求数。

复用modelTaskUsage已生成的groups、count、totals.output.value和totals.output.known。只汇总现有任务组，不重新扫描原始请求或解析关联标识；风险与结果可能由组内不同请求命中，匹配小计始终包含匹配组的全部窗口请求。有效关联与独立请求使用同一汇总口径。

本批作为一个功能交付，不把两行摘要拆成多个QQ验收项。不新增用量占比、费用估算、全历史查询、输入/缓存汇总面板、存储或报告字段。历史预算900000及[其他待验收/暂缓项](remaining-acceptance.md)保持，不自动开始额外功能。

## 2 展示与计算契约

计划入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量。沿用后台权限；功能实施并构建部署后刷新页面生效，无保存操作。本轮只添加规划入口，现有使用步骤继续以[模型统计说明](model-request-statistics.md)为准。

在现有覆盖统计后添加两行纯文本，按下列格式设计：

```text
匹配任务已知输出：30 Token（已知2/3次）。
全窗口已知输出：30 Token（已知3/5次）。
```

“匹配任务”行的分母为所有匹配组的count合计；“全窗口”行分母为value.count。两行的已知次数均只计算有效输出字段，不使用输入/缓存完整性、请求结果或提示数量推断。原匹配任务数X/Y和请求覆盖N/M继续显示。

| 场景 | 显示规则 |
| --- | --- |
| 至少1次输出已知 | 合计已知值并展示十进制整数及Token单位，附已知k/n次 |
| 已知值全部为0 | 展示0 Token，k必须大于0；不误写为未知 |
| 匹配组非空、输出全未知 | 匹配任务已知输出：未知（已知0/n次）；不补0 Token |
| 非空窗口但没有匹配组 | 匹配任务已知输出：未知（已知0/0次）；保留原无匹配提示及全窗口小计 |
| 有效空窗口 | 沿用“暂无近期请求，任务用量未知。”；不追加虚构两行小计 |
| 无效/缺失统计窗口 | 沿用未知窗口提示，不使用上次小计 |

补一条简短口径：“仅合计已返回的有效输出Token；未知不补零，不代表完整用量或费用。”不展示百分比，避免将两个部分已知的小计当作实际用量占比；不要求缓存分项一致才计入输出。输出值的有效性沿用现有汇总规则：非负安全整数才算已知，单值无效仍未知，多个有效值相加可超过Number安全整数范围。

累加使用BigInt，输出转换为十进制字符串，禁止通过Number、parseInt或浮点转换已有字符串合计。known是现有窗口内计数，直接相加。只对已有非null的value做BigInt累加；最终known为0时显示未知。使用已有合法汇总对象，不重复校验每个分组、不捕获异常后补零。

### 固定样例

A为有效关联组，2次请求，输出10与未知；B为有效关联组，1次请求，输出20；C和D各为独立请求，分别输出0与未知。窗口共4组5次，已知3次、合计30 Token。

| 条件 | 匹配组/请求 | 匹配输出 | 全窗口输出 |
| --- | --- | --- | --- |
| 默认全部 | 4/4组、5/5次 | 30 Token，已知3/5次 | 30 Token，已知3/5次 |
| 有效关联 | 2/4组、3/5次 | 30 Token，已知2/3次 | 保持30 Token，已知3/5次 |
| 独立请求 | 2/4组、2/5次 | 0 Token，已知1/2次 | 保持全窗口值 |
| 有效关联且至少2次 | 1/4组、2/5次 | 10 Token，已知1/2次 | 保持全窗口值 |
| 独立请求且至少2次 | 0/4组、0/5次 | 未知，已知0/0次 | 保持全窗口值 |

为A分别设置一条命中风险、另一条命中结果，组合条件保留A整组，输出仍为10、已知1/2次。风险命中次数即使重叠也不重复累加；同一请求只属于一个既有分组。额外测试全未知组、已知0组以及两次MAX_SAFE_INTEGER相加为18014398509481982。

## 3 生命周期、报告与布局

筛选改变时随现有renderModelTaskView重算匹配行；全窗口行始终基于同一快照的全部groups。五种排序均不改变两行数值，展开/收起不改变范围。重置恢复全组，匹配值应与全窗口值相同，阈值草稿和已应用阈值沿用现有规则。

阈值草稿不重算匹配；应用或恢复默认阈值后随风险交集重算。手动/自动刷新使用新快照，保留现有条件，同键可见组展开和焦点保持。256条窗口淘汰后重算，跨启动不能带入旧小计。失败/未知时清空旧内容；离页、退出和认证失效仍由现有流程清除，不增加缓存或状态变量。

JSON完整导出继续包含整个快照和既有taskBreakdown，version=1及校验器不变。新摘要是页面派生信息，不写入报告；固定快照和阈值下，除exportedAt外，切换筛选前后报告应一致。摘要也不触发额外网络或模型请求。

优先复用modelTaskUsageText的换行文本和现有容器。先验证320/640/768/1280px明暗主题、长整数换行及全选复制；只在出现实际裁剪或横向溢出时局部修样式，不压缩字体、不增加卡片或新控件。保持现有五个选择框和重置按钮的键盘顺序，无需新焦点节点。
