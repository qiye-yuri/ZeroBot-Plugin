## 1. 目标与范围

下一阶段优先解决两个使用问题：不同群希望采用不同 Agent 人物设定；不同 AI 入口希望明确选择模型配置。先实现可理解、可回退的配置能力，再依据实际使用需求决定是否接入联网工具。

当前已具备会话档案、历史和记忆检索、记忆修订、任务停止与状态核对，不重新实现这些能力。现状与限制以[上阶段设计](ai-agent-development.md)、[使用指南](user-guide.md)、[人物设定](ai-persona.md)为准。

本计划建议首批仅包含 N1、N2；N3 为独立候选，不是首批交付条件。定时自主发送、向量知识库、多 Agent 编排、自动模型评分/切换、档案物理清理暂不开发。未经使用验证不增加新筛选器、新任务状态或可配置的容量开关。

初次交付物是本文及文档入口、进度和验证记录；功能实现按下面工作包推进，分阶段测试并上传。上传不自动触发日常服务部署。

## 2. 开发原则：避免过度防御性编程

1. 沿用现有 Go 服务、SQLite/控制配置、原生后台页面及已有模型客户端，不引入配置中心、工作流引擎或通用插件框架。
2. 外部输入在 HTTP、模型工具和持久化读取边界检查一次；内部调用使用明确类型，不层层重复解析、判空、复制或恢复。
3. 保留会话隔离、身份权限、密钥脱敏、并发修订检查、现有请求期限和容量限制。这些有实际用途；不为假想故障新增多级兜底、自动重试、隐藏默认值或异常吞并。
4. 配置显式选错就返回可定位的错误。模型请求失败沿用现有错误路径，不能静默换模型或重放发送、保存记忆等动作。
5. 优先复用现有配置读写和页面保存流程。出现第二个实际调用场景后再提取共用逻辑，不预建接口层或泛化策略体系。
6. 测试围绕可见行为、数据一致性和已存在的边界；不为简单样式、文档修改或实现细节编写镜像测试。
7. 每个工作包达到约定验收条件即收尾。新增需求单列，不能把无限补充边界案例当成持续开发目标。

## 4. N1：按会话覆盖 Agent 人物设定

### 使用行为

后台选中机器人及群/私聊后，可以选择“继承全局”或“自定义”。自定义时编辑人物设定与性别；显示当前生效值及来源。保存后影响该会话的新任务，原档案和长期记忆保留。切回继承删除该会话覆盖，以后跟随全局变化。

本批只覆盖 Agent 人物字段。普通聊天、GPT 和群总结的系统提示词保持独立，页面说明这个作用范围。人物文本不能提升调用者的动作权限。

### 数据和生效设计

- 以现有机器人 ID + 群/私聊会话键保存覆盖，不使用只有群号的全局键。复用控制配置存储；不建独立人物模板库。
- 覆盖为可选对象，包含人物文本与性别；不存在即继承。自定义人物文本去除首尾空白后不能为空；恢复继承使用明确操作，不靠空字符串隐式猜测。
- 人物文本长度沿用现有全局字段限制；若现有字段没有限制，本批不单独创造一套群级限制。性别沿用已有取值规则。
- 统一解析规则为“该会话覆盖 → 全局设定 → 当前源码默认值”，默认值只用于原有未配置情形。
- 任务开始时获取一次生效配置快照；进行中的任务不混用新旧人物。保存生效方式应与现有设置代次/停止机制一致，不能另建并发控制系统。
- 全局人物命令仍只修改全局；本批不增加群命令。后台复用已有登录和写权限、修订冲突处理及备份流程。
- 旧配置缺少覆盖字段时直接继承，无需批量改写会话、迁移记忆或清理档案。

### 工作包与验收

| 编号 | 工作 | 可验收结果 |
| --- | --- | --- |
| N1-01 | 会话键、覆盖存储及有效值解析 | 两个机器人下同号群、群与私聊互不影响；旧配置与当前行为一致 |
| N1-02 | 接入 Agent 任务准备 | 模拟模型实际收到所选人物；全局修改只影响继承会话的新任务 |
| N1-03 | 后台表单、继承说明与保存 | 自定义、保存、撤销、恢复继承完整可用；修订冲突不会覆盖新值 |
| N1-04 | 使用文档与整机回归 | 更新人物说明、AI 设置说明和统一验证；重启后覆盖保留 |

完成判定：继承、自定义、恢复继承三条主流程通过；进行中任务、会话隔离和重启持久性验证通过。仅切换人物不会自动发送消息或修改记忆。

## 5. N2：命名模型配置与按入口固定选择

### 使用行为

后台维护少量有名称的模型配置，每项包含稳定 ID、显示名、现有协议类型、地址、模型名和密钥；为普通聊天/GPT/群总结、Agent、识图分别选择配置。首批普通聊天/GPT/群总结共用一个选择，避免一次引入过多开关。

这里只做显式选择，不做按内容智能路由、失败切换、负载均衡、价格比较或按群模型覆盖。识图是否适用由实际配置与验证说明，不能仅凭模型名称推断。

### 数据、迁移与请求设计

- 配置列表和入口引用放入现有配置仓库；引用使用稳定 ID，改显示名不改引用。禁止删除仍被引用的配置，提示先改入口选择。
- 从旧配置读取时，缺少新列表就沿用旧路径；用户首次保存新配置时，将现有普通模型、Agent 和识图配置映射到对应项目并一起保存引用。相同配置可以复用同一项，不能仅凭相同模型名合并。
- 迁移前沿用现有控制数据库备份；写入与引用更新同一次完成，失败不留下半套配置。读取不会自动写入。
- 后台从不回传明文密钥；留空表示保留旧密钥，清除使用明确操作，复用当前密钥编辑约定。新建项目缺少必要凭据时按现有协议要求返回错误。
- 入口解析集中在一个函数，返回已有客户端需要的配置结构。任务启动时固定所选模型配置；多轮执行不因后台编辑而切换模型。
- 配置检查只验证现有协议支持和必需字段；保存不自动请求付费服务。“测试连接”若实现，必须为单独的显式操作并说明会调用模型。
- 请求统计复用现有口径；只有确实需要区分配置时才补充非敏感 ID/名称，不持久化密钥或完整请求正文。
- 已保存的显式引用若不存在，明确报配置错误；不静默选择第一项或换成默认模型。

### 工作包与验收

| 编号 | 工作 | 可验收结果 |
| --- | --- | --- |
| N2-01 | 配置列表、引用及旧配置兼容 | 旧配置直接运行；首次保存迁移、备份恢复及引用校验通过 |
| N2-02 | 统一解析并接入三个入口类别 | 模拟服务准确收到各入口指定的协议、模型和请求；不会串用密钥 |
| N2-03 | 后台列表和入口选择 | 新增、编辑、改名、删除未引用项与引用冲突提示可用 |
| N2-04 | 新任务快照、统计核对和使用文档 | 进行中任务模型固定；后续任务采用新配置；错误按原口径统计 |

完成判定：原单模型配置兼容；三个入口选择和重启持久性通过；模型失败不会导致重复动作。回退复用原后台备份流程：在新程序中预览并恢复迁移前控制数据库，然后停止服务，换回旧程序再启动核对；不能声称旧程序可以直接读取所有新配置。实际步骤见[维护说明](operations.md)。

## 6. N3：联网搜索原候选设计（已按新计划恢复）

2026-10-17已确定DeepSeek Search并恢复实施，下文保留原候选约束，现行参数和范围以[实施计划](deferred-web-search-design.md)为准。

原前置条件：明确实际搜索服务、凭据来源、费用预期和允许使用的会话。没有这些信息时，只保留设计，不安装依赖或选择收费供应商。

最小方案是一个只读搜索工具：接收查询文本，返回标题、链接和摘要，由 Agent 在回答中标明来源。先不抓取任意网页、不执行网页脚本、不下载附件。复用现有工具权限、请求超时及结果容量机制；网页内容仅作为资料，不能变成工具权限或系统指令。

工作顺序：确定提供商 → 接入单一适配函数 → 明确可调用角色与会话开关 → 模拟正常/超时/空结果 → 经授权验证真实搜索与引用 → 编写用法。测试关注引用对应性、失败不捏造结果和不可跨会话读取配置。搜索配额单独命名，不能挤占已有历史/记忆三次共享查询额度；具体上限随提供商约束确定。
