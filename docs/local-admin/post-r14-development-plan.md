## 2 目标与范围

R15完成后，开发者在仓库根目录执行一条命令，即可检查公开管理文档的本地文件链接和Markdown锚点，并看到可定位的错误；工具可在无机器人、无浏览器、无提供商凭据的环境运行。

检查源为Git跟踪的 docs/local-admin 下Markdown及根README.md、AGENTS.md。暂存新增文件后纳入检查；报告说明文件选择范围，不将未跟踪的私有笔记扫描入内。目标可以是仓库内的已跟踪文档、源码或目录；链接到忽略目录、本机绝对路径或仓库外目标报错。根相对路径按仓库根解析，相对路径按来源文件目录解析。

本批不引入文档站点、生成目录、自动改标题、通用规则插件、数据库或网络爬虫。不修改机器人接口、页面和运行配置，不新增CI工作流或修改现有功能测试19步。外部HTTP链接只统计为未验证，不发网络请求，不把格式正确写成远端可访问。

## 3 实现设计

### 文件与调用约定

以下文件为拟新增，完成开发前不是可用命令或已存在入口：

| 落点 | 职责 |
| --- | --- |
| scripts/check-doc-links.mjs | 文件清单、链接提取、目标与锚点检查、命令行报告 |
| scripts/test-doc-links.mjs | 使用Node内置测试及临时夹具验证可观察行为 |
| docs/local-admin/document-check.md | 前置条件、执行步骤、范围、错误修复与限制 |

复用现有Node与Git环境，不新增运行时依赖。检查器只导出测试必需的少量函数，解析与命令行入口保留在同一文件；测试夹具优先由测试动态生成到系统临时目录，结束后只清理自身目录。不要为这批脚本创建通用测试框架。

拟定命令（R15实施后可用）：

~~~powershell
node --test scripts/test-doc-links.mjs
node scripts/check-doc-links.mjs
git diff --check
~~~

无错误退出0；发现无效引用或读取失败退出1；参数误用退出2。输出扫描文档数、本地引用数、锚点引用数、跳过的外部引用数，以及每条错误的来源路径、行号、原目标和原因。顺序稳定；不读取或打印凭据与运行数据。不新增报告文件格式或强制落盘，维护者可按需重定向输出。

### 链接与锚点规则

1. 先调查仓库真实语法再实现有限扫描器；覆盖行内链接、图片、完整及折叠引用式链接与定义、尖括号包裹目标、可选标题。代码围栏及行内代码中的示例不当作链接。若仓库发现本契约未覆盖的形式，明确补用例或记录未检查项，不能静默计为通过。无需实现整个CommonMark解析器。
2. 文件路径与片段分别解码百分号；空路径表示当前文档。检查大小写与Git路径一致，避免Windows通过而Linux失败。目录只检查存在于跟踪树，不要求每个目录有README。
3. Markdown标题锚点支持ATX标题、Setext标题、中文、行内强调与链接文字、重复标题后缀，以及显式HTML id/name。重复编号要处理标题本身已带后缀的冲突，按GitHub实际规则验证固定夹具，不能只给相同原文计数。标题尾部井号按Markdown规则处理。
4. Markdown片段必须存在；非Markdown文件只验证文件路径，片段单独计为未验证，不用Markdown标题算法解析源码行号或HTML。外部协议与协议相对URL单列跳过，Windows盘符和本机file路径不得被误归为合法外链。
5. 链接失效直接返回具体错误，不自动纠正大小写、不补默认文件、不修改文档、不重试网络。相同目标的标题可在单次进程内缓存，无需持久化缓存。

### 状态一致性边界

链接存在不等于内容正确。自动脚本不根据R编号推断“已部署”，也不以关键字搜索代替状态验收。每次交付仍人工核对首页当前计划、对应计划的实施状态、交付记录的PR状态、自测记录的测试范围；历史记录按日期保留，不把历史“待开发”全局替换。

R15使用说明放入开发与验收导航；普通用户指南仍只描述已实现的后台功能。旧标题与旧锚点保持，发现失效引用按实际原因修复并记录，不使用跳过名单隐藏已有错误。

## 4 开发工作包与顺序

| 工作包 | 实施内容 | 依赖与完成出口 |
| --- | --- | --- |
| R15-01 范围与样本 | 列出跟踪文档实际链接形式，核实Node版本、Git路径及标题规则，整理最小正反例 | 首先完成；样本覆盖本仓库语法，记录任何范围调整 |
| R15-02 检查命令 | 实现读取、解析、路径和锚点检查、统计与退出码 | 依赖01；全库运行得到可定位结果，离线且不写源文件 |
| R15-03 回归用例 | 验证成功、坏路径、坏锚点、重复标题、编码、代码示例、读取失败、跨平台大小写 | 与02迭代；正反例通过，注入错误时命令确实失败 |
| R15-04 文档接入 | 新增开发使用说明，更新索引、进度、自测与交付；修复实际发现的引用 | 依赖02和03；说明命令可直接执行，人工核对当前与历史状态 |
| R15-05 审查上传 | 复跑专项与全量文档检查、差异检查，审查文件清单，提交中文PR | 依赖04；远端SHA一致，标记已上传但未合并，无服务部署 |

按顺序完成一个PR即可；不拆成多层框架或增加中间服务。若01发现必须借助完整解析器才能支持现有语法，先缩小新增需求并说明影响，再决定是否需要一项成熟依赖，不临时手写完整Markdown引擎。

## 5 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 干净检出与暂存新增文档 | 无本机私有文件也能执行；新增已暂存Markdown纳入扫描，未跟踪笔记不纳入 |
| A02 | 正常路径 | 同目录、父目录、根相对、中文及编码空格、图片和目录均正确解析；当前文档片段可用 |
| A03 | 无效路径 | 缺失文件、大小写不符、越出仓库、私有目标、绝对本机路径返回1，错误包含来源行和目标 |
| A04 | 锚点 | 中文、强调、链接标题、重复与后缀冲突、显式锚点可引用；不存在片段返回1 |
| A05 | Markdown语法 | 行内与引用式链接均计入；代码块、行内代码中的伪链接不报错；未知语法明确暴露检查边界 |
| A06 | 外链和非Markdown | HTTP及其他外部协议不访问网络；非Markdown片段单列未验证，不能误计为锚点通过 |
| A07 | CLI与失败 | 无错0、引用或读取失败1、错误参数2；错误不被吞掉；多错一次报告，顺序稳定 |
| A08 | 只读与可移植性 | 检查前后源文件与Git状态一致；不启动服务；Windows实际通过，路径规则用夹具覆盖，未实跑Linux则如实记录 |
| A09 | 仓库全量 | 本范围链接与Markdown锚点零错误；检查数量来自本次输出，不沿用R14数字；无忽略名单掩盖坏引用 |
| A10 | 文档状态 | 首页R15状态与计划、交付、自测一致，R13仍为最新功能部署；旧历史、已通过和条件性验收含义不变 |
| A11 | 上传范围 | 仅工具、必要用例及公开说明；中文PR到用户origin，远端提交核对一致；不含配置、私有笔记或运行证据 |

R15开发验收必须实际执行拟定命令，不能用本次规划检查代替。语法规则以测试样本及实际仓库结果共同核对，避免只测试内部正则或照抄实现断言。达到A01～A11后交付；没有机器人功能变化，无需构建、重启、部署或真实QQ验收。
