## 统计口径

| 显示 | 含义 |
| --- | --- |
| 发起 | 已进入上述模型客户端的HTTP传输次数；重定向每一跳单独计数，不等于QQ消息数或模型任务数 |
| 进行中 | 尚未结束传输，包括已收到响应头但仍读取响应的请求 |
| 接口完成 | 2xx响应，读到结束或读完声明的响应长度；不证明解析成功、内容有效、Agent动作获准或QQ发送成功 |
| 失败 | 网络/取消/超时/响应读取错误、非2xx响应；重定向3xx跳也在此类，后续跳可能完成 |
| 提前关闭 | 2xx响应未核对完整就被调用方关闭；可能是解析错误或只读取部分内容，并不自动等同业务失败 |
| 平均与最长耗时 | 所有已结束传输（包括失败与提前关闭）从进入HTTP传输到读取完成、报错或关闭的时间；页面以秒显示，接口以毫秒返回；不包括前置提示组装、排队或QQ发送时间 |

响应正常传输和“用户收到正确回复”属于不同证据。未知长度响应必须读到结束；解析器若提前结束而没有再读取结束标记，将显示提前关闭。统计包装层不主动读取剩余正文，不增加请求或重试，客户端的超时、重定向策略、Cookie处理和原传输保持。

Agent 和识图非流式客户端对未知长度响应先在既有容量内收取到结束，再按实测长度交给解析器，避免合法分块回复因 JSON 解码器没有再读取 EOF 而误记为提前关闭。Agent 上限仍为 2 MiB，识图仍为 256 KiB；均最多额外探测 1 字节，透明解压后同样受限，读取及关闭错误仍算失败。先收到合法 JSON 但传输迟迟不结束时，仍须等待结束或原客户端超时，不能提前执行其中动作。无需新增设置，运行相应构建后生效，不补改旧统计。

2026-10-16 的聊天完整读取修复覆盖普通聊天、Agent 的普通聊天兜底，以及 `/gpt` 和群聊总结：模型协议解析成功后继续读取剩余响应至 EOF，再返回回复。剩余正文直接丢弃，不增加内容缓存或请求重试，仍使用原 HTTP 客户端的超时。尾部读取错误或超时会使模型请求失败；协议解析失败则立即返回原错误，不继续等待正文。统计层仍只记录实际读取结果，未知长度的正常完整响应记为完成，真正提前关闭仍保留 incomplete。新程序重启后生效，旧进程中的累计记录不回填。回归及真实接口结果见[修复验证](self-test.md#聊天响应完整读取修复)。

统计只保存固定类别、次数、时间与耗时汇总，不保存逐条请求历史、QQ/群号、模型名称、接口地址、消息、图片、密钥或原始错误。不会写入配置或备份，不提供清零/修改接口。内存容量不随用户/请求历史增加；响应期间仅保留一次结束回调，结束重复通知不重复计数。

维护工具可使用已登录的同源只读`GET /api/overview`中`modelRequests`对象取得累计快照。它沿用本机地址、来源和后台会话限制，响应禁止缓存；没有统计来源返回`null`，不能当作0。对比两个快照须核对统计起点一致，否则跨重启的差值无效。`observe-live-services.ps1`仍只采资源和日志，尚不读取这个接口，不能直接宣称同时取得请求数量或端到端回复延迟。

## 缓存统计一致性修复（2026-10-26）

总览、分组与导出报告现在共用缓存校验及加权命中率算法。此前总览只要求命中/未命中可读，而分组还核对输入总量，异常数据可能得到不同百分比；现统一要求输入、命中、未命中均为非负安全整数，且输入等于两分项之和。

总览分别列出有效缓存记录、缓存字段缺失/无效、分项不一致次数；不一致或未知记录不进入命中率。输出字段缺失不影响缓存命中率，但高未命中风险提示仍要求输出也已知。风险提示中的“字段不完整”和“分项不一致”可能发生在同一请求，二者不能相加作为总请求数。

累计使用整数计算并统一四舍五入到两位小数，避免大量Token相加超出安全数值范围后出现未知或精度偏差。没有有效缓存记录时小计与命中率为未知；有效记录总Token为零时保留小计0，命中率仍未知。报告新增 `cacheSummary`，与页面同一快照一致，分组与报告字段原有含义保持。

每个字段分别显示Token合计和已知k/n次：k仅统计该字段有有效值的请求，n是匹配整组或全窗口的请求数。有效0显示0 Token，全未知显示未知；无匹配为未知、已知0/0次，全窗口保持。有效空窗口或缺少有效统计窗口只显示原有提示。

例如同一任务两次输入为100、未知，命中为60、0，未命中为40、未知，则匹配输入100 Token（已知1/2次）、命中60 Token（已知2/2次）、未命中40 Token（已知1/2次）。三个字段独立求和，即使输入与缓存分项不一致也不互相推导或丢弃有效单值；输出全部已知不表示输入及缓存全部已知。总和超过安全整数范围仍精确。

五类筛选按完整组取交集，风险和结果可由不同请求命中，仍合计整组；排序及展开不改变小计。刷新使用新快照重算；阈值草稿应用后才改变风险范围，重置恢复全部范围并保留阈值和草稿。失败、离页、退出或认证失效清除旧值。只覆盖最近最多256条已结束请求，未知不补零，不代表完整任务用量或费用。

页面本地计算不增加模型或网络请求。完整JSON导出仍包含完整快照与taskBreakdown，version=1，不附加筛选小计。部署、测试及集中验收状态见[本批清单](task-token-summary-acceptance.md)。

## 按会话或任务标识筛选

登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量，在工具栏首项“会话或任务标识”粘贴完整标识。沿用后台登录权限，部署新程序后刷新页面生效，无需保存。输入即时本地筛选，Enter不提交设置，不增加网络或模型请求。

只匹配当前最多256条请求形成的有效关联组：完整会话标识或完整任务标识任一相等即可，区分大小写，忽略首尾空白，框内原文不改写。空查询不限制标识范围。前缀、部分或无效标识自然无匹配；独立请求即使原记录含部分标识也不参与，不查询历史记录或自动补全。

标识条件与风险、结果、次数、关联、输出已知情况按组取交集，之后执行排序；匹配保留整组，汇总表同步更新。无匹配仍显示全窗口列，匹配列未知、已知0/0次。原生清除或清空输入只移除标识条件，保留其他筛选；非空查询与独立请求组合无匹配属正常结果。

刷新保留查询原文，用新快照重算；阈值草稿需应用才影响风险交集。重置任务视图清空查询、恢复筛选和排序并收起明细，保留阈值与草稿。读取失败禁用输入并清理结果，恢复后继续保留查询；离页、退出、认证失效或整页刷新清空查询。有效空窗口允许输入但不显示汇总表。

完整JSON报告仍包含整个快照，不携带查询也不按查询裁剪。键盘可从标识框依次访问各筛选和重置；长查询只在输入框内滚动。部署与验收范围见[本批清单](task-identity-filter-acceptance.md)。

## 按请求类别筛选任务

登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量，在风险筛选之后使用“任务包含的请求类别”。沿用后台登录权限，部署新程序后刷新页面生效，无需保存配置。

可选全部类别、包含GPT／群总结请求、包含普通聊天请求、包含Agent请求、包含识图请求、包含未知类别请求。按组内是否至少有一条对应kind匹配：gpt/chat/agent/vision为已知值，缺失、null、大小写不同或其他未识别值按未知；未知不等于失败。

类别与标识、风险、结果、次数、关联和输出已知情况按组取交集，再排序。类别、结果和风险可由不同请求命中，仍保留整组全部请求及四字段小计，不拆分混合类别任务。例如同组有Agent完成请求与识图失败请求，选择Agent和失败仍保留两条请求。无匹配时匹配列未知0/0，全窗口列不变。

只筛选本地最近最多256条窗口，不增加网络或模型请求，不代表完整任务或费用。完整JSON报告仍包含整个快照，version=1，不附加类别筛选条件或裁剪请求。部署和证据范围见[本批清单](task-kind-filter-acceptance.md)。

## 任务明细显示单次请求耗时

登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量，展开任务即可在每条请求标题之后、Token行之前查看“接口耗时”。沿用后台登录权限，部署新程序后刷新页面生效，无需保存配置。

已有非负有限毫秒值四舍五入到整数显示，例如1199.6显示1200 ms，0和0.4均显示0 ms；后者是显示舍入，不等于没有耗时。缺失、null、负数、非有限值或字符串显示未知，不强制转换为数值。极大有限值可能显示科学计数法。请求失败、提前关闭或结果未知不影响其有效耗时的展示。

接口耗时来自单次模型接口记录，含响应读取、不含QQ发送，不代表首字节延迟或任务总耗时。不新增计时、任务耗时求和、排序或告警。筛选仍保留整组全部请求的明细；原组摘要、四字段汇总和请求顺序不变。刷新替换当前快照，重置收起明细；无匹配、空/无效窗口、读取失败、离页或退出不保留旧耗时。

完整JSON报告保持原始milliseconds精度及现有未知值规则，version=1不变；显示舍入不写回报告，也不增加模型或网络请求。实际证据及待验收状态见[本批清单](task-request-duration-acceptance.md)。
