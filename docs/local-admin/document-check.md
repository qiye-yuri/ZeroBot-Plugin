# 文档链接检查

R15提供独立的开发检查命令，检查公开管理文档的本地链接与Markdown锚点。无需后台登录、管理员权限、机器人服务、浏览器或模型凭据；检查即时读取工作区内容，不修改源文件，不访问网络。

## 执行步骤

需要Git及Node.js，已验证环境为Windows与Node.js 24.22.1。进入仓库根目录，先显式暂存本次新增的公开文档和引用目标，使它们进入Git跟踪清单；已有文件的未暂存内容也会检查。不要为了检查使用全目录暂存，否则可能纳入不应上传的本机资料。

```powershell
node --test scripts/test-doc-links.mjs
node scripts/check-doc-links.mjs
git diff --check
```

命令也可从子目录用脚本的正确相对路径执行，扫描范围仍为整个仓库的规定文档。检查器不接受参数。专项测试会建立隔离的系统临时Git仓库并在结束后删除自身目录；检查命令本身只读，不创建报告或修改Git索引。

## 范围与结果

源文件为Git跟踪的 docs/local-admin 下全部Markdown，以及根README.md和AGENTS.md。不遍历子模块、运行数据、私有笔记或未跟踪文件。目标可为仓库内跟踪文件或跟踪树中的目录；检查目标是否存在及路径大小写，不要求目录拥有README。

报告包括文档数、本地引用数、Markdown锚点引用数、跳过的外部引用数、未验证的非Markdown片段和错误数。每条错误给出来源路径、行号、目标与原因，按文件和扫描顺序输出。退出0表示受支持范围内无错误；退出1表示引用、解析、读取或Git环境错误；退出2表示命令参数错误。CI未新增接入，人工执行通过不能记成GitHub CI通过。

HTTP、协议相对URL及其他外部协议不联网验证；源码行号等非Markdown片段只检查文件存在，片段逐条报告为未验证。裸写网址和自动链接不计入外部引用统计。退出0不代表这些外链可达、片段有效或文档业务状态正确。

## 支持的语法

- Markdown行内链接、图片、嵌套图片徽章、完整及折叠引用式链接、已定义的快捷引用。引用定义的目标和可选标题写在同一行；未定义的方括号组合按Markdown普通文字处理，适用于命令参数示例。
- 尖括号包裹目标、单引号或双引号标题、平衡括号和反斜线转义。路径和片段分别解码百分号；根相对路径从仓库根解析，空路径片段指向当前文件。
- HTML a的href及img的src；显式HTML id/name锚点使用引号属性。
- ATX标题、单行Setext标题、中文及常用行内强调、代码和行内链接标题；重复标题及带编号标题冲突递增分配后缀。显式锚点不占用自动标题的编号。
- 忽略顶层、至多3空格缩进的反引号或波浪线代码围栏、行内代码及HTML注释中的示例链接。

标题规则依据[GitHub章节链接说明](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links)。工具覆盖仓库当前用法，不是完整CommonMark渲染器：嵌套列表或引用中的代码块、缩进代码块、多行Setext标题、标题中的引用式链接、HTML实体及任意HTML布局未保证解析。输出始终提示该边界；新增这些语法时须人工核对GitHub渲染并补相应能力或改用现有支持的写法，不能仅以退出0作为验收依据。未闭合行内目标及无法解析的引用定义会明确报错。

## 修复错误与交付

| 错误 | 处理方式 |
| --- | --- |
| 目标未跟踪或大小写不一致 | 对照Git路径修正拼写；新公开文件显式暂存后重跑 |
| 工作区缺失或读取失败 | 恢复目标或修正引用，检查UTF-8编码与Git环境 |
| Markdown锚点不存在 | 核对标题、重复标题顺序与显式锚点；保留仍被引用的旧标题 |
| 仓库外、私有目录或本机绝对路径 | 改为可交付的公开文档引用，不上传凭据或本机证据来消除错误 |
| 查询参数、反斜线或不支持的语法 | 使用仓库相对路径和支持的Markdown写法 |

检查器不自动纠错、不重试、不新增忽略名单。修改后重跑专项及全量检查，将实际数量、限制和修复复验写入[自测记录](self-test.md)，按[交付约定](github-delivery.md)核对上传范围。

链接检查之外，人工确认[首页](README.md)、[阶段计划](post-r14-development-plan.md)、进度、交付与自测记录的状态一致。上传、合并和部署分开记录；历史文字保留当时含义。只改此工具或文档时不需要构建、重启或部署机器人，也不改变既有真实QQ验收条件。
