## 工作包与实施顺序

### A：冻结候选与核对差异（2～3小时）

1. 列明画图、引用和撤回改动的源码、合成测试、使用说明及依赖；区分无关测试、data子模块和本机资料。
2. 对照部署记录、程序哈希和候选构建，核对实际运行来源。差异先解释或重新构建验证，不能凭时间戳认定一致。
3. 整理可审查候选提交；保留必要的既有画图配置实现，不借整理扩展页面。
4. 输出候选清单：源码提交、程序哈希、验证范围、部署备份和剩余QQ缺口。公开文档只写脱敏摘要。

出口：候选可独立构建、差异归属明确、用户既有改动未丢失。可上传开发分支供审查，真实验收完成前不合入master。

### B：按实际风险补齐机器人链路（3～6小时）

复用已有测试与隔离脚本，先跑相关回归，再决定是否修改实现。

| 链路 | 必要检查 | 实际限制 |
| --- | --- | --- |
| 文生图与参考图 | 无图走生成；附图和引用图按当前规则合并；字节与顺序进入编辑请求 | 不承诺所有服务商参数一致 |
| 引用与缓存 | 合法引用、UUID缓存兼容；跨会话、错误图片与目录外路径拒绝 | 不递归追溯引用链，不放开任意本机路径 |
| 撤回 | 提交前停止、提交后抑制结果；重启和测试批次隔离 | 已提交请求可能计费，不承诺跨平台原子取消 |
| 预算 | 耗尽不调用；usage缺失记未知；失败按现有规则保留占用 | 估算不等于账单，不扩大自动重试 |
| 帮助 | 现有九主题和参考图说明与入口一致；帮助不消耗模型额度 | 不新增管理页面或帮助框架 |

只修复可复现的问题，每个问题保留能复现根因的合成回归。入口检查、权限、文件边界、预算和测试隔离属于必要约束；不叠加无依据兜底、重复校验、通用重试或未来兼容层。

出口：相关单元与独立OneBot/假模型链路通过。失败轮保留，修复后重新验证；不为本计划重跑真实付费测试。

### C：候选部署与独立验收（2～3小时）

按[运行维护](operations.md)执行备份和回退准备。候选程序变化时才部署，验证单实例、OneBot连接、配置保持与必要后台健康；纯文档不重启机器人。

用合成身份、独立OneBot和独立数据目录验证画图/引用/撤回/预算路径，测试结束后验证正常请求不读取测试历史或记忆。记录实际候选构建与部署哈希，不套用旧版本验证结果。

出口：独立验收通过，真实QQ缺口逐条列出；画图仍为1项，不因子功能、补丁或部署次数重复登记。

### D：累计与集中QQ配合（准备1～2小时，等待时间不计）

累计到5项统一进行，不逐批要求用户发消息。只有完成开发、隔离、部署和独立检查，且确有单条QQ配合缺口的独立功能批次才能加入；计划、文档或旧缺口不自动占位。其余四个位置不预设功能，不为凑数开发。

累计期间可按用户授权推进下一个独立必要批次；这是批量验收排队，不代表前批已合入。存在未解决的部署或自动化失败时先修复，不能以等待QQ为由跳过。

达到5项后生成覆盖表，记录每项候选版本、前置状态、消息步骤、期望结果、实际证据及未覆盖分支。优先共用一次用户操作，但一条消息只计实际覆盖；撤回操作、多个场景或多人角色需要额外动作时明确列出，不能声称一条消息完成全部验证。

真实模型测试仅在北京时间空闲时段安排，调用前核对时间；真实QQ测试先使用现有测试会话/测试消息入口，结束后验证日常数据不回流。本计划不发送QQ通知、不创建定时任务。

出口：按项判定通过/失败/未覆盖；失败留本批修复。只有已验收且依赖满足的候选才能合入，队列按实际关闭项扣减，不清空未验收项。

### E：合入、文档与上传（1～2小时）

出口：说明对应实际版本、远端提交可查、未验收范围保留。合计约9～16小时有效工时，不包含新增功能、等待五项或真实事件的时间；A核对后按实际差异修订估算。
