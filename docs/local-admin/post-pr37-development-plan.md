# PR37后的开发设计与详细计划：任务风险原因定位

核对日期：2026-10-26（Asia/Shanghai）。源码基线为master `58aecc32`，PR #37已合并，已有任务筛选、排序及中文校验说明已部署并获用户确认。逐请求风险原因现已完成本地实现与专项验证，尚未合并部署。下文保留设计契约与工作包；规划检查不代替功能验收，实际结果见自测与交付记录。

## 1 目标与源码依据

现有任务筛选能找到包含风险请求的任务，但任务正文仍逐条输出原始Token和状态，用户需要自己比较阈值才能判断究竟是哪一次请求触发筛选。本批在现有逐次明细中补充风险原因，让用户从匹配任务直接定位请求编号及触发条件。

源码依据：[任务分组与渲染](../../internal/localadmin/assets/overview.js)中的modelTaskUsage、modelTaskUsageText、modelRequestRisk及renderModelTaskView；[概览结构](../../internal/localadmin/assets/index.html)已有任务区域、筛选和排序控件。modelRequestRisk已经共用于风险汇总和任务筛选，本批继续使用它。报告构造另由buildModelUsageReport所在流程生成，不能把显示标签加入原始请求对象。

优先完成一个可独立交付的小功能：逐请求风险说明及其测试。暂不增加另一组筛选、图表、任务详情页、后台接口或统计存储。现有功能入口与边界见[使用说明](model-request-statistics.md#任务风险筛选与排序)。

## 2 产品与数据契约

入口保持“运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量”，沿用当前登录权限。每条请求在现有四项Token文本后增加一行“提示：…”。既有请求编号、匿名会话与任务标识、模型、状态、时间及小计保留；不展示消息正文或真实QQ身份。

| 条件 | 显示内容 | 判定来源 |
| --- | --- | --- |
| large为true | 大输入（单次输入达到已应用阈值X） | modelRequestRisk.large，X取已应用large |
| highMiss为true | 高未命中（输入达到X且未命中占比达到Y%） | modelRequestRisk.highMiss，X/Y取已应用minimum/missPercent |
| incomplete为true | 用量字段不完整 | modelRequestRisk.incomplete；沿用四项Token有效性定义 |
| inconsistent为true | 缓存分项与输入不一致 | modelRequestRisk.inconsistent；不自动修正字段 |
| 四项均为false | 未触发当前用量提示 | 仅表示当前阈值与字段规则未命中，不表示请求业务成功或费用为零 |

多项同时命中时全部显示，按上表顺序连接；字段不完整和缓存不一致可以同时出现。请求失败与用量提示分开，保留原outcome，不把传输失败自动归为Token风险。零输入、零输出按现有规则处理，未知不是零。高未命中沿用现有整数比较，不新增浮点比率计算或另一套阈值判断。

筛选仍显示匹配任务的全部窗口内请求，包括未触发提示的请求；每一条独立解释。小计不参与单次风险判定，不因一个任务总输入很高就给每次请求标“大输入”。缺少有效关联标识的独立请求同样显示提示。

报告版本、requests、taskBreakdown、hints及独立校验契约保持；风险说明只由页面渲染生成，不写入快照、报告或配置。导出仍包含完整窗口，不能受筛选、排序或标签影响。

## 3 页面生命周期与实现方式

沿用modelCostRows、modelUsageSnapshotMeta和modelCostSettings。让modelTaskUsageText接收当前已应用设置（可设现有设置为默认参数），调用modelRequestRisk生成提示字符串。若抽取函数，只抽取一个页面内的原因格式化函数；renderModelTaskView继续负责选择分组和替换textContent，不新增状态对象或渲染框架。

| 操作 | 预期行为 |
| --- | --- |
| 初次读取成功 | 全部任务中每条请求显示当前规则的提示 |
| 修改阈值草稿 | 标签、筛选结果和报告仍使用之前已应用的阈值 |
| 应用或恢复默认阈值 | 当前快照立即重算筛选与逐请求提示，不发请求 |
| 更改筛选或排序 | 原标签规则不变，整组请求及组内顺序保持 |
| 同页刷新成功 | 使用新快照替换全部明细，保留当前筛选与排序 |
| 无匹配、空窗口、读取失败 | 沿用三类既有状态；无旧请求标签残留 |
| 离页、退出、认证失效 | 沿用既有清理与默认选择，不能留下上一会话明细 |

保持纯文本渲染和长文本换行，复用现有任务容器，不增加点击标签、复制按钮或每条请求的live播报区域。完整256条窗口仍按当前方式渲染；只有测试发现可重现问题才考虑性能调整，不预先加入分页、缓存或虚拟列表。

## 6 简洁实现约束

只在现有输入边界使用已有校验，不在每层重复验证已校验的快照。不引入通用策略注册、异常吞并、自动重试、备用状态、自动修复、第二份风险缓存或重复统计逻辑。保持必要的认证、纯文本输出、未知值语义和会话清理；避免过度防御性编程不等于删除已有正确边界。

不改报告版本、预算900000、插件开关、模型调用路径或定时任务。无新依赖、数据迁移及配置项。对异常只显示已有数据支持的原因，不推测服务商故障或建议改写报告。
