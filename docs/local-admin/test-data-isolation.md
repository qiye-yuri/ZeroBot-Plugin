## 新测试的必用入口

优先运行合成OneBot与独立运行目录。确需真实QQ时，仅机器人主人可以控制测试范围：

```text
/测试会话 开始 case-001
需要验收的消息或原插件命令
/测试会话 状态
/测试会话 结束
```

批次ID必须以字母或数字开头，后续仅字母、数字、下划线和连字符，最长48字符。开发验收统一使用小写ID，避免Windows目录大小写别名；不能把大小写变体当成独立批次，也不要使用CON、NUL等系统保留名。会话模式按机器人和群/私聊保存，重启仍有效；群测试模式会覆盖该群所有发言者的后续事件，必须及时结束。开始、状态和结束在本机处理，不调用模型。单条Agent消息可用 `/测试消息 case-002 测试内容`，只标记这一条及衍生记录，不改变后续默认模式。它不会剥离前缀去调用其他插件命令；需要测试原命令时使用会话模式。

测试范围是宿主写入的状态，模型不能通过 `save_memory` 参数改范围；普通用户不能开启或结束测试会话。已知测试消息的QQ回声和引用继承测试范围；来源不明的外部内容不靠语义猜测为测试。测试隔离不是平台动作模拟器：QQ发送和其他已授权平台动作仍可能真实执行，纯模拟验收继续用隔离OneBot。

## 数据边界

- 原事件、请求、响应与结束记录保留在档案中，同时标记批次和来源。任务在启动时固定测试批次；并发新消息或随后结束测试模式不会改变在途任务归属。
- 测试任务只加载本批次历史和测试记忆；正常任务排除测试记录、测试来源记忆及显式隔离的旧记忆。普通聊天测试不使用日常短上下文，也不把回复写入日常短上下文；主动跟进缓存同样排除测试回复。
- 测试记忆保存到 `data/aichat/history/testing/<批次>/<机器人>.sqlite`，与日常机器人数据库分开。保存回执为 `mode=test` 并带 `testRun`。个人、长期和永久知识在测试中均写入该测试库，永久知识也只在同一测试批次内共享。
- 日常历史检索和精确读取排除测试事件，前后邻居也在同一范围内选取。测试检索不允许选择别的批次。普通 `get_msg` 不允许读取已知其他测试范围的消息；群聊总结排除已知测试平台消息及授权历史时间边界以前的记录。
- 测试任务不启动日常滚动摘要。日常摘要只扫描未隔离记录；批量补标后旧摘要被移入审计表并失效，在途旧摘要受到隔离修订号保护，不能迟到写回。

后台原记忆列表仍可审核旧条目，显示“测试隔离（不注入日常）”；测试任务标题显示批次。停用、恢复启用或改写旧条目不会清除隔离标记，不能因此重新注入日常。旧文本记忆文件中被隔离的行在读取时排除，以后显式迁移时标记继续保留。原始文件与归属记录不删除。

## 历史处理流程

仅在用户授权范围内运行导出。示例路径和时间须换成实际授权值：

```powershell
go run scripts/agent-test-isolation.go -db <历史数据库> -legacy-dir <旧agent目录> -before <带时区RFC3339边界> -out <本机私有目录>
```

导出不改日常数据库。应用前停止日常ZeroBot，备份程序、完整历史目录及SQLite辅助文件、旧agent目录，核对冻结计划。随后运行同脚本，增加 `-apply <plan.json>` 并省略 `-before`。源正文、记忆版本、旧文件哈希发生变化时拒绝应用，不能盲目重试或重写冻结计划。应用新增标签、隔离旧记忆、失效摘要及建立独立测试档案，不删除聊天。

历史授权时间边界也用于排除晚到的旧平台事件。边界后的新消息默认正常，除非主人显式开启测试模式或消息引用了已知测试来源。旧摘要清除后如果没有正常资料，不调用模型生成空摘要；以后正常资料达到阈值再重建。

部署新程序后必须验证：旧消息不进入正常上下文、正常检索不命中测试来源、测试记忆只存在测试库、测试结束后的回复不带回测试内容、隔离旧文本迁移不会复活测试记忆、摘要迟到结果被拒绝、导出与原件哈希一致。回退旧程序会失去读取过滤能力，不能把“换回旧程序”当成仍然隔离；原件和新数据必须保留，必要时停机核对备份后制定数据回退方案。
