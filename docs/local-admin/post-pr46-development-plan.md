# PR46之后的开发计划：按窗口内请求次数排序

日期：2026-10-27（Asia/Shanghai）。设计基线为codex/task-any-risk的aa6dfd0ec762f1fac6a63e0a0ede699674d816c7；master仍为02fc0e78。PR #46已实现并部署，非空验收按用户要求等待集中安排，尚未合入。当前状态见[验收清单](task-any-risk-acceptance.md)。本次仅规划，新增排序尚未实现。

## 1 目标与范围

任务摘要已有窗口内请求次数，但任务排序目前只有原记录顺序、已知输入小计降序和已知未命中小计降序。排查多轮调用时，需要逐组扫描次数才能找到轮次较多的任务。

下一批在现有排序选择框增加“窗口内请求次数降序”，把当前窗口请求较多的任务放在前面。复用modelTaskUsage产生的g.count，不新增数据采集、接口或持久化。窗口次数不是完整任务轮数、耗时、费用或异常等级，不按次数自动触发提示。

依据：[overview.js](../../internal/localadmin/assets/overview.js)中modelTaskUsage已生成count，selectModelTaskGroups先按任务级风险/结果筛选，再处理input/miss排序；[index.html](../../internal/localadmin/assets/index.html)中的model-task-sort定义现有选项。只需局部排序分支与原生option，不改模型调用或分组规则。

历史预算900000、[其他待验收与暂缓项](remaining-acceptance.md)不变，不以本批开发补做其他业务验收。

## 2 使用与行为契约

入口保持“运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量”。需要既有后台登录，无额外权限或保存配置。更新程序后刷新后台生效。

“任务排序”增加内部值count、标签“窗口内请求次数降序”，位于“原记录顺序”之后；input和miss选项及其相对顺序保持。默认值仍为original，不新增按钮、图标、默认持久化或排序方向切换。Tab顺序与原生键盘行为保持。

### 排序规则

- 先执行原有风险/结果筛选，再对匹配组按g.count从大到小排列；任何风险选项（包括PR #46的anyRisk）均可组合。
- 次数相同，保持modelTaskUsage输出的原组顺序。比较器相等返回0，使用既有JavaScript稳定排序语义，不增加人为时间、标识或Token次序作为第二条件。
- 只排序筛选得到的新数组，不改value.groups、g.requests或输入快照。返回original时恢复原分组顺序，不以最近一次排序结果为基础累计排序。
- 次数只覆盖最近最多256条已结束请求。窗口截断后按实际保留次数重新计算，不补查历史、估算丢失轮次或跨启动累加。
- 有有效会话/任务标识的组按现有规则计数，跨会话隔离；独立请求每条一组，重复id不去重。组内请求顺序及完整正文保持。
- g.count来自现有合法分组结果，为正整数且不超过256；不引入缺失次数补零、特殊未知次序或兼容其他数据类型的分支。

### 与现有操作的关系

改变排序仅重绘当前视图，不请求后端、不保存设置、不增加模型调用。摘要五段、用量提示计数、结果分布和小计不变，完整JSON导出不受排序影响，不新增排序字段。

可见同键任务继续保持展开和摘要焦点；排序控件保持自身焦点，不主动跳转页面或滚动到第一组。切换到其他排序模式按各自既有规则排列，input/miss的未知末尾规则不变。

刷新使用新快照和当前count选择重排；原先同次数变为不同次数时位置随之改变，但不丢失可识别任务的展开状态。跨启动不继承旧展开状态。读取失败禁用控件并清空旧内容，恢复后按保留选择重算。离页、退出和认证失效恢复original。

重置任务视图恢复all/all/original并收起明细，不改变阈值草稿或已应用阈值。空窗口、无匹配和未知数据继续使用原有提示，不创建虚构的零次任务。阈值应用可以改变匹配组，但不会改变同组请求次数。
