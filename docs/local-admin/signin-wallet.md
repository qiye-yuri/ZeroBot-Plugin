# 签到与钱包

P083 score统一承接P092钱包。后台和QQ服务列表仅显示score（签到与钱包）；旧wallet不再独立注册。通过`/启用 score`、`/禁用 score`按原插件管理权限调整当前会话；关闭后签到和钱包命令同时停止响应。原score开关状态继续生效，旧wallet开关不再单独生效。

| 命令 | 权限与作用范围 |
| --- | --- |
| 签到 / 签到0～3 | 私聊和群聊；同一账号每天一次，跨会话共享。增加签到等级及钱包奖励 |
| 补发签到图 | 当天已签到时重新生成当前会话样式的图片，不增加签到次数、等级或余额；图中新增金额显示0 |
| 设置签到预设0～3 | 机器人主人；设置当前会话样式 |
| 获得签到背景[@成员] | 群聊；获取签到背景 |
| 查看等级排名 | 群聊触发，展示跨群签到等级排名 |
| 查看我的钱包 / 查看钱包余额[@成员] | 私聊和群聊；查询钱包余额 |
| 查看钱包排名 | 群聊；当前群成员余额排名，图片每日缓存 |
| 钱包转账金额[@成员] | 群聊；转账金额须为正整数且余额充足 |
| 管理钱包余额+金额 / 管理钱包余额-金额，可附@成员 | 仅机器人主人；未指定成员时操作自己 |
| 设置硬币名称XX | 仅机器人主人，对机器人发送；修改全局币名 |

等级和余额是不同指标：签到等级不会因转账减少。钓鱼P058继续使用同一钱包余额，关闭score不会关闭钓鱼。

### 转账一致性

群内“钱包转账金额[@收款人]”保留原入口、权限及旧币名。扣款和入账改为同一SQLite事务：任一写入失败时回滚，余额不足及收款方整数溢出会拒绝；同一账号给自己转账不增加或减少余额。并发转账在共享钱包锁下串行处理，避免两个请求同时花掉同一余额。

仍使用 `data/wallet/wallet.db` 的原表和数据，无需迁移或重设余额。签到、群配对和钓鱼仅统一引用本地共享钱包包，现有玩法保持原规则。本次保证的是单笔钱包转账的双边原子性，不把它扩大为跨插件物品/签到数据的一体化事务。数据库异常会返回转账失败，不输出内部数据库错误。
