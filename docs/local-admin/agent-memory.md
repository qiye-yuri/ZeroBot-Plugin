## Agent 历史检索

### 按事件类型检索历史

运行新构建后，可在已启用 Agent 且允许响应的会话中要求“只回顾聊天消息”或“查之前的通知/请求”。例如 `{"action":"search_history","params":{"eventType":"notice","limit":5}}` 只查通知，可省略或留空关键词；也可把 eventType 与原关键词、发言者、时间和 before 组合。模型是否调用由其决定，无新增配置或 QQ 权限。

| eventType | 保存事件的顶层 post_type |
| --- | --- |
| message | 聊天消息 |
| notice | 通知，如已保存的成员变化或撤回事件 |
| request | 请求，如已保存的好友或入群请求 |
| 省略或空串 | 不限事件类型，沿用原行为 |

仅匹配 kind=event 的顶层 post_type，不按正文、嵌套字段或档案分类猜测。工具动作的 kind=request 不是事件请求，不会被 request 条件选中；非空的其他 post_type 不属于上述目标。缺失、空串或非字符串元数据跳过并标明 partial，未知旧资料不补造。sender 仍仅匹配消息作者；把通知/请求与 sender 组合会得到空交集，不按操作者或被通知者猜测作者。只能查已进入本机档案的事件，筛选不能补采未保存的通知或请求。

条件、已加载会话与最近重置范围保持，类型不匹配的记录仍计入原 5,000 条/4 MiB 扫描预算；返回仍限 20 条/16 KiB，空窗口可按实际 nextBefore 继续。成功回执的 eventType 表示已应用条件；继续须沿用原类型，最多三次历史/记忆共享查询，非法参数也计额度。read_history 及前后事件不继承类型，邻居可属于其他类型；记忆查询与读取不接受 eventType。省略类型、关键词、发言者和时间时仍不能只用 before/limit 查询。

后台也可在已读取会话中选择“事件类型”搜索，操作见[档案事件类型筛选](agent-archive.md#按事件类型搜索)。真实模型调用和事件采集效果待验收。
### 只按时间回顾会话

运行新构建后，可在已启用 Agent 且允许响应的会话中要求“回顾昨天聊过的事情，说明来源”。模型可调用 `{"action":"search_history","params":{"from":"2026-10-14T00:00:00+08:00","until":"2026-10-15T00:00:00+08:00","limit":5}}`。只要指定有效的 from 或 until，就可省略 keyword 和 sender，或把 keyword 留空；不限定发言者。是否调用及日期理解由模型决定，不保证自动完成整日总结。

时间仍按档案保存时刻筛选，起点包含、终点不含，接受带时区的 RFC3339 时间。可单独填写一端，另一端不限；两端都有时开始须早于结束。关键词、发言者、时间或事件类型至少提供一项；仅传 before 或 limit 不构成查询条件。记忆搜索可在指定具体来源时省略关键词，见下文。

沿用当前任务的机器人、群/私聊及最近重置范围，只返回历史事件，可能包括通知，不把它们都当作用户发言；工具请求、响应和结束记录不进入 Agent 结果。按来源序号倒序返回，单次仍受 5,000 条/4 MiB 扫描和 20 条/16 KiB 返回上限约束，时间范围外的记录也占扫描预算。未命中或 partial 不能证明该时段没有其他记录。

有 searchMore 时，沿用空关键词、原时间条件及实际 nextBefore 继续。每次独立读取当前状态，不冻结快照；与其他历史/记忆查询共用每任务三次额度。片段不足可用 read_history 读取实际来源，正文读取和前后事件不继承原时间条件。沿用现有角色、停止和上下文预算，无新增配置；不修改档案，也不直接调用 OneBot。后台操作见[按保存时间搜索](agent-archive.md#按档案保存时间搜索)。

### 按发言者检索历史

在已启用 Agent 且允许响应的会话中，可提出“查 QQ 12345678 之前说过的项目安排，说明来源”。模型可调用 `{"action":"search_history","params":{"keyword":"项目安排","sender":"12345678","limit":5}}`，仅查询当前任务绑定的机器人和群或私聊，仍排除最近重置前记录。sender 可省略；未指定发言者、时间范围或事件类型时关键词必填。是否调用由模型决定，不保证自然语言请求每次触发。沿用原角色白名单，不新增动作或 QQ 权限。

也可要求“查 QQ 12345678 最近说过什么”，调用 `{"action":"search_history","params":{"sender":"12345678","limit":5}}`。指定有效 sender 时可省略 keyword，或传空白字符串，按来源序号从新到旧返回该发言者的消息片段；未指定时间范围或事件类型时，关键词与发言者不能同时为空。可组合原有 from/until、before 和实际继续回执，继续时沿用空关键词及发言者条件。只按已保存消息的顶层 user_id 匹配，仍受下述扫描、返回和每任务三次共享查询额度约束；“最近”指保存顺序，不承诺覆盖该账号的全部发言。记忆搜索可在指定具体来源时省略关键词，见下文。

sender 须为规范正整数字符串，数字、空串或无效类型会返回本地参数错误并占查询额度。只依据已保存的消息事件（post_type=message）顶层 user_id 精确匹配，不按昵称、正文提及或嵌套 sender 字段猜测；通知、工具和其他类型不算发言。旧字段未知/无效时跳过并标明 partial，不补造作者。成功回执仅在已应用时返回 sender 字符串，它表示查询条件，不证明存在消息、账号身份或历史完整。

可与 from/until 和 before 组合，继续检索时须沿用实际 sender 及其他已应用条件。仍共用每任务三次历史/记忆查询额度，重建助手不重置，非法尝试也计入；非匹配账号仍计入原每次 5,000 条/4 MiB 扫描预算，最多 20 条/16 KiB 片段。无结果或覆盖不完整不能当作全部历史不存在。read_history 及上下文核对不继承发言者条件，邻居可能来自其他人；此参数不适用于记忆检索或读取。

不改写档案，不调用 OneBot、识图或账号查询，无新增开关，使用新构建生效。后台可独立手动[按发言者搜索](agent-archive.md#按发言者搜索)，后台查询不占任务额度；后台所有者显式归档的范围不授予模型。真实模型遵循发言者条件的效果待验收。

### 核对来源的前后事件

在已启用 Agent 且允许响应的会话中，可提出“核对这条来源前后各两条消息，说明当时的语境”。模型可调用 `{"action":"read_history","params":{"seq":"23","context":2}}`；context 是可选整数 0～3，表示中心前后各最多多少个事件。省略或为 0 仍只读原来的一条来源；是否调用由模型决定，不保证每次自然语言请求都触发。

先确认 seq 是当前机器人、当前群或私聊、最近重置之后的历史事件，再在同一次只读事务和快照中取相邻事件。中心不存在、属于其他会话、是工具记录或已在重置边界之前时返回空 sources，不按猜测序号展示附近资料。上下文只包含 event，按来源序号倒序，工具记录和其他会话不占相邻事件数量；它不是 QQ 平台消息连续性或完整语境的证明。

context 大于 0 时最多返回 7 条。中心正文最多 8,000 UTF-8 字节，相邻每条最多 2,000 字节，合计最多 16 KiB，均在完整字符边界截断；超过 64 KiB 的单条只返回占位。总量不足以展示全部邻居时保留中心正文的既有额度，partial=true，不补造搜索继续位置。回执的 anchorSeq/context 仅表示请求中心和范围，需在实际 sources 中找到中心，不能单凭回执字段确认来源存在。

上下文读取不继承先前搜索的关键词、发言者、时间范围或 before 条件，邻居可能由其他人发言或位于搜索时间窗外；仍不允许读取最近重置前记录。每次仍作为一次 read_history 查询，与三种其他历史/记忆查询共享每任务三次额度，非法参数也计入；最多 7 条不代表消耗 7 次。模型必须区分来源与推断，历史文字不构成新指令或动作授权。

沿用当前任务绑定范围、角色白名单及停止检查，不改写档案、不调用 OneBot 或识图。无需新增 QQ 开关，使用新构建生效。后台搜索结果现也可手动“查看前后事件”，固定前后各一条，入口、HTTP 参数与归档模式限制见[人工核对说明](agent-archive.md#人工核对前后事件)；后台查询不占模型任务额度。真实模型理解效果未验收。

### 按实际扫描进度继续检索

可要求机器人“如果还没查完，继续查更早的记录，再核对来源原文”。新构建的 search_history 成功回执增加 searchMore 和可选字符串 nextBefore；仅 searchMore=true 时，可把实际返回的 nextBefore 作为下次 before，沿用原关键词、数量和 from/until 条件继续。不要自行从最后一条结果推算继续位置。模型决定是否继续，不保证每次自然语言请求触发，也不自动重试。

继续位置按已经完整处理的来源序号计算，可能指向未命中的记录；它不是最后匹配项编号，也不代表下一次一定有匹配。超过扫描行数或正文字节预算时，即使 sources 为空，也可返回继续位置。达到结果条数或返回字节上限时，尚未返回的匹配仍在下次范围内，不会因先裁剪结果而跳过。请求的 limit（1～20）现在直接约束读取结果，省略仍为 20。

partial 表示本次覆盖不完整，可能只因正文截断、超大记录跳过或旧时间无效；此时若已扫描完当前范围，searchMore=false 且没有 nextBefore，不能把 partial 一律当作可翻页。有继续位置也只是允许再查，不代表在三次额度内能覆盖所有历史。

首次查询、继续查询、read_history 及记忆查询仍共用每任务三次额度，非法尝试也计入；例如搜索一次、继续一次、再核对一条来源，恰好使用三次。每次仍受 5,000 条/4 MiB 扫描、20 条/16 KiB 返回限制，下一次按当前存储与最新重置边界独立读取，不是冻结快照。绑定的机器人、群或私聊及角色权限保持，继续位置不能用于其他会话，不调用 OneBot、不新增配置开关。使用新构建生效；后台页面可手动点击“继续搜索更早记录”，操作见[档案说明](agent-archive.md#按实际进度继续搜索)，后台只读查询不占模型任务额度。

### 按保存时间检索历史

在已启用 Agent 且允许响应的群或私聊中，可提出“查北京时间 2026 年 10 月 15 日提过的约定，并标明来源”。模型可为 search_history 增加 from/until，例如 `{"action":"search_history","params":{"keyword":"约定","from":"2026-10-15T00:00:00+08:00","until":"2026-10-16T00:00:00+08:00","limit":5}}`。两个时间均可省略或为空串，起点包含、终点不包含；都提供时起点须早于终点。时间须为带时区的 RFC3339 字符串，可保留纳秒；时区不明确时不应由模型猜测。

依据为服务器写入档案的保存时刻，不是 QQ 消息中的 time 字段或动作执行时刻。成功响应在原 sources/partial/scanned/note 之外，仅对已应用的端点返回 UTC from/until；不带时间的查询和 read_history 不返回这两项。模型应结合回执与来源记录判断，不得把请求中的日期当作已检索成功的证据。模型决定是否调用，不能保证每次自然语言请求都执行。

可同时使用 before，含义仍是来源序号严格小于边界；时间条件不会改绑机器人或会话，也不允许包含最近重置前记录和工具记录。时间范围在原每次 5,000 条及 4 MiB 扫描预算内过滤，范围外条目仍计入预算；未知旧时间跳过并标明 partial，较旧日期未命中不能推断不存在。仍最多返回 20 个/16 KiB 片段，后续可用实际来源 seq 调用 read_history，读取沿用当前重置范围，不重新应用日期过滤。

带时间、无时间和非法参数尝试均与历史/记忆四类查询共用任务三次额度，后台任务摘要按原类型累计，重建查询助手不重置额度。非法时间返回本地参数错误，存储故障返回读取失败，不伪装为空来源；历史保存时间条件不用于 read_memory/read_history；search_memory 使用独立的当前修订时间条件，见下文。权限沿用原角色白名单及任务检查，不调用 OneBot、不新增发送或管理权限。使用新构建后生效，无新增开关；后台时间搜索入口见[档案说明](agent-archive.md)。

### 按来源序号继续检索

可要求机器人“继续查这条之前提过的内容”。`search_history` 新增可选 `before` 参数，须为来源序号的正整数字符串，例如 `{"action":"search_history","params":{"keyword":"约定","limit":5,"before":"23"}}` 只检索序号小于 23 的事件；不包含 23 本身。省略时仍从最新记录开始。该参数按档案序号限定先后，不是日期，也不要求边界记录仍存在。

模型是否继续检索由其决定。带边界的查询仍只查当前机器人、当前群或私聊，仍排除最近重置前的记录和工具记录；与无边界检索、`read_history`、`search_memory` 及 `read_memory` 共用每任务三次额度。每次仍受 5,000 条扫描、4 MiB 正文、最多 20 个片段和 16 KiB 返回总量限制，不会无限向前翻页。空结果只说明本次限定范围内的已检查内容未命中，不能宣称全部历史不存在。后台网页也提供独立的序号边界输入及“查此条之前”按钮，见[档案说明](agent-archive.md)。

在已启用 Agent 且允许响应的群或私聊中，可要求机器人查找以前提过的内容。模型获得本地动作 `search_history`，是否检索由模型决定，不保证自然语言指令每次都会触发；无需新增 QQ 配置命令。

执行范围由任务绑定的机器人和当前会话决定。模型只能传关键词、可选的 1～20 条返回数量及上述来源/时间边界，不能指定其他账号、群、私聊或文件路径。沿用现有角色白名单，新增检索不会授予发送或群管理权限，非主人私聊仍受原发送权限限制。

历史检索、按来源读取与长期记忆查询每任务合计最多 3 次。后台[任务摘要](agent-tasks.md)可核对实际已用额度、查询类型、空结果、覆盖不完整及错误，查看摘要本身不消耗额度。历史查询仅处理最近上下文重置之后的事件，不读取工具请求或旧检索结果。字面匹配区分大小写，关键词最多 128 个字符；每次历史检索最多扫描最近 5,000 个事件和 4 MiB 正文，最多返回 20 个片段、合计 16 KiB。单条超过 64 KiB 则跳过，返回覆盖不完整标识。

若检索片段不够完整，可要求机器人“继续核对来源原文”。模型可使用新增本地动作 `read_history`，以 `seq` 正整数字符串指定来源序号；例如 `{"action":"read_history","params":{"seq":"23"}}`。模型是否调用由其决定，不保证自然语言请求每次触发。机器人和群/私聊由当前任务注入，不能由模型指定；序号读取也遵守最近重置边界，只允许历史事件。

省略 context 或为 0 时，一次最多返回一条、8,000 UTF-8 字节的脱敏正文，超过 64 KiB 的记录只返回占位；截断时条目 `truncated` 和响应 `partial` 均为真。它不是完整正文或向更早记录翻页的接口，也不会触发图片描述。不存在、其他会话或重置前的序号返回空来源；读取失败返回错误，不能据此推断历史不存在。历史查询与记忆检索/读取共用三次额度（非法参数尝试也计入），仍走原任务停止、权限及有限上下文预算，不转发 OneBot。

检索结果包含来源序号、时间和脱敏节选，模型被要求区分引用和推断；查不到或读取失败不能编造历史。结果进入现有有限上下文预算，存盘不等于每次模型请求都能看到。检索是本地读操作，不转发到 OneBot；后续向模型发送的上下文会包含检索片段。跨会话调用、超过次数和不合法动作不会放宽权限。

## Agent 检索长期记忆

### 按当前修订时间检索记忆

运行新构建，在已启用 Agent 的会话中可要求“查看今天保存或修改过的记忆”。模型可调用 `{"action":"search_memory","params":{"from":"2026-10-16T00:00:00+08:00","until":"2026-10-17T00:00:00+08:00","limit":5}}`；也可组合 keyword、source 和记忆编号 before。指定有效的单端或双端时间后，可省略或留空关键词，无需新增配置或 QQ 权限。模型是否查询及能否正确理解自然语言时间，仍取决于实际模型。

from 包含开始时刻，until 不包含结束时刻；均为带时区的 RFC3339 时间，支持纳秒，双端时开始必须早于结束。条件匹配当前版本的 updatedAt：新保存、正文编辑、启用/停用及恢复旧内容都会更新此时间；不是最初创建时间、触发消息时间，也不检索历史修订。重复保存复用既有条目时沿用原保存时间。来源筛选仍表示当前版本来源，不能用时间推断原作者或授权。

Agent 始终只检索当前机器人、群或私聊中的启用独立记忆。响应以 UTC 的 from/until 回显实际边界，未指定的边界省略；继续时保留该条件、关键词、来源、limit，并以实际 nextBefore 作为 before。结果仍按记忆编号倒序，不按修订时间排序；后续编辑或启停可能使条目进入或离开条件，查询不是冻结快照。缺失、无效或零值的旧时间跳过并标明 partial，不根据其他字段补造。

时间条件在原有界扫描内判断，保持单次 5,000 条/4 MiB 扫描、20 条/16 KiB 片段及 UTF-8 截断规则。可能出现本批空结果但 searchMore=true，此时沿实际位置继续；没有命中不能证明全部记忆不存在。与历史及记忆查询共用每任务三次额度，非法时间尝试也计入，重建助手不重置；read_memory 仍独立按编号和精确版本读取，不接受 from/until。无数据库迁移或额外后台计时任务。

后台登录后，在“Agent 会话”读取已连接机器人对应会话和独立记忆，填写“修订开始时间”和/或“修订结束时间”，点击“搜索记忆”。日期输入使用浏览器所在本机时区，提交时转换为 UTC；页面显示实际应用边界。可与关键词、来源和“搜索状态”组合，例如查询今天停用的当前条目；后台停用/全部结果仅供管理，不会装入 Agent。时间表示最后一次修订，不能据此列出今天曾经停用、后来又恢复的全部过程。

“继续搜索更早记忆”和“查此条之前”保留本批已应用条件，不使用尚未提交的时间草稿。清空时间后重新搜索可取消范围；没有关键词、具体来源或有效时间时不发请求。重新读取记忆、切换范围、退出及保存清理会取消旧条件；失败清除旧继续位置，迟到响应沿用原范围检查。精确正文、来源及当前版本定位独立于搜索时间。

后台沿用 `POST /api/agent/memories/search`，新增可选字符串 from/until，规则与模型相同；可与后台 state=active/disabled/all 组合，默认 active。GET 记忆入口拒绝时间查询参数，修订、创建和迁移操作不接受非空时间条件。沿用后台登录、CSRF、no-store、并发、搜索频率和超时，不调用模型/OneBot，也不消耗模型任务额度。真实模型和 QQ 体验待验收。

### 按记忆来源检索

运行新构建后，可在已启用 Agent 的会话中要求“查后台录入或修订的偏好记忆”。模型可调用 `{"action":"search_memory","params":{"keyword":"偏好","source":"admin","limit":5}}`，只检索当前机器人、群或私聊中该来源的启用独立记忆。是否调用由模型决定，沿用原角色白名单；无需新增配置或权限。

| source | 当前版本来源 |
| --- | --- |
| 省略或空串 | 不限来源，保留原搜索行为 |
| agent | Agent 保存 |
| admin | 后台录入、修改正文或从旧版本恢复 |
| legacy | 已显式迁移的旧文件条目 |

来源按当前条目的 source 字段匹配，不代表最初作者、用户原话或动作授权。Agent 记忆经后台修改正文后归入 admin；仅启停不改变来源，旧修订不会因筛选而开放。尚未迁移的旧文件仍不可搜索，未知旧来源只在不限来源时参与原检索，不归入已知类别。

指定有效的 agent/admin/legacy 来源时，keyword 可省略、留空或仅含空白。例如要求“看看后台录入了哪些记忆”，可调用 `{"action":"search_memory","params":{"source":"admin","limit":5}}`。未限定具体来源和修订时间时仍须关键词；仅传 before 或 limit 不构成查询条件。无关键词时从每条脱敏正文开头截取片段，仍按记忆编号倒序，不代表最近修订时间顺序。可与 limit 和记忆编号 before 组合。先限定当前会话、启用状态和来源，再沿原编号倒序及 5,000 条/4 MiB 扫描、20 条/16 KiB 返回预算检索。响应仅在筛选时返回 source 条件；继续查询须沿用该条件、关键词及实际 nextBefore，仍与其他查询共用每任务三次额度。每次读取当前状态，不冻结版本；按 id/revision 读取正文不继承搜索来源。

后台登录后，在“Agent 会话”读取目标会话和记忆，选择“记忆来源（当前版本）”，按需填写关键词后点击搜索。选择具体来源时可留空关键词；选择“全部来源”且未指定修订时间时须填写关键词。“继续搜索更早记忆”和“查此条之前”保留该批已应用的来源，不使用尚未提交的草稿。选择“全部来源”再搜索可取消条件；重新读取记忆、切换范围、退出和保存后的搜索清理会取消旧来源。只读搜索不调用模型或 OneBot，也不占模型任务额度，原后台认证、频率与超时限制保持。

接口沿用 `POST /api/agent/memories/search`，新增可选 source 字符串，只接受表中取值；GET 记忆接口不接受 source，其他动作不能带非空来源条件。无存储结构迁移，真实模型的来源筛选效果待验收。

### 按实际进度继续检索记忆

可要求机器人“没查完就继续查更早的记忆，并核对正文”。新构建的 search_memory 成功回执增加 searchMore 和可选字符串 nextBefore；仅 searchMore=true 时，模型可把实际 nextBefore 用作下一次 before，沿用关键词与 limit。该编号是记忆 id，不是档案来源序号或修订号，可能来自已检查但未命中的记忆；不要从最后返回条目推算它。模型决定是否继续，不保证每次自然语言请求触发。

达到 5,000 条或 4 MiB 扫描上限时，即使当前 memories 为空也可取得继续位置；达到返回条数或 16 KiB 上限时，不跳过尚未返回的匹配。只有片段截断或超大正文跳过而已扫描完当前范围时，partial=true 但 searchMore=false，不补造下一批。继续不保证能找到结果，也不代表所有记忆已覆盖。

每次按当前启用状态、正文和版本重新读取，不延续冻结快照；停用与旧版本不会因继续位置而开放。记忆仍按当前机器人和群/私聊隔离，不受聊天重置影响；未迁移旧文件不提供继续位置。search_memory、read_memory 及两种历史查询共用每任务三次额度，非法尝试也计入，助手重建不重置。两次搜索后再用实际 id/revision 核对一次正文恰好用满三次；read_memory 不返回搜索继续位置。

后台操作：先在“Agent 会话”读取档案，再点击“读取记忆”，输入关键词或选择具体记忆来源后搜索。有有效继续位置时会出现“继续搜索更早记忆”，空结果也可点击；使用已加载会话和该批关键词，不使用输入草稿。新批结果替换旧批，不自动请求或重试。仍保留每条结果的“查此条之前”，它按所点条目 id 查询，两者的边界含义不同。

回执缺失、不是独立存储、编号无效或不再前进时隐藏继续入口。新搜索、重新读取记忆、切换范围、退出及记忆保存尝试会清除旧继续位置；保存结果未知时须重新读取核对。无效表单草稿保留先前成功结果，迟到响应不能恢复旧状态。编辑窗口或写入期间禁止继续操作。后台手动查询不占模型任务额度，但每次仍受原扫描/返回预算、并发、频率和超时限制。

入口权限、角色白名单和作用范围保持；后台需登录且机器人当前已连接。只读查询不改写记忆、不调用 OneBot、不授予新平台权限；Agent 的检索结果仍进入后续模型上下文并受原预算限制。新构建生效，无新增配置开关。

### 继续查询更早的记忆

在已启用 Agent 且允许响应的会话中，可要求机器人“继续查这条编号之前的记忆”。`search_memory` 支持可选 `before`，须为记忆编号的正整数字符串，例如 `{"action":"search_memory","params":{"keyword":"偏好","limit":5,"before":"23"}}` 只搜索编号小于 23 的当前启用记忆，不包含 23 本身。省略时仍从最新编号开始。可从已知记忆结果取得编号；边界条目即使已停用或不存在，仍按数值限定范围。

此处 `before` 是记忆 `id`，不是档案 `sourceSeq`、修订号或日期。修订不会改变记忆编号，搜索仍读取当前启用修订，不读取旧版本。每次查询重新读取当前状态，期间新增的较大编号不进入已指定的边界范围；这不是固定快照，也不保证连续查询期间的启停变化没有遗漏。

范围由任务固定为当前机器人、当前群或私聊，沿用原角色白名单与任务停止机制。带边界和不带边界的记忆搜索、记忆正文读取及两种历史查询合计每任务仍最多三次，非法尝试也计入。单次仍最多扫描 5,000 条/4 MiB、返回 20 个/16 KiB 片段；不能借边界无限翻页。没有结果只说明本次限定范围的已检查内容未命中，覆盖不完整时仍有 `partial` 标记。

模型决定是否继续查询，不保证自然语言请求每次触发。该动作不改记忆或旧文件，不转发 OneBot，不受聊天重置边界影响；后续模型输入仍受容量预算限制。后台网页也支持独立填写记忆编号边界及从结果继续查询，见下方后台搜索说明。实现需要使用新构建。

### 默认检索与返回结果

可在任务页的上下文摘要核对“记忆检索/读取响应片段”数量。它统计实际装入历史上下文且可解析的记忆响应，不等于直接装载的启用记忆条数，也不保证唯一或目前仍有效。旧摘要与零条结果分别提示；详细口径见[任务说明](agent-tasks.md)。

在已启用 Agent 且允许响应的会话中，可要求机器人“查找以前保存的某项记忆”。新增本地动作 `search_memory`，例如 `{"action":"search_memory","params":{"keyword":"偏好","limit":5}}`。模型决定是否调用；无需新增 QQ 配置命令。机器人和群/私聊由当前任务绑定，模型只可传关键词、可选 1～20 条数量、记忆编号边界 `before` 及上述来源 source，不能指定其他范围、文件、启停状态或历史版本。

只搜索当前独立存储的启用记忆，包括未进入初始默认 100 条/30,000 字节装载范围的条目。按记忆编号从新到旧扫描，指定 `before` 时先限定编号范围，再扫描最多 5,000 条及 4 MiB 正文；采用脱敏后的区分大小写字面匹配，关键词最多 128 个字符，查询使用三秒超时。最多返回 20 个片段，每条最多 2,000 UTF-8 字节，正文片段总量最多 16 KiB。超过 64 KiB 的异常单条跳过；超扫描、结果或字节限制及片段截断均返回 `partial=true`。没有结果只表示已检查的范围未命中。

返回 `memories` 数组，包含记忆 `id/revision/source/sourceSeq/active/updatedAt/text/truncated`，编号、版本和来源序号均为字符串。记忆可能是 Agent 提取或后台修订，不能当作用户逐字原话或动作授权；可在后台用编号、版本和来源进一步核对。响应同时包含 `available/mode/partial/scanned/note`。未迁移旧文件、迁移待完成或旧文件已归属其他机器人时 `available=false`，不会搜索或展示旧正文；读取失败返回错误，不能当作没有记忆。

长期记忆沿用原持久化语义，不因聊天上下文重置而停用，因此该检索不受聊天重置边界影响；停用条目和旧修订不参与查询。历史检索、来源读取、记忆检索及精确版本读取共用每任务三次额度（非法参数也计入）。检索本身不修改、恢复或新增记忆，不转发 OneBot，不触发图片描述；结果通过现有历史响应进入后续模型上下文并受其预算约束，不保证每条结果最终装入。任务累计摘要将其计为本地动作；原长期记忆准备条数仍只统计直接装载的记忆，检索结果包含在历史正文容量中。

### 按编号和版本核对记忆正文

检索片段不足时，可要求机器人“继续核对这条记忆的正文”。模型可调用 `read_memory`，例如 `{"action":"read_memory","params":{"id":"23","revision":"4"}}`，编号和修订号均须为正整数字符串，并取自已知记忆信息。它读取当前机器人、当前会话中仍启用且修订号完全匹配的条目；分层记忆候选还允许读取主人显式共享的永久知识，跨会话来源序号不提供。不能读取其他会话的非共享条目、停用条目或旧版本。

最多返回一条 8,000 UTF-8 字节的脱敏正文及原编号、版本和来源；超过 64 KiB 的异常正文只返回占位，截断时 `truncated/partial` 为真。正常记忆保存仍受原 4,000 字节输入限制。正文仍是记忆资料，不保证是用户原话。已修订、已停用、编号不存在或不属于当前会话时返回空 `memories`，应重新检索核对，不能凭空复原；读取失败返回错误。未迁移旧文件不允许通过该动作读取。

`search_history`、`read_history`、`search_memory`、`read_memory` 每任务合计最多三次，非法参数也计入。读取本身不保存或启用记忆、不调用 OneBot、不触发图片描述，仍受任务停止和有限模型上下文预算约束；任务累计摘要归入本地动作。聊天重置不改变独立记忆的启用状态，读取沿用长期记忆的现有持久化范围。后台查看历史版本仍按下述管理入口操作。

## 查看与修订长期记忆

### 按编号定位当前记忆

登录后台，在“Agent 会话”选择已连接机器人及群或私聊，读取档案并点击“读取记忆”。在“按记忆编号定位当前版本”填写已知的记忆 id，点击“定位当前记忆”。编号可以来自 Agent 保存/查询回执；搜索结果也提供同名按钮，无需先逐页查到该条列表记录。填写的是记忆编号，不是修订号或档案来源序号。

定位区独立显示当前版本、启停状态、脱敏正文与来源。它可读取列表当前页之外的条目及已停用条目，不继承列表启停筛选或搜索关键词/来源条件。读取固定使用已加载的机器人和会话，未提交的范围草稿不改变目标；同号群与私聊分别查找。列表、搜索结果和分页保持原读取状态；重新定位会清除旧定位、版本和来源面板。

点击定位结果的“修订或启停”打开原编辑窗口，明确确认保存才写入；窗口采用定位时的当前正文和修订号，搜索片段及其旧修订不会作为编辑正文。也可查看版本、比较或恢复较早正文、核对来源，仍沿用原版本冲突检查和保存规则。之后若有其他修改，旧修订提交会冲突，需重新定位后核对。定位本身不新增修订，不调用模型或 OneBot，也不占 Agent 任务查询额度。

未找到条目、独立记忆不可用与读取失败分别提示。旧文件尚未迁移或已归属其他机器人时不展示旧正文；失败或迟到响应不能保留旧定位卡片。重新读取/翻页记忆、切换范围或退出会清空定位；保存尝试会清除已定位的旧版本，保存成功或结果未知后均应重新读取核对，不自动重放保存。

只读接口为 `GET /api/agent/memories/current?botId=12345678&type=group&id=10001&memoryId=23`，要求后台登录和机器人当前已连接，沿用五秒请求上下文、Agent 操作并发限制与 no-store。memoryId 为正整数字符串，不能混用 after/state/revision/before/source；定位不应用搜索关键词。返回原 MemoryView 结构：mode 和最多一条 items，没有后续分页；未找到时 items 为空。该入口只供后台管理，模型 read_memory 仍须精确版本且只读启用条目。新构建生效，无新增配置。

### 后台新增记忆

登录后台并读取目标会话的记忆后，点击“新增记忆”。此入口仅在已连接机器人的独立记忆存储中可用；旧文件尚未归属、迁移待完成或已归属其他机器人的模式需先处理归属，不能直接写入旧文件。窗口显示已加载的机器人和群/私聊，未提交的范围输入不会改变保存目标。

填写非空单行正文（最多 4,000 UTF-8 字节），点击“确认保存”才写入；“取消”不保存。新条目默认启用，修订号为 1，属于后台来源，来源档案未知，不补造聊天消息。正文按当前配置脱敏；首个版本与正文在同一事务内保存，失败回滚。成功后重新读取列表核对，启用的新记忆对后续模型准备生效，仍受条数和字节预算限制。

如果同一机器人、同一会话已有归一化和脱敏后完全相同的启用正文，则复用原条目，不新增编号或版本，不改原来源、时间；页面分别提示已新增或已复用。仅存在相同的停用条目时会新建启用条目，旧停用版本保持不变。它不做语义合并，也不会自动清理已有重复。

保存期间阻止导航与重复点击，保存结果未知或归属冲突时关闭窗口并重新读取核对，不自动重试。退出或登录失效仍不能撤销已到达服务端的写入。新增成功会清空列表、版本、搜索结果和来源面板，等待重新读取，不自动加载假定的成功内容。

接口 `POST /api/agent/memories/create` 只接受 `botId/type/id/text`，要求登录、来源和 CSRF 校验；不可混用修订编号、迁移票据或搜索参数。成功响应含 `saved/created/item`，`created=false` 表示复用，条目编号和版本为字符串，响应 no-store。操作不调用模型或 OneBot。

### Agent 保存回执与后续读取

运行新构建、启用 Agent 并允许该会话响应后，`save_memory` 成功会向后续模型上下文返回保存回执，无需新增 QQ 指令或配置。动作仍只接受单行 `text`，机器人、会话和触发来源由宿主固定；模型不能指定记忆编号、修订号或其他范围。

独立存储的回执为 `mode="managed"`，`created=true` 表示新建，`created=false` 表示复用已有相同启用正文；`memory` 包含 `id/revision/source/sourceSeq`。编号、修订及来源序号以字符串返回，保持 int64 精度，不是平台消息编号或任务编号。回执不再次携带记忆正文。例如复用后台修订后的条目可返回：

```json
{"status":"ok","data":{"mode":"managed","created":false,"memory":{"id":"23","revision":"2","source":"admin","sourceSeq":"0"}}}
```

模型可从实际回执取得 `memory.id` 和 `memory.revision`，再用既有 `read_memory` 在原会话按精确版本核对正文。保存本身不消耗三次共享查询额度，后续读取消耗一次；是否继续读取仍由模型决定。保存回执不是模型已阅读或永远可读的证明，后续被修订或停用时，旧编号/版本读取依旧返回空结果，应重新核对。

新建条目只有正文与首个修订事务提交后才返回编号。复用保留原条目的编号、当前版本、来源和时间，可能是 Agent、后台或旧文件导入的来源；其来源不自动改为本次触发消息。同文并发保存只新建一次，其余返回复用同一引用。只存在停用条目时会新建启用记忆，旧停用历史保持不变。后台可以重新读取记忆及会话档案核对回执，读取要求登录及机器人已连接。

尚未迁移的旧文本文件继续按原方式追加，回执只有 `{"mode":"legacy"}`，没有 `created` 或 `memory`，不补造编号、版本或去重结果，也不能用 `read_memory` 直接读取旧文件。来源校验、配置读取或保存失败不返回成功引用；保存之后回执入档失败也会停止任务，实际写入可能已完成，需在后台核对，不自动重试或宣称已回滚。没有收到本次成功回执时不能使用旧回执认定当前保存成功。

开发者可调用 `MemoryStore.SaveFromSequenceResult` 获取仅含元数据的结果；旧 `Save/SaveFrom/SaveFromSequence` 保留原错误接口并丢弃回执。SDK 动作说明标为宿主可选回执，通用 SDK 自动保存和旧构建仍可能返回 `null`，不能自行补造元数据。功能需新构建。

### Agent 保存时的准确触发来源

新构建的消息入口在任务启动时捕获当前事件实际入档的准确序号，任务和该任务新建的独立记忆使用同一来源。无需新增配置，`save_memory` 仍只接受单行 `text`；机器人、群或私聊及来源序号由宿主固定，模型不能指定。来源指向触发任务的事件，不保证记忆中的每一句都来自该条消息，也不把 Agent 提取标成用户明确要求。

登录后台，读取已连接机器人的目标会话长期记忆，在“Agent 保存”条目旁点击既有的“查看来源”，可核对该序号对应的脱敏事件；也可从[任务摘要](agent-tasks.md)查看触发消息。读取包含重置前来源，只读、不重新装入模型，仍受有界正文和会话隔离限制。平台消息编号重复、模型等待时收到其他消息或事件已超出最近 5,000 条，都不会让保存改绑到较新的消息。

没有捕获档案序号时来源明确为未知（`sourceSeq="0"`），不再按平台消息编号或最新事件推断。非零序号必须属于本机器人库内同一会话的事件；来源缺失、跨会话、非事件或存储不可读时保存失败，包括正文已存在的去重调用。零来源兼容原无来源调用；旧记忆保留原元数据，不自动修正已有来源。未迁移的旧文本文件沿用原保存方式，没有单条来源元数据。

开发者内部调用 `MemoryStore.SaveFromSequence` 传入宿主捕获的序号；旧 `Save` 和仅持有平台消息编号的 `SaveFrom` 保留保存兼容，但新建条目来源为未知。首次正文和修订仍在同一事务写入，失败回滚。重复保存复用已有启用记忆时保留它最初的来源、版本和时间，因此该记忆来源可能与本次重复触发任务不同，不能据此认为首次来源已更新。功能需新构建。

### Agent 重复保存的处理

运行包含本功能的新构建后，Agent 的 `save_memory` 在独立记忆存储中自动去重，无需新增配置或 QQ 指令。保存前按现有规则去除正文首尾空白、隐藏当前配置的密钥，再与同一机器人、同一会话内的启用记忆做区分大小写的精确比较。已有相同正文时返回成功并复用原条目，不新增编号、修订或时间，不改变原来源；相同内容的并发保存也只新增一条。可以在后台重新读取记忆及版本核对。

不同措辞、大小写或正文内部空白不会自动合并；不同机器人、群与同号私聊分别处理。此功能不清理数据库已有重复条目，不合并后台修订或恢复形成的重复内容，也不改变未迁移旧文件的保存行为。仅有停用条目时，后续 Agent 保存会沿用原行为新建启用条目，旧停用记录保持不变；停用单条记忆不等于禁止未来再次记住同样内容。存储读取失败仍报告失败，不以去重为由伪装保存成功。

### 按启停状态搜索记忆

运行新构建，登录后台，在“Agent 会话”读取已连接机器人对应群或私聊的档案和记忆后，在“搜索记忆”的“搜索状态”选择“仅启用”“仅停用”或“全部”，输入关键词或选择具体来源，再点击“搜索记忆”。默认仅启用；只选状态不能替代关键词或具体来源。不新增 QQ 权限，范围固定为已加载会话。

搜索状态与上方记忆列表的启停筛选互相独立，选择后点击搜索才应用。结果标明每条当前版本的启停状态；“继续搜索更早记忆”和“查此条之前”保留该批状态、关键词及来源，忽略草稿。先按会话、状态、来源和编号筛选，再使用原有 5,000 条/4 MiB 扫描及 20 条/16 KiB 返回预算，只查询当前版本，不搜索历史修订或未迁移旧文件。期间启停改变时以再次读取的当前状态为准。

找到停用条目后，点击“定位当前记忆”读取最新完整正文，再选择“修订或启停”并恢复。停用片段本身不提供启用版本正文读取或直接保存；原精确版本读取仍拒绝停用条目。搜索、定位不会自动恢复或装入 Agent，只有确认恢复并保存成功后才按原规则生效；若期间有新修订，保存仍检查版本冲突。

重新读取列表、翻页、保存后的搜索清理、切换范围和退出会把搜索状态恢复为仅启用，迟到响应不回填。POST 搜索接口新增可选 state=active/disabled/all，省略或空串为 active，响应 state 表示已应用条件；状态不能与新增、修订或迁移请求混用。GET 列表的 state 仍为列表筛选，精确读取及当前版本定位不接受搜索状态。原认证、CSRF、no-store、频率和超时保持，不新增接口或数据库结构。Agent 的 search_memory 不接受 state 参数，始终只返回启用条目，三次共享查询额度不变。真实使用效果待验收。

### 后台搜索启用记忆

登录后台并读取目标会话的长期记忆后，在“搜索记忆”输入关键词，或选择具体记忆来源、指定修订时间并留空关键词，点击“搜索记忆”。需要运行包含本功能的新构建、机器人当前已连接且该范围为独立记忆存储；未归属旧文件和待完成迁移模式不提供搜索按钮。查询固定为已加载的机器人、群或私聊，未提交的范围输入不会改变目标。列表的启停筛选不改变搜索范围：搜索默认只查启用条目，可在独立的“搜索状态”中选择停用或全部。

可选填写“仅查此记忆编号之前”，须为正整数字符串，最大为 9223372036854775807。例如填写 23，只搜索记忆编号小于 23 的当前启用条目，不包含 23 本身；留空从最新记忆查起。它不是档案来源序号、修订号或日期，不要求边界条目仍存在。当前搜索状态显示已应用关键词和编号范围，后续修改输入仅为草稿，点击搜索后才应用。

结果旁的“查此条之前”使用该次结果的原关键词、已加载会话及此记忆编号继续向前查询，忽略未应用的关键词和边界草稿，并回填实际条件。新结果替换上一批片段，原记忆列表、筛选和分页位置保留。修改、停用或恢复不会改变编号；带边界查询仍读取符合搜索状态的当前版本，是每次读取时的结果，不是冻结快照，连续查询期间的启停变化可能导致遗漏。

关键词通过 POST 请求体传输，按脱敏后的区分大小写字面匹配；最多 128 个字符。复用 Agent 记忆检索的 5,000 条/4 MiB 扫描预算，最多返回 20 个只读片段，每片段 2,000 字节、合计正文 16 KiB；覆盖不完整或片段截断会提示。搜索结果和原列表分别显示，不改变原列表的筛选或下一页位置。没有命中不表示全部记忆不存在。

点击结果的“读取较长记忆正文”，按该条编号和精确修订号核对当前启用版本，最多显示 8,000 UTF-8 字节，异常超大正文只返回占位。结果已变更、停用或范围不可读时提示重新搜索；读取失败单独提示，保留的旧片段不当作本次核对成功。来源已知时可点击“查看来源”。结果只读，不提供修订/启停按钮，避免用截断片段直接覆盖完整正文；可点击“定位当前记忆”后管理，或继续在原记忆列表进行。

重新读取列表、翻页或成功保存记忆会清除搜索结果和编号边界，切换范围、退出或登录过期也会清空关键词，迟到响应不会回填。查询不调用模型或 OneBot，不写入记忆版本。后台搜索与档案搜索共享 250 毫秒间隔和两路操作并发限制，繁忙/失败时手动重试；后台查询不使用 Agent 每任务三次额度，单次预算仍保持有界，零结果不代表全部记忆不存在。

接口为 `POST /api/agent/memories/search`（`botId/type/id`、关键词 `keyword` 或具体来源 `source`，以及可选字符串 `before` 和 `state`，登录、来源和 CSRF 校验）与 `GET /api/agent/memories/read`（`botId/type/id/memoryId/revision`，登录校验）。搜索省略或空字符串 before 按无边界处理；非空 before 不能与新增、修订或迁移操作混用。GET 查询不接受 before，精确读取也不能与分页、状态筛选混用。响应正文均为 no-store，返回格式同上述 Agent 的记忆查询结果；关键词和边界经 POST 请求体传输。

### 任意两次历史修订对比

运行新构建，登录本机后台，在“Agent 会话”读取已连接机器人的目标群或私聊档案，再读取独立记忆，点击某条记忆的“查看版本”。版本区顶部提供“基准历史修订”和“目标历史修订”，填写两个修订号后点击“对比两次修订”，也可在输入框按 Enter。目标默认填入本页第一条修订号；按号定位单条后默认填入该修订，基准需自行填写。

两项都是同一条记忆的历史修订号，可跨历史页选择，不要求目标大于基准，也允许比较同一修订。修订号须为不超过 9223372036854775807 的正整数字符串，不能填写记忆编号或档案来源序号。表单绑定此次查看版本时已加载的机器人、会话和记忆编号，未提交的账号或会话草稿不会改变目标。

点击后依次读取两个精确历史修订，全部找到后才显示比较。删除线表示基准正文中的差异，下划线表示目标正文中的差异；Unicode 字符保持完整，多个修改点可能合并标示。启停状态独立显示，正文相同也可能有启停差异；内容经过脱敏，正文相同不证明原始资料完全相同。正文均为纯文本，不执行 HTML 或加载附件。

对比只读，不修订或启停记忆，也不改变当前记忆、列表、版本分页及搜索结果。任一修订未找到、范围尚无独立记忆、读取失败或回执不符时不显示半份对比，保留表单供手动重试，不自动重试。读取期间禁用控件；离开或切换范围后不继续第二次读取，迟到响应不回填。重新读取记忆、查看另一版本页、按号定位或保存清理版本区时，表单与对比结果一并重建，不保留选择。

原“对比当前版本”和“恢复此版本正文”仍按各自原流程使用；恢复仍要求核对当前版本并确认保存，新表单不提供直接恢复操作。权限沿用后台登录、已连接机器人、同一群或私聊及独立记忆模式。复用现有 `GET /api/agent/memories/revision`，每次比较最多两次读取，沿用原脱敏、容量及超时规则，无新接口、配置或存储结构，不调用模型/OneBot，不占 Agent 查询额度。真实环境体验待验收。

### 按修订号定位历史版本

运行新构建，登录后台，在“Agent 会话”读取已连接机器人对应群或私聊的长期记忆，点击条目的“查看版本”；也可先按记忆编号定位当前条目，再查看版本。在版本区填写“历史修订号”，点击“定位历史修订”，直接读取该条记忆保存的指定版本，无需逐页寻找。记忆编号由所点条目固定，修订号须为正整数字符串，最大 9223372036854775807，不是来源序号或另一条记忆编号。

定位显示该修订当时的脱敏正文、来源、保存时间及启停状态，允许核对旧版和当时停用的修订；不会修改当前正文、启停状态或新增修订。原记忆列表、搜索结果、状态筛选和列表分页保持。返回项必须与请求的记忆编号/修订号一致；不存在时明确提示当前会话内未找到，未迁移范围和读取失败分别提示，不将故障当作不存在。

定位旧版后，可沿用“对比当前版本”和“恢复此版本正文”。两者继续使用已加载的当前版本；若该条尚未加载当前版本，请先定位当前条目。对比只读；恢复仍须确认并提交当前版本号及目标修订号，由服务端生成新修订并保留当前启停状态，定位旧版不会自动启用或恢复。并发更新仍按原版本校验拒绝，需重新读取核对。

“返回最新版本”回到该条从新到旧的历史首页；直接定位不保留旧历史页继续位置，当前记忆列表分页保持不变。返回历史页后，“下一页版本”仍按原排他修订号继续。非法修订号不发请求并保留已有结果；实际读取失败会清除旧版本区及其分页按钮，需重新点击“查看版本”。离开、切换范围、退出或保存清理时取消旧结果，迟到响应不回填；版本区输入及按钮沿用请求期间禁用。

后台接口为 `GET /api/agent/memories/revision?botId=12345678&type=group&id=10001&memoryId=23&revision=4`，HEAD 同样只读。要求后台登录、机器人当前已连接，仅返回该账号和会话中的指定独立记忆修订。不能混用 after/state/order/before/source/from/until；返回既有 MemoryView：mode、最多一条 items、more=false，next 仍按修订号返回但没有继续页。缺失、其他范围或非独立存储时 items 为空；存储故障返回错误，响应 no-store，沿用 Agent 并发和五秒请求上下文。

不新增 QQ 权限、模型动作或数据库结构。此入口仅供后台管理；模型 read_memory 仍只读启用且修订号完全匹配的当前版本，不能通过历史定位获取旧版或停用正文。真实环境体验待验收。

### 从最新修订查看版本

运行新构建，登录后台，在“Agent 会话”读取已连接机器人目标群或私聊的长期记忆，点击条目的“查看版本”；也可先按编号定位当前记忆，再查看版本。历史默认从最新修订向前显示，包含各修订当时的正文、来源及启停状态，每页最多 50 条，状态文字标明当前排序和版本边界。“下一页版本”继续查看该页最后修订之前的历史，使用已加载的机器人、会话和记忆编号，不使用尚未提交的范围草稿；当前列表、状态筛选和分页位置保持。

查看期间产生的新修订不会插入后续较旧页面，再点击“查看版本”才从最新修订重新读取。历史不作为冻结快照；比较与恢复仍基于已加载的当前版本，期间有新修订时保存会按原规则拒绝版本冲突。原“对比当前版本”“恢复此版本正文”及来源核对保持，查看历史不会启用、恢复、写入版本或让模型读取停用条目。失败会清除旧版本页及其分页按钮，需重新查看；切换范围、离开或退出按原流程清空，迟到结果不回填。

接口沿用 GET /api/agent/memories，仅在提供 memoryId 的版本查询中支持 order=desc；可选 after 为排他的修订号边界，省略或空串从最新修订开始。next 是该页最后返回的修订号，more 为真时沿用 order=desc 并以 next 作为下一次 after；这不是记忆编号或来源序号，最大为 9223372036854775807，按字符串传输。省略 order、空串或 order=asc 保留原从早到晚及大于 after 的查询语义，原记忆列表接口排序不变。排序不能与启停状态筛选、正文读取、当前版本定位或写操作混用；state=all 与历史原行为一致。

权限仍属于后台登录用户，机器人须已连接，响应 no-store，不新增 QQ 权限、模型动作、数据库结构或接口。真实环境使用体验待验收。

### 后台查看与修订

“记忆状态”可选全部、仅启用或仅停用，选择后点击“读取记忆”应用并返回第一页。状态文字标明实际加载的筛选；“下一页记忆”沿用已加载的会话与筛选，不使用下拉框中尚未应用的选择。每页最多 50 条，按记忆编号向后读取；这是实时列表，不是冻结快照，翻页期间启停变化可能改变结果，应重新读取核对。启用不代表每次都进入模型，仍受下述条数和字节预算限制。

“查看版本”始终展示该条完整的修订序列，不过滤旧版本启停状态。修订、停用或恢复保存后，重新读取即可按所选状态核对；切换会话或退出会清空内容并将筛选恢复为全部。旧文件未归属、迁移未完成等模式仍显示原提示，不因筛选而暴露旧正文。该操作只读取列表，不调用模型或发送消息。

接口 `GET /api/agent/memories` 增加可选 `state=all|active|disabled`，省略或空值按全部处理；与 `after` 分页位置一起传递，历史版本查询 `memoryId` 只接受全部状态。权限和机器人/会话范围沿用现有记忆接口。

要核对某次 Agent 任务准备了多少长期记忆，读取同一会话的“任务状态”，查看新增的长期记忆取用摘要及容量限制原因。它记录当时实际准备的计数，不是当前列表总数；旧文件模式尚不提供最终输入计数。详见[任务说明](agent-tasks.md)。

1. 登录本机后台，进入“Agent 会话”，先选择机器人并读取目标群或私聊档案。
2. 在“长期记忆”点击“读取记忆”。权限属于后台密码持有者；群和同号私聊、不同机器人分别管理。仅支持当前已连接账号。
3. 独立存储的记忆显示编号、修订号、启停状态、来源及时间。来源“Agent 保存”的新条目使用任务启动时捕获的准确档案序号；没有捕获时为未知，不补造历史。重复保存保留已有条目的最初来源。后台修订标记为“后台修订”，旧文件导入明确标记原始来源未知。
4. 点击“修订或启停”，选择修改正文、停用或恢复启用，点击“确认保存”。正文须为非空单行且不超过 4,000 UTF-8 字节。取消不保存；发生版本冲突或提交结果未知时，关闭窗口并重新读取核对，不自动重试。
5. 点击“查看版本”浏览保留的旧版本。列表与版本均每页最多 50 条，通过对应下一页按钮继续；它们是读取时的结果，不是实时监控。
6. 有来源序号的当前记忆或历史版本可点击“查看来源”，在下方核对同一机器人、同一群或私聊的原档案片段。来源未知或旧文件导入的条目不提供按钮。

来源核对会显式包含上下文重置前的记录，但不会把旧消息重新送入模型，也不改变时间线的翻页位置。页面显示来源版本、序号、时间及脱敏纯文本；单条最多展示 8,000 UTF-8 字节，超过 64 KiB 的正文只显示占位，并提示截断。档案文件缺失、当前范围内没有对应记录和读取失败分别提示；不能把缺失来源当作记忆已被证实。切换会话、重新读取记忆或版本、保存修订及退出登录会清除来源内容。

修改对后续构建的模型请求生效。停用将该条排除出长期记忆提示，不删除原聊天、档案或旧版本；原聊天中的相关内容仍可能出现在上下文或历史检索中。已发出的模型请求不会被撤回。分层记忆候选中，模型从最多1,000条候选按词项相关性和个人/永久类型权重选取最多100条、约30,000 UTF-8字节；旧版本仍为按新旧加载。详见[分层记忆与滚动摘要](layered-memory.md)，不保证装载所有启用条目。

修订和启停写入同一事务并保留版本。新版本号不匹配时拒绝覆盖；页面切换、退出或登录过期清空记忆正文和迁移预览。保存过程中阻止页面导航与重复提交；强制关闭页面仍不能撤销已送达服务端的写入，应重新读取核对。

## 恢复历史版本的正文

恢复前可在较早版本旁点击“对比当前版本”。页面显示该历史正文和已加载当前正文，旧正文差异用删除线、当前正文差异用下划线标示，并单独显示两个版本的启停状态；正文相同会标明“脱敏后的正文相同”。多个修改点可能合并为一个高亮片段，这不是逐词或语义差异分析，也不能用脱敏后相同推断磁盘原文完全相同。

对比仅使用当前页面已读取的版本，不发请求、不保存修订。显示的是读取时的当前版本，其他窗口可能已产生新修订；需要时重新读取记忆再查看版本。点击“收起对比”清空对比正文，重新读取列表/版本、切换范围或退出也会清空。后台登录、连接账号与会话范围要求沿用记忆列表；实际恢复仍须确认并由服务端检查当前版本。

读取记忆后点击“查看版本”，在较早版本旁点击“恢复此版本正文”。确认窗口显示当前修订号、目标修订号、脱敏正文预览及当前启停状态；点击“取消”不写入，点击“确认保存”才执行恢复。需要后台登录权限，机器人必须当前已连接，范围固定为已读取的机器人和会话。

恢复从服务端历史记录读取正文，按当前配置脱敏后保存为新的“后台修订”，保留目标版本的来源序号和全部旧版本。当前启停状态保持不变：恢复停用记忆的正文不会重新启用它；需要时另行执行“恢复启用”。成功后重新读取记忆核对，新正文只影响后续加载该条启用记忆的模型请求，不撤回已发送请求。

保存携带当前版本与目标版本。其他窗口已修改、目标版本缺失或范围不匹配时拒绝覆盖；发生冲突、网络异常或结果未知时重新读取核对，不自动重试。恢复不会修改原聊天，不提供物理删除，也不会让浏览器提交的正文替代服务端历史版本。

接口沿用 `POST /api/agent/memories/update`，传入 `botId/type/id/memoryId/revision`，`action` 为 `revert`，额外传入正整数字符串 `targetRevision`（必须小于当前 `revision`），`text` 省略或为空。`restore` 仍仅表示恢复启用；其他操作不接受 `targetRevision`。

## 旧文件归属与迁移

原记忆为 `data/aichat/agent/<内部会话编号>.txt`，没有机器人维度。内部群号为正数，私聊用户编号为负数；网页仍填正整数并选择群或私聊。

若页面显示“旧文件尚未分配归属”，后台不展示原正文。迁移前机器人仍沿用旧文件行为，因此不能认为未迁移的旧记忆已经具备机器人隔离。请由所有者确认目标机器人后操作，不能仅凭同号会话自动推断归属。

1. 在目标机器人和会话下点击“预览旧文件迁移”。页面显示条数、字节数及目标，不调用模型，也不发送 QQ 消息。
2. 核对归属和回退限制。取消预览不会导入；预览五分钟有效，切换范围或登录失效后需重新预览。
3. 点击“确认归属并迁移”。先保存原文件的一致备份，再保留归属、核对来源摘要，并用单事务导入。相同来源重复提交不会重复导入；来源改变、已分配给其他机器人或新库已有独立范围时拒绝覆盖。
4. 重新读取记忆核对。原 `.txt` 保留，之后已迁移范围只写机器人独立数据库；其他机器人不会读取这份已归属的旧文件，其新记忆独立保存。

迁移限 1 MiB、最多 1,000 条有效非空行，每条最多 4,000 UTF-8 字节；不自动截断超限旧文件。未迁移文件的运行时读取也受 1 MiB 上限约束，超过时报告存储不可用，原文件不变。原文件的备份名为 `<会话编号>.<来源摘要>.bak`，归属记录为 `<会话编号>.owner.json`，均保存在原 agent 目录并设置私有权限。不要手工删除归属记录来重复分配。

提交前失败会回滚导入并释放本次新建归属，原文件保留。提交结果不确定或进程在保留归属后崩溃时，归属保持保留：先重新读取，若显示待完成，原机器人可重新预览并重试，其他机器人不能接管。若此时源文件被外部修改，需要先核对本机备份并恢复对应源文件，再重试，不能猜测归属。

## 存储与回退

新记忆及版本保存在每机器人现有 `data/aichat/history/<机器人QQ>.sqlite` 的独立表。打开记忆功能可能初始化空数据库和表结构，但不自动导入旧正文；现有历史表保持兼容。读取或配置失败会停止相应记忆操作，不把异常伪装成成功保存。

迁移前后均应保留档案数据库和整个 agent 目录。手工备份或恢复先停止 ZeroBot，复制完整目录及可能存在的 WAL/SHM；后台三类配置备份仍不包含这些资料。旧程序只认识旧 `.txt`，回退后不会自动获得新库里的新增或修订记忆；当前未提供旧格式导出和归属转移入口。只替换旧程序不等于数据回退完成。
