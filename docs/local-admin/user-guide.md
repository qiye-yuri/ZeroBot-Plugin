## 启动与登录

首次从源码安装：初始化data子模块，使用Go 1.26.1或满足go.mod要求的工具链编译，再按[Windows OneBot](onebot-windows.md)安装并配置本机QQ接入。下面的启动步骤适用于本机配置已经准备好的环境。

```powershell
git submodule update --init --recursive
.\scripts\build-windows.ps1
.\scripts\install-onebot.ps1
```

安装会在.local生成网络配置。启动前把.local/config.json中的示例主人QQ改为自己的账号，并创建.local/onebot/account.json，填写实际机器人账号，例如`{"expectedQQ":"87654321"}`；此处数字仅为格式示例，必须替换为自己的机器人QQ。首次扫码登录后运行test-onebot.ps1核对实际登录账号，再启动ZeroBot。后台默认启用情况由.local/admin/options.json和托管脚本控制；需要显式开启时运行configure-local-admin.ps1后重启ZeroBot。

在仓库根目录的 PowerShell 中执行：

```powershell
.\scripts\start-local-services.ps1 -Service OneBot
# 到 NapCat 登录机器人账号，首次登录可能需要扫码及手机确认
.\scripts\test-onebot.ps1
.\scripts\start-local-services.ps1 -Service ZeroBot
```

当前 NapCat 登录页为 <http://127.0.0.1:6099/webui/>，管理后台为 <http://127.0.0.1:3010/>。机器人账号按 `.local/onebot/account.json` 核对，主人账号按 `.local/config.json` 管理，两者用途不同。后台使用独立密码；重启 ZeroBot 后需要重新登录后台。首次未设置密码时按页面提示选择本机设置码文件并设置密码，密钥或密码不需要发到聊天中。

Chrome 自动打开本机后台首页支持顶层页面导航；跨站读取接口、嵌入页面和提交配置仍受来源及登录校验保护。导航修复需更新并重启 ZeroBot 后生效，排查步骤见 [浏览器恢复流程](operations.md#浏览器恢复流程)。

仅重启机器人时先执行 `stop-local-services.ps1 -Service ZeroBot`，再执行 `start-local-services.ps1 -Service ZeroBot`；NapCat 登录可以保留。完整启动、停止与恢复说明见 [运行维护](operations.md) 和 [Windows OneBot](onebot-windows.md)。

## 配置模型

1. 登录后台，进入“AI 设置”，点击“读取命名模型配置”。尚未迁移时只显示预览，不写库或调用模型。
2. 填写模型类型、地址、模型名和独立密钥，选择聊天/GPT/群总结、Agent、识图入口，再点击“备份并保存命名模型”。Agent/识图可停用，一个配置可由多个入口共用。
3. 查看基础字段检查；需要实际核对时，点击“测试聊天模型”或“测试 Agent 模型”。每次手动测试可能消耗额度，只使用已保存配置和固定短文字。未保存草稿不参与，成功不代表工具、识图或 QQ 收发已通过。
4. 配置修订冲突时重新读取并核对，模型失败不自动换配置或重试。新设置按既有生效规则使用，不需要为了普通保存而重启。

模型与密钥规则见[命名模型](named-models.md)，测试结果、费用提示和失败限制见[手动测试](model-probe.md)。需要完整业务用例时使用[真实模型测试脚本](real-model-test.md)：默认只读预检，显式 `-run` 才调用提供商。

## 普通聊天、Agent 与 GPT

显式语音命令为`发送AI语音要朗读的文字`：有效响应的群内限群主/管理员或机器人主人使用。群内直接发送一次，只使用当前群；私聊给出仅支持群聊的提示，不生成群语音。普通AI聊天的语音输出也仅作用于当前群，私聊保留文字。Agent文字动作和`/gpt`方式保持；语音配置不在控制库备份范围内，详见[QQ AI语音](qq-ai-voice.md)。

识图已配置为同一DeepSeek的`deepseek-flash`。在有效响应、已启用Agent的会话中同时发送QQ图片和文字提问，群内按规则@机器人，主人私聊直接发送。模型先描述图片，Agent再回答；纯图片可能不触发，`/gpt`仍是文字入口。使用与图片传输/缩放限制见[DeepSeek识图](deepseek-vision.md)。

机器人主人、群主、管理员、成员和非主人私聊的AI命令与Agent动作各按发言者权限执行。群主/管理员不是机器人主人，不能改全局模型或重置上下文；非主人群查询/动作仅限当前群，普通成员不能让Agent@全体成员。权限表、生效方式和测试范围见[AI角色权限](ai-role-permissions.md)。

可临时移除现有账号的主人资格来测试其他真实角色，须先备份、设置期限恢复并重启使身份生效。临时授予群管理员后，需同时核对消息成员缓存和实时`sender.role`；新鲜成员信息与事后历史查询不能替代实时身份。2026-10-13普通成员/非主人私聊GPT及管理员会话参数、主人专属开关拒绝已验证，原身份和配置已恢复；具体步骤和群主/Agent未验收范围见上述权限说明。

GPT引用文字时，先用QQ消息引用/回复功能选中原消息，再发送`/gpt 本次要求`。程序将引用原文与新要求分开提交给模型；引用卡片需实际存在，仅@不代表引用。普通单问和纯引用用法保持，仍遵守原权限、响应及同会话30秒限速。完整规则见[GPT引用原文与本次要求](gpt-quoted-message.md)，主人私聊测试步骤见[主人私聊联调](self-test.md)。

Agent 人物已改为 DeepSeek「鲸鱼娘」风格的 Q 版小人，蓝发蓝瞳、蓝白连帽衫，软萌、聪明，偶尔呆萌自嘲。后台「AI 设置」可查看或修改人物设定；新设定保留对话档案，停止服务时应用的设置在下次启动后使用。普通聊天、GPT 与总结仍采用独立的系统提示词。详细说明见 [小人人物设定](ai-persona.md)。

实际模型以后台已保存入口为准；普通聊天、Agent 与 GPT 的区别是上下文、输出及后续执行方式。

| 入口 | 行为 | 如何触发 |
| --- | --- | --- |
| 普通 AI 聊天 | 返回文字，使用近期内存上下文 | 当前会话关闭 Agent 后，@ 机器人发消息，或按配置概率响应非 @ 消息 |
| Agent | 生成 OneBot 动作，检查权限并执行，把动作结果交回模型；历史持久保存 | 当前会话开启 Agent 后，同样 @ 机器人发消息，或按配置概率触发；没有单独的 `/agent` 入口 |
| `/gpt 问题` | 使用聊天接口处理本次问题，不切换会话模式 | 直接发命令，或回复一条消息后发送 `/gpt 问题`；没有问题时可只发送 `/gpt` 使用被引用内容 |
| `群聊总结 200` | 读取指定数量群消息并调用聊天接口总结 | 群内由主人、群主或管理员发送；省略数量默认 200，最多 1000 |

**开启 Agent 后，普通聊天触发优先走 Agent，`/gpt` 和群聊总结仍使用聊天接口。** 其他插件的明确命令仍由原插件处理。Agent 未产生可执行动作时可能回退到普通聊天，所以“开启”不代表每次消息最终必定由 Agent 回复。

用机器人主人账号，在目标群或私聊发送以下指令；不加 `/` 前缀：

```text
查看AI聊天配置
设置AI聊天使用Agent模式
设置AI聊天不使用Agent模式
设置AI聊天响应AT
设置AI聊天触发概率0
```

每次只发送一条所需指令。模式、响应 @ 与触发概率按当前群/私聊分别保存；在主人私聊里修改，不会自动应用到目标群。群内可以 @ 机器人后发送配置指令。开启“响应 @”后，@ 消息不受随机触发概率限制；概率 0 不主动响应非 @ 消息。模式和响应 @ 由主人管理，触发概率也允许群管理员管理。后台的“使用 Agent 模式”对应同一个会话设置。

测试 Agent：在目标群开启模式后发送 `@机器人 你好，接着刚才的话题聊`。测试普通聊天：在同一会话关闭模式后再次 @ 发消息。测试单次 GPT：发送 `/gpt 请用一句话解释什么是 API`，不需要关闭 Agent。

还须满足 aichat/aichatcfg/llm 对应插件启用与会话响应条件。群内开启响应由主人、群主或管理员发送 `@机器人 /响应`；`/沉默` 同样需要 @ 和管理权限。全局响应覆盖群门控，相关规则见 [运行维护](operations.md)。普通成员私聊不能使用 Agent 的私聊发送动作；主人可用，普通聊天与 GPT 不依赖这项 Agent 动作权限。Agent 不增加发起者或机器人原本没有的管理权限。

GPT 与群总结共用每群/私聊 30 秒一次的额度，失败请求也计入；普通聊天与 Agent 不使用这项 GPT 限额。请求会把问题、所需上下文或群总结的昵称/文字发送到配置的模型接口。

## 服务列表与用法

私聊发送 `/服务列表`，群内 @ 机器人后发送同一命令，即可收到带使用方式的合并聊天记录。每页最多 20 个已加载插件，包含名称、说明、当前会话启用状态及注册用法；关闭的插件仍列出。发送 `/服务列表 2` 翻页，英文别名 `/service_list` 同样可用。

| AI 设置 | [命名模型与入口选择](named-models.md)、全局提示词/采样参数、[会话人物覆盖](conversation-persona.md)；各表单分别保存/放弃，基础检查不调用模型 |
| 运行日志 | 级别/关键词/起止时间与快捷范围统一应用；可暂停、读取一次、复制本条、清空显示和导出；统计/导出采用服务仍保留的脱敏日志，清空显示不删日志，最多 1000 条 |
| 备份恢复 | 按范围/状态/关键词/本地日期筛选，排序/分页、内容大小摘要与目录下载；三类范围独立备份/预览/确认恢复，到期须重读，启动地址等变更需重启；目录清单不能恢复 |
| 清理旧备份 | 在“备份恢复”填写保留数量和天数，先预览清单，再勾选永久删除确认；默认每类保留最近 10 份和近 7 天全部备份，只手动执行 |
| 外观 | 登录页或后台顶栏选择跟随系统、浅色或深色；浏览器本地保存偏好，小屏可用顶部导航 |
| 后台安全 | 输入当前密码并确认新密码后修改后台密码；成功后全部后台会话失效，需要重新登录 |

“继承”按原控制层规则生效；存在显式全局开关时，不能把群开关当作一定覆盖全局。插件开关与会话响应门控分别生效。遇到编辑冲突先重新加载并核对，插件与 AI 重新加载先确认，成功读取才替换未保存内容。完整步骤和限制见 [运行维护](operations.md)，功能专项文档见 [文档索引](README.md)。

插件搜索与状态条件同时生效，计数按当前范围最后读取或保存的实际结果计算，不把尚未保存的选择当成启用状态。筛选只影响显示；保存后卡片可能因状态变化而不再匹配。完整步骤见 [插件搜索与筛选](plugin-search.md)。

AI 设置切换后台页面后保留当前草稿；重新加载、切换群和退出时提示未保存更改。取消会保留编辑，读取或保存失败也保留草稿；全局与各群表单分别保存，不自动保存。草稿仅在页面内存中，退出或会话过期清空，刷新/关闭时的原生提醒受浏览器限制。步骤见 [AI 编辑保护](ai-drafts.md)。

私聊参数填写与机器人聊天的用户 QQ；同号群聊与私聊互不覆盖。保存目标由已经读取的表单决定，仅改变范围输入框不会改变保存目标。参数不会放宽 Agent 权限、改变插件开关或发送测试消息。步骤见 [AI 会话参数](ai-conversations.md)。

清理只删除预览列出的旧备份，不修改当前配置或对话档案，无需重启。删除不能通过配置恢复撤销；先另存要长期保留的备份，再检查清单并确认。预览 10 分钟有效，修改参数、切页或备份清单变化后重新预览；每批最多 100 份。损坏、旧版无摘要或结构异常的内容跳过，失败时先刷新检查实际状态。完整步骤见 [备份清理](backup-cleanup.md)。

概览“近期异常”复用脱敏日志，按最新在前显示；数量仅对应本次启动仍保留的记录，不是尚未解决的故障数量。切页、隐藏和退出停止概览读取；回来重新获取，失败会清除旧在线账号显示。异常暂不可读取时仍保留独立的连接状态。插件列表使用“重新加载状态”查看最新网页/聊天开关，概览自动刷新不会覆盖插件编辑表单。说明见 [运行概览与近期异常](overview-alerts.md)。

## 回复显示与记录

`/gpt` 和群聊总结的最终文字，200 个 Unicode 字符以内（含 200）直接发送；超过 200 字以合并聊天记录发送，完整保留，单个节点最多 1000 字。总结标题、标点、空格、换行都计入长度。这项阈值当前只用于这两个入口；普通 AI 聊天和 Agent 沿用各自的发送路径。

Agent 没有固定 8 轮行动上限；任务完成、错误或重复动作时结束。记录从新版本接收事件后保存到 `data/aichat/history/<机器人QQ>.sqlite`，群与私聊隔离。重启或修改人物设定后继续读取；单次模型请求只加载容量允许的近期记录，磁盘档案仍保留。升级前旧进程的内存历史无法补回。

主人指令 `重置AI聊天Agent` 开启新的 Agent 上下文并保留旧档案；这是当前已加载机器人的会话重置操作，不应当作只清当前群。`重置AI聊天` 清空普通聊天的内存上下文。人物设定在后台修改后应用，历史继续保留。详细记录、文件备份与限制见 [Agent 连续对话](agent-history-2026-10-03.md)。后台配置备份不包含对话档案、长期记忆、QQ 登录或全部插件文件。

## 没有回复时

依次核对，定位到实际问题后再修改设置：

1. **连接**：在运行概览确认已连接机器人账号；断开时先检查 OneBot 与连接配置。
2. **插件**：核对目标范围的 aichat、aichatcfg 或 llm 开关，开关已启用不代表其他条件都满足。
3. **响应规则**：群内核对全局与群单独响应。两者任一开启即可通过响应检查；全局响应开启时，群单独沉默不能禁止该群。私聊不套用群单独响应规则，其他门控按实际日志核对。步骤见[响应状态](response-status.md)。
4. **模型与会话模式**：检查已保存入口、Agent 模式、响应 @ 和触发概率。需要核对网络/密钥时用[手动模型测试](model-probe.md)；一次成功仅证明基础调用。GPT/群总结仍有每会话 30 秒共享限额，失败也占用。
5. **任务与日志**：在目标会话读取任务状态，核对错误、动作回执和停止状态；到运行日志查实际失败。模型返回文字不证明 Agent 动作成功，平台回执不证明 QQ 客户端已读。

读写错误、修订冲突或备份失败时按页面提示处理，先重读并核对，不反复提交不确定的操作。权限限制不会因模型测试成功而放宽；具体步骤见[任务说明](agent-tasks.md)、[日志说明](log-viewer-2026-10-02.md)与[待办](todo.md)。

## 页面操作细节

插件列表显示当前范围未保存开关数量，卡片标记“未保存”；改回原模式清除标记。可单项保存或 [逐项保存全部草稿](plugin-save-all.md)，逐项成功立即生效、遇错停止并保留余下选择；搜索、筛选、切页保留草稿。刷新/切群/退出先确认，取消及读写失败保留选择；请求中等待完成，退出或过期清空，旧请求不影响新会话。详见 [插件编辑保护](plugin-drafts.md)。

连接设置会标记地址/Token与主人账号的未保存更改。重新加载/退出先确认，取消或读写失败保留草稿；切换连接只确认当前连接修改，主人草稿保留；切页不丢输入。请求中等待完成，退出或过期清空，旧响应不会回填或解锁新会话。保存后仍需重启机器人，不自动修改 NapCat。步骤见 [连接编辑保护](connection-drafts.md)。

排障时，在概览“近期异常”点击“查看异常日志”，进入日志并应用警告/错误/Fatal/Panic组合，清空旧关键词；“只看异常”保留已应用关键词，“清除筛选”恢复全部。查看/导出使用页面标明的已应用条件，输入修改需提交才生效；快速筛选保留暂停/滚动偏好。见 [异常日志筛选](log-issues.md)。

备份列表支持范围、校验状态和编号/日期组合检索，显示匹配数与已加载总数；有更早未加载记录时只搜索本次最新200份。筛选只调整显示，不影响已打开恢复/清理目标；恢复预览明确显示备份编号。条件跨页/刷新保留，读取失败标记上次结果，退出清空。见 [备份检索](backup-search.md)。

备份恢复页默认每页20份，可选择10或50份，以“上一页”“下一页”浏览筛选后的记录；列表位于清理表单之前。改变筛选或份数回首页，刷新保留当前页并在结果减少时校正；切页保留，退出重置。分页仍只涵盖已加载的最新200份，不改变恢复/清理目标，打开恢复预览自动定位到编号与确认处，见 [备份分页](backup-pagination.md)。

读取备份列表后可“下载筛选清单”，生成UTF-8 JSON，包含所有已加载匹配页的编号/时间/范围/状态等目录信息和最近读取时间。仅加载最近200份或刷新失败时会明确标记；不写关键词原文、配置正文或密钥，不能用来恢复。不新增接口请求，不修改备份，详见 [下载备份清单](backup-catalog-export.md)。

恢复和清理预览显示截止时间与本机估算剩余分秒。到期后取消确认、禁用执行，须重新预览并再次确认；页面隐藏暂停计时，回来即核对。计时不发网络请求，不自动执行，也不中断已提交的请求；服务端仍校验当前状态。见 [备份预览有效期](backup-preview-expiry.md)。

插件列表支持默认20个、可选10/50个分页；搜索和实际状态筛选覆盖全部已加载插件。翻页保留所有开关草稿，总数包含隐藏项；单项保存规则保持，读取成功换范围回首页，刷新/保存后校正页码。详见 [插件分页](plugin-pagination.md)。
