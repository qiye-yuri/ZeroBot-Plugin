## 1 目标与取舍

现有任务摘要显示请求数量、Token小计和缓存统计，结果筛选则判断组内是否包含某类请求。用户选择“包含失败请求”后，仍需展开才能知道同组是否也包含接口完成或提前关闭的请求。下一批在收起状态的任务摘要中增加固定四类结果计数，让混合结果直接可见。

采用已有请求的outcome字段，在摘要渲染时统计；不新增控件、筛选、后端采集、请求重试或数据保存。相比继续增加筛选维度，本批改善现有任务列表的可读性，开发范围可以限定在摘要文字和相关说明、测试。

示例使用合成数据：任务内有两次completed和一次failed，摘要显示“窗口内请求结果：接口完成 2 · 失败 1 · 提前关闭 0 · 未知 0”。它描述当前窗口的请求分布，不是任务成败判定，也不表示QQ已回复。

历史预算900000、[其他待验收与暂缓项](remaining-acceptance.md)保持；不借本批触发真实处罚、转账、好友申请、下载投递或定时任务。

## 2 展示与计算契约

入口保持“运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量”，沿用原登录权限。每个原生summary在身份/窗口请求数之后、Token小计之前增加一行结果分布。顺序固定为接口完成、失败、提前关闭、未知；四类都显示，包括零值，不添加百分比、图表或颜色告警。

| 原始outcome | 计入类别 | 解释 |
| --- | --- | --- |
| 严格等于completed | 接口完成 | 接口响应正常传输，不代表业务成功、内容有效或QQ收件 |
| 严格等于failed | 失败 | 已记录的接口失败，不推断整个任务失败 |
| 严格等于incomplete | 提前关闭 | 与失败分开，不根据耗时补判 |
| 缺失、null、空字符串或其他值 | 未知 | 与现有结果筛选一致，不自动归入失败或完成 |

每条已有请求恰好计入一类，四类计数之和等于该组窗口内请求数；未知结果也参与分母。只遍历g.requests，不读累计统计、当前进行中请求、其他组或旧快照。不按请求id去重，因为既有分组按窗口记录计数；重复或缺失标识不能改变请求数量口径。计数最多256，使用普通整数即可，无需为此增加BigInt或溢出处理。

对有效关联标识的任务，统计整个组；无有效关联的独立请求显示自己的结果分布。跨会话的同任务号继续隔离。原始outcome不修改、不纠正大小写，不根据Token完整性、缓存命中率、风险标签或QQ回执推断结果。未知文字继续使用固定标签，不把原始未知字符串拼进新增摘要。

### 筛选与报告

风险与结果仍在任务级取交集，命中后摘要计数和展开明细都覆盖整组。例如同组完成2、失败1，选择“包含失败请求”后仍显示完成2、失败1，不能只统计命中筛选的请求。排序、小计精度、阈值草稿/应用和重置按钮的职责保持。

结果分布仅用于页面文本，不能向modelTaskUsage返回的组对象附加新属性：该对象同时用于完整报告，附加字段可能意外改变version=1格式。buildModelUsageReport、requests、taskBreakdown、thresholds及独立校验器保持不变；新增分布可以从原始报告请求复算，但本批不在报告中添加它。

## 3 生命周期与最小实现

| 操作 | 预期 |
| --- | --- |
| 新快照新增或淘汰请求 | 从当前组重新计数，旧计数不累计 |
| 同页刷新、排序或阈值应用 | 沿用原同键展开和焦点恢复；分布与当前完整组一致 |
| 修改阈值草稿 | 不改变分布或已应用风险提示 |
| 结果/风险筛选切换 | 保留匹配组的完整分布；被筛掉后返回仍按原规则收起 |
| 重置任务视图 | 三项默认、明细收起；当前组分布和费用阈值不变 |
| 空窗口、不可用或读取失败 | 沿用现有状态文案，不伪造“全为0”的任务摘要，不保留旧计数 |
| 跨启动、离页、退出或认证失效 | 沿用现有清理及刷新入口，不创建新状态恢复路径 |

已核对的实现落点：
