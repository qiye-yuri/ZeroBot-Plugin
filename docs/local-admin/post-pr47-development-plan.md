# PR47之后的开发计划：窗口内请求次数筛选

日期：2026-10-28（Asia/Shanghai）。设计基线为codex/task-count-sort的4a23e60afa00e133d35041981c63b3f8e3f7bf20。PR #46、#47均为未合入草稿，#47依赖#46；当前部署包含两项，已完成独立检查，集中非空验收仍为2/5。本文件只交付设计，不表示功能已实现，不增加队列计数。

## 1 目标和范围

现有次数排序可以把请求较多的任务放在前面，但不能隐藏单次任务。下一批增加独立的“窗口内请求次数”筛选，帮助查看单次或多次请求任务。它不归入风险筛选：次数较多本身不代表风险、重试、费用高或任务失败。

复用[overview.js](../../internal/localadmin/assets/overview.js)中modelTaskUsage的g.count，以及selectModelTaskGroups的任务级过滤和排序。现有[index.html](../../internal/localadmin/assets/index.html)工具区已有风险、结果、排序和重置；[style.css](../../internal/localadmin/assets/style.css)采用自适应网格，优先直接复用。

本批不增加接口、模型调用、存储、配置项、报告字段或依赖。不改变历史预算900000、分组标识、窗口长度和[其他待验收及暂缓项](remaining-acceptance.md)。不为了累计到5项拆分琐碎功能或自动开发下一目标。

## 2 使用与行为契约

入口仍是登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量，无额外权限。未来实现并部署后刷新后台生效；本规划不修改现有操作步骤。

在请求结果与排序控件之间新增原生select，ID为model-task-count，label为“窗口内请求次数”。

| 值 | 显示文字 | 含义 |
| --- | --- | --- |
| all | 全部次数 | 默认，不限制次数 |
| single | 仅1次请求 | g.count === 1 |
| multiple | 至少2次请求 | g.count >= 2 |

采用固定边界，不提供任意数字输入、上下限组合、快速按钮或保存偏好。次数来自当前最多256条已结束请求的分组；不补查历史，不跨启动累计。独立请求按原规则每条一组，即使id重复也不合并；缺失Token字段仍计为请求，不能将未知Token当成缺少次数。

### 组合和展示

风险条件、请求结果条件、次数条件在任务组层面取交集，然后按当前排序方式排列。风险和结果可以由组内不同请求命中。次数按完整窗口组计算，不能先删掉未命中风险或结果的请求再计数。全部次数时行为与本批基线一致。

筛选不改变源数组、分组对象、请求次序或摘要五段；展开保留整组请求。全部次数恢复原始候选组，排序仍按original/count/input/miss既有规则。完整报告始终包含整个已读取快照和已应用费用提示条件，不增加任务次数筛选字段，筛选前后除导出时间外应相同。

附近说明明确：“次数仅覆盖当前窗口，不代表完整轮数或重试；筛选不影响完整报告。”重置说明继续适用于全部任务筛选。

### 刷新、焦点和生命周期

切换筛选仅本地重绘，不发请求，不自动展开或跳到第一组。仍可见的同键组沿用当前展开与摘要焦点保持；被筛掉的组不额外缓存展开状态，回来时按既有行为收起。焦点停留在操作控件，不增加强制聚焦逻辑。

新快照按当前条件重算：组从1次增到2次时退出single、进入multiple；窗口淘汰使2次降到1次时反向变化。费用阈值应用可改变风险匹配，不改次数。跨启动不继承旧任务展开状态。

“重置任务视图”恢复all/all/all/original并收起明细，保留已应用费用阈值及未应用草稿。手动/自动状态刷新保留当前次数条件；整页刷新、离页、退出或认证失效按现有任务视图规则恢复默认。读取失败禁用新增控件并清空旧任务，恢复后按保留选择重新计算。空窗口与无匹配继续使用既有提示，不虚构零次组。
