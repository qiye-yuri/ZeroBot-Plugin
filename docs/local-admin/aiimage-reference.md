# AI画图附带参考图

## 使用方式

**支持直接附图，或回复当前会话中的图片消息。** 回复图片后发送 `AI画图 保留主体，把背景改成海边`，bot会读取该消息中的全部图片作为参考。也可以把图片和命令文字放在同一条QQ消息中发送。 例如在输入框中粘贴/添加图片后，再输入：

```text
AI画图 保留这张图的主体，把背景改成海边
AI画图 --size=2k 按参考图的风格画一座森林小屋
AI画图 将第一张图的角色放进第二张图的场景，保持角色外观
```

带图时，图片原始字节会通过JSON的 `images[].image_url`（Base64 data URL）交给绘图模型，使用同一服务的 `/images/edits`。这不是先让聊天模型写一段文字描述再画图；使用的是画图独立配置中的模型和密钥。

没附图仍使用 `/images/generations`。后台地址仍填写完整的生成接口，如 `https://api.openai.com/v1/images/generations`，程序自动切换同一主机上的编辑端点，不改写保存的地址和密钥。自定义服务须支持同样的JSON编辑请求；任意非标准路径无法推断时会报错，不猜测地址或重试到其他模型。

回复会显示“已读取N张参考图”，完成消息也包含参考图数量，方便确认图片确实参与了请求。模型如何保留细节仍取决于指令和模型能力，不能保证逐像素一致。输出尺寸、质量、格式、数量仍沿用单次参数或后台值，不自动等于输入图片大小。

## 消息与图片限制

- 直接附图和被回复消息中的全部image段合并作为参考图（直接附图在前、引用图在后），按原顺序上传，最多16张。
- PNG、JPEG、WebP；单张不超过8MiB，合计不超过32MiB；单边不超过8192像素，总像素不超过16M。
- 支持QQ图片URL、内嵌Base64；必要时通过OneBot的get_image刷新图片元信息。不会打开消息中指定的任意本机文件路径。下载链接失效时，可读取OneBot返回且核对为当前机器人Pic缓存目录内的原图。
- 图片先下载并完整解码校验，上传时保留原始字节；不按相似度缓存，不把两张相似图混为一张。
- 一张失败就停止整次请求，提示具体第几张；不会忽略坏图后退回文生图。图片读取失败发生在预算预留和模型调用之前。
- 不自动读取未引用的上一张图；引用会核对消息编号、当前群/私聊和测试隔离范围，包括历史测试截止边界。无法确认归属、已撤回、过期、没有图片或多条引用时停止，不退回文生图。私聊中机器人发送的图片必须有能核对当前对方的回执字段，缺失时请重新附原图。
- GIF、蒙版、涂画标记、历史多轮图片编辑暂未接入。单独发送图片但没有AI画图命令不是此功能。
- 原siliconflow协议不支持此链路，带图时会拒绝，不静默忽略图片。后续本地服务如支持OpenAI JSON编辑接口可使用。

下载参考图不携带模型密钥；下载链接和图片内容不会进入用户可见报错。原始聊天档案仍按现有规则保存，本功能不新建参考图文件缓存。

## 预算

参考图会产生额外图片输入费用。当前公开文档给出了GPT Image 2/2.5的图片输入token费率，但未给出本实现可可靠套用的固定每张输入价格；不能拿旧模型的输入规则或输出价格当作输入成本。

后台新增 **每张参考图额外预算预留（美元）**：默认0.25，可设0.01–100。官方接口的本次预留为：

```text
原有文字与输出预算预留
+ 每张参考图额外预留 × 输入参考图张数 × 输出张数
```

**0.25美元是本地预算预留，不是OpenAI的固定每张收费。** 月预算、失败保留、跨月及重启保持继续生效。无图不增加此项；兼容服务仍按管理员填写的每张最高总价计额，该总价必须覆盖参考图输入费用。

读取帮助不读取附图、不调用模型、不占额度。QQ查看完整规则：

```text
AI画图帮助 参考图
AI画图帮助 全部
```

## 官方接口依据

[OpenAI图片编辑API](https://developers.openai.com/api/reference/resources/images/methods/edit)支持多张输入图的JSON引用与Base64 data URL；普通输出参数和流式选项继续适用。编辑流事件 `image_edit.partial_image` / `image_edit.completed` 已与原生成流一起处理。当前模型的输入保真参数使用API默认行为，不发送不适用的旧参数。
