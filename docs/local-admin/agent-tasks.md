# Agent 任务状态与停止

M3 已于 2026-10-16 部署到日常服务，提供任务状态、停止请求和上下文取用摘要。隔离验证不代表真实 QQ 验收。

来源上下文读取补充：Agent 可用 read_history.context 核对前后少量事件，仍只登记一次历史读取并占一次共享查询额度；后续模型上下文中的检索来源片段数按实际装入事件统计，可能多于查询次数，不表示模型已理解所有资料。使用与容量限制见[来源上下文核对](agent-memory.md#核对来源的前后事件)。

## 使用步骤

1. 登录本机后台，进入“Agent 会话”，选择已连接机器人、群聊或私聊及账号，点击“读取档案”。
2. 在“会话任务”点击“读取任务状态”。每页最多显示 50 个任务，按创建顺序倒序；点击“更早任务”继续翻页，点击“读取任务状态”返回最新一页。没有自动轮询。翻页使用固定创建序号，中途新增任务不会挤入旧页，需返回最新一页查看；各任务状态以本次读取时为准，不是冻结的状态快照。
3. 核对已加载范围和任务编号，点击运行中任务的“请求停止此任务”。按钮绑定已读取的任务编号和版本；未提交的输入不会改变目标。
4. 显示“已请求停止”后，再读取核对最终状态。版本冲突需刷新；网络错误、存储失败或结果未知不自动重试。已结束任务不能重新运行。

“任务状态”可选择全部、运行中、已请求停止、已停止、已完成、失败或进程中断，选择后点击“读取任务状态”应用并返回第一页。“更早任务”沿用已加载的会话和筛选，未应用的下拉框选择不会改变翻页范围；页面明确显示实际加载的条件。运行中与已请求停止分别筛选。停止成功后单独显示该任务响应并恢复全部筛选，便于继续核对终态；失败仍需手动重新读取。

筛选按本次读取时的状态处理，不是冻结快照。翻页期间状态变化可能使任务进入或离开当前筛选，应返回最新页核对；创建序号分页仍使新任务不挤入旧页。当前进程未可靠保存的内存终态在首页按实际状态显示，不因磁盘上的旧“运行中”标记而漏掉失败；更早页不追加未落盘条目。切换范围、离开或退出后，筛选恢复全部，正文及旧分页位置清除。

读取和停止均要求后台登录，停止同时检查来源与 CSRF。没有新增 QQ 角色权限。机器人当前未连接时不提供此入口。

## 按错误类别筛选任务

登录后台，读取已连接机器人目标群或私聊的档案，在“会话任务”的“错误类别（选择后重新读取）”中选择类别，再点击“读取任务状态”应用。可与任务状态组合，例如“失败”与“模型请求或响应解析失败”；两项条件同时成立才返回。只改下拉框不发请求，“更早任务”沿用已加载的会话、状态及错误类别，不采用尚未应用的草稿。点击“读取任务状态”重新应用选择并返回最新一页，状态文字会说明实际条件。

可筛选模型请求或响应解析失败、模型动作格式无效、模型输出超限、状态存储失败、执行失败、重复动作停止、设置已更新、进程退出或重启。“未记录错误类别”表示保存的 error 缺失或为空，可能包含运行中、正常结束或旧失败记录，不能据此认定任务成功；“其他或旧类别”包含非空但不属于上述八类的旧值，页面统一说明类别未知，不把旧文字推断为某种模型或平台错误。“全部类别”保留原有列表行为，类别不自动改变状态筛选。

筛选读取实际保存的类别，不分析提供商正文或历史聊天，不修改任务状态或分类。当前进程未可靠保存的任务先用内存摘要覆盖旧磁盘值，再应用两项条件；因此存储失败不会因为旧行缺少类别而被隐藏。旧任务不补造分类。每页最多 50 个，按创建序号倒序继续；状态和类别不是冻结快照，期间变化需返回最新页核对。按编号核对单条仍独立于列表筛选，停止成功后两项筛选恢复全部。切换会话、离开或退出时清除任务与筛选，失败不自动重试，迟到响应不会回填旧范围。

权限沿用后台登录及已连接机器人，只查询所选机器人、群或私聊；不调用模型、OneBot，不消耗模型任务查询额度，不新增 QQ 配置。使用新构建后生效。接口 `GET /api/agent/tasks` 新增可选字符串 reason：省略为 all；允许 all、none、other 及 storage_error、settings_changed、repeated_action、model_request_failed、model_output_limit、model_output_invalid、process_interrupted、execution_error。可组合原 state/before；空值、未知或重复 reason 拒绝，单条读取与停止接口不接受 reason。响应与原分页结构一致，沿用 no-store、两路共享 Agent 操作并发及 5 秒请求期限；不提供全账号汇总或无限量导出，无数据库结构迁移。

## 按阶段筛选任务

运行新构建，登录后台，在“Agent 会话”读取已连接机器人对应群或私聊的档案。在“会话任务”选择“任务阶段（选择后重新读取）”，再点击“读取任务状态”。可选准备中、等待模型（含上下文准备）、等待普通聊天兜底模型、动作在途、动作已返回和结束；默认全部阶段。可与任务状态、错误类别组合，三项条件同时满足才返回。例如“已请求停止 + 等待模型”可查看仍在等待模型准备或返回的停止请求。

只改选项不会发请求；“更早任务”保留已应用的会话、状态、错误类别及阶段，页面显示实际条件。重新点击“读取任务状态”应用当前选择并返回最新一页。阶段是读取时的当前值，不是完整轨迹或冻结快照；阶段变化会使任务进入或离开筛选，需要手动重读。等待模型可能包含上下文、图片准备，不代表模型 HTTP 请求已经发出；动作已返回也不代表整个任务完成或 QQ 客户端已收到消息。

每页最多 50 个，所有筛选先于创建序号分页应用。存储失败时先覆盖为当前进程的实际内存摘要，再筛选，并保留未可靠保存提示。旧摘要缺少阶段或含未知阶段时，仅在“全部阶段”下可见，不从状态猜测阶段。按编号核对单条独立于筛选；停止成功后显示该任务响应并恢复全部筛选。切换范围、离开或退出时清空条件，读取失败清除旧分页，迟到响应沿用现有范围检查。

沿用后台登录、已连接机器人和原会话范围，无新增 QQ 权限、模型调用或查询额度。`GET /api/agent/tasks`（也支持 HEAD）新增可选 phase，省略为 all；允许 all、starting、model_wait、fallback_model_wait、action_wait、between_actions、finished，可与 state/reason/before 组合。空值、未知值及重复 phase 拒绝；单条读取和停止不接受 phase。响应结构、只读观察时间及 no-store 保持，无数据库迁移。

## 按最近动作结果筛选任务

运行新构建，登录后台，在“Agent 会话”读取已连接机器人的目标群或私聊档案。在“会话任务”的“最近动作结果（选择后重新读取）”选择条件，再点击“读取任务状态”。可选全部结果、等待回执、成功回执、平台拒绝、结果未知、本地失败、未记录结果及其他或旧结果。可与任务状态、错误类别、阶段和开始时间组合，所有条件同时满足才返回。

筛选按摘要已有的 outcome，即最近一次登记的本地或平台动作结果。等待回执表示动作在途，不是等待模型；成功回执不等于整个任务完成，也不证明 QQ 客户端收到或已读。模型准备期间可能仍保留此前动作结果，模型请求失败也不能据此推断为平台拒绝。本功能不按累计 results 计数筛选，不能用它查找“任务期间曾出现过某类结果”的全部任务。

“未记录结果”匹配缺失或空 outcome，可能是尚未执行动作或旧摘要，不能据此认定动作次数为零或任务成功。“其他或旧结果”匹配非空但不属于上述五类动作结果的旧值，页面不根据旧文字推断实际结果。当前进程未可靠保存的摘要先使用内存中的实际值，再应用筛选，并保留存储故障提示；旧磁盘上的等待回执不会掩盖内存中已返回的结果。

只改下拉框不会发请求；“更早任务”沿用已加载的会话、结果和其他筛选条件，忽略未提交的草稿。页面说明实际条件及“非累计结果”，每页最多 50 个匹配任务，按固定创建序号继续，筛选先于分页应用。状态和结果以本次读取时为准，变化后需手动重读。单条核对不附带列表条件；停止成功后恢复全部结果和其他不限条件，失败不自动重试。切换范围、离开或退出清空旧结果和条件。

`GET /api/agent/tasks`（也支持 HEAD）增加可选 outcome：省略为 all；允许 all、none、other、in_flight、ok、rejected、unknown、local_error。空值、未知值及重复参数拒绝，单条读取和停止接口不接受此参数。响应结构及已保存字段保持，无数据库迁移或结果重分类。沿用后台登录、已连接机器人、会话隔离、no-store、原并发和 5 秒期限；不调用模型或 OneBot，不占 Agent 查询额度。真实环境体验待验收。

## 按任务开始时间筛选

运行新构建，登录本机后台，在“Agent 会话”读取已连接机器人的目标群或私聊档案。在“会话任务”填写“任务开始时间下限”和/或“任务开始时间上限”，点击“读取任务状态”应用。输入按浏览器所在机器的时区解释，已加载条件显示转换后的 UTC 时间；下限包含，上限不含，同时填写时下限须早于上限。两项留空即不限时间，可与任务状态、错误类别及阶段组合，所有条件同时满足才返回。

筛选依据任务摘要的 startedAt，即任务开始时刻；不是结束、最后更新、模型请求或平台动作时间。时间范围内开始、随后仍在运行的任务可以命中；范围前已开始而范围内结束的任务不会因此命中。旧记录缺失或无法解析开始时间时，仅在不限时间的列表中显示，不从其他字段推算。

“更早任务”沿用成功加载的会话、时间及其他筛选条件，未提交的时间草稿不会改变翻页。每页最多 50 个匹配任务，仍按固定创建序号倒序；时间筛选先于分页应用，不只过滤当前页。按编号或从条目核对单条仍独立于列表条件。停止成功后时间和其他筛选恢复不限，便于核对停止回执；失败须手动重读。切换会话、离开或退出清空已加载条件与输入，不保存时间偏好，无自动刷新。

权限、机器人连接要求及会话隔离沿用原列表。`GET /api/agent/tasks`（也支持 HEAD）增加可选 from/until，接受带时区的 RFC3339Nano 绝对时间，响应回显已应用的 UTC 边界；空值、重复边界、无效时间或倒序范围拒绝，省略两项保持原行为。单条读取和停止接口不接受时间条件。存储层按真实时刻比较，保留偏移时区及纳秒精度；不新增数据库字段或迁移。时间过滤逐条读取候选摘要，匹配较少或任务较多时可能较慢，仍受原后台 5 秒期限约束；失败不显示为空结果，也不自动重试。

无新增模型调用、查询额度或 QQ 权限，列表及单条结果的统计展开规则保持。真实环境使用体验待验收。

## 查看任务的触发消息

新构建在事件实际入档时取得该次写入的序号，再由消息处理入口绑定到任务。任务摘要只保存 `sourceSeq` 字符串，不复制消息正文；它是档案来源序号，不是任务编号、实例编号或平台消息编号，不会根据可能重复的消息编号或时间猜测来源。

1. 读取已连接机器人、目标群或私聊的任务列表，或按任务编号核对单条摘要。
2. 有已捕获来源的任务显示“触发消息档案 #…”及“查看触发消息”。点击后在下方只读核对该任务、机器人、会话、来源时间和脱敏纯文本。
3. 来源明确包含上下文重置前的记录，不会把旧消息重新加入模型，也不影响原列表、筛选、分页或档案时间线位置。当前会话未找到对应事件、档案文件不可用和读取失败分别提示；来源未知的旧任务或未捕获序号的新任务不提供来源按钮，也不补造历史。

来源核对要求后台登录、机器人当前已连接，固定在任务摘要已加载的范围，输入框中尚未应用的账号不会改变目标。读取不调用模型、识图或 OneBot，不停止或重跑任务，也不能证明消息中的每项动作已获授权或已成功。单条最多显示 8,000 UTF-8 字节，超过 64 KiB 的异常正文只显示占位，并明确提示截断。

重新读取任务列表、翻页、按编号核对另一条任务、提交停止或切换会话/离开/退出后会清空已显示来源，迟到响应不能回填新范围。任务重启恢复、终态保存和单条读取保留既有来源序号；来源条目后来缺失时只能提示无法核对。未可靠保存的任务仍如实提示故障，不能因为来源可读而认为状态已保存。

来源使用既有 `GET /api/agent/history` 的完整范围、`seq` 和 `archived=true` 查询。服务端在创建任务时确认非零来源属于同一会话的事件；`Begin` 保留无来源兼容，内部宿主通过 `BeginFrom` 传入已捕获序号，模型或网页不能指定任务来源。旧持久任务没有此字段，新任务没有来源时为字符串 `"0"`；前端两者均标明未知。功能需新构建。

## 展开任务取用与执行统计

运行新构建，登录后台，在“Agent 会话”读取已连接机器人目标群或私聊的任务列表。每条任务的“上下文、记忆与执行统计”默认收起，点击标题即可展开，再点击收起；键盘聚焦标题后按 Enter 同样可以操作。每条独立，不会联动其他任务，展开和收起不发起网络请求，不调用模型或 OneBot，也不改变任务状态、版本、筛选及分页。

展开后显示原有五类摘要：最近一次上下文准备、长期记忆取用、累计模型/本地/平台动作次数、累计动作结果、历史与记忆查询额度和覆盖情况。数据来自本次已读取响应，原条数/字节口径、未知/旧记录提示和容量说明保持；收起只改变呈现，不删除这些统计，也不表示统计值为零。

任务状态、编号、阶段、时间/耗时、错误原因及未可靠保存提示始终保留在折叠区域外；结果未知说明、触发来源、核对最新状态和停止入口也保持直接可见。单条按编号或快捷核对的结果默认展开，便于检查完整摘要；用户仍可自行收起。核对结果依旧只读，不能由此直接停止或重跑任务。

重新读取列表、翻页或停止回执重建条目时，列表统计恢复默认收起；重新核对单条时恢复默认展开。选择状态/原因/阶段草稿或展开收起不会触发重新读取；仍需点击相应读取按钮更新服务端状态。离开、切换范围和退出沿用原清理流程，不保存跨页或跨会话的展开偏好。

权限与原任务列表及单条核对相同：后台登录、机器人当前已连接，并限定所选机器人、群或私聊。没有新接口、配置、存储字段或 QQ 权限；原停止、版本校验及查询额度不变。真实环境体验待验收。

## 从任务条目核对最新状态

运行新构建，登录后台，在“Agent 会话”读取已连接机器人对应群或私聊的任务列表。每个任务条目提供“核对最新状态”，运行中、已结束及未可靠保存的任务均可使用。点击后按该条任务编号和已加载会话读取最新摘要，无需先复制编号；编号自动填入原“按任务编号核对”输入框，后续仍可手动重读或输入其他编号。

成功后页面滚动到单条核对结果，显示最新版本、状态、阶段和原有取用/耗时摘要；有触发来源时可继续查看。结果区只读，不提供停止或再次快捷核对按钮；需再次读取时可使用原编号表单或列表入口。快捷核对不调用模型或 OneBot，不消耗 Agent 查询额度，不修改任务版本，也不会自动刷新。

原任务列表、筛选和“更早任务”的位置保持，输入中的范围、编号及筛选草稿不会改变所点条目的目标。列表仍是此前读取的快照；单条最新结果不会覆盖原列表或替换停止按钮绑定的版本，停止前仍需重新读取列表。筛选期间任务已转为其他状态，也能独立核对该任务；没有重新筛选整个列表。

读取在途时沿用原控件禁用和请求检查。不存在、存储故障或返回编号/版本无法核对时，清除旧单条结果并提示失败，保留原列表，不自动重试或据此认定任务已经结束。离开、切换范围或退出会清空编号与结果，迟到响应不回填；翻页、重读列表或停止提交按原流程清理单条结果。

权限、范围与原编号读取一致：要求后台登录、机器人当前已连接，只读所选机器人、群或私聊。直接复用 GET /api/agent/tasks/read 及原 no-store、超时和并发规则，不新增接口、数据库字段或 QQ 权限。真实环境体验待验收。

## 按任务编号核对最新状态

1. 先按上述步骤读取目标会话的任务列表，核对已加载的机器人和群/私聊。即使该筛选没有任务，也可查询已知编号。
2. 在“按任务编号核对（只读）”粘贴已知任务编号。编号须为 32 位小写十六进制字符串，可从已有任务摘要复制；它不是分页序号、实例编号或版本号。
3. 点击“核对单条任务”。查询使用任务列表已加载的范围，未提交的机器人、账号或筛选草稿不会改变目标。可读取不在当前 50 个列表项中的旧任务；其他会话或机器人的同名请求不会返回该任务。
4. 在下方只读结果核对当前版本、状态、起止时间、阶段、最近动作/结果、累计次数和历史/记忆取用摘要。运行任务和状态写入失败的当前任务优先返回内存中的实际摘要，后者仍显示未可靠保存；旧摘要继续显示未统计。

单条核对不调用模型、不派发动作、不取消或重跑任务，不递增任务版本，也不自动轮询。单条结果与原列表分开，保留原列表、已加载筛选和分页位置；列表仍是此前读取的状态，停止前应重新读取列表以取得可操作的当前版本。只读结果不提供停止按钮，有来源时可继续查看触发消息；已发出的模型与平台请求继续遵守原停止语义。

“任务不存在”表示当前范围内没有该编号，不能据此确认任务正常结束；存储不可读、参数错误和返回编号/版本无法核对分别提示失败，不显示核对成功。重新读取列表、翻页或提交停止请求会清除单条结果并保留编号输入；切换会话、离开、退出或登录过期会同时清空编号与结果，迟到响应不回填。请求在途时该表单暂时不可重复提交，失败需手动核对或重试。

接口为 `GET /api/agent/tasks/read`，仅接受 `botId/type/id/taskId` 作为单条范围参数，要求后台登录、机器人已连接，响应使用 no-store。任务编号不能与 `before`、`state`、`reason`、`phase` 或 `version` 混用；原列表接口不接受 `taskId`，以免将指定任务误当作整页查询。HEAD 沿用只读处理，不派发停止请求；存储查询复用两路 Agent 操作并发限制和五秒 HTTP 请求上下文。新构建提供该入口。账号首次访问时的重启恢复仍按下述语义处理。

## 当前阶段与首次停止请求时间

登录本机后台，在会话档案中读取已连接机器人对应群或私聊的任务列表，或按已知任务编号核对单条摘要。新任务显示“当前阶段开始”及已登记的“首次停止请求”时间，无需新增配置或 QQ 权限，仍需手动重新读取。列表、筛选、分页及单条读取使用同一字段；查看时间不会调用模型、派发动作或重新停止任务。

进入准备、Agent 模型准备、普通聊天兜底准备、动作在途、动作返回和结束阶段时，记录服务端 UTC 时间。连续两轮同类模型准备也分别更新时间；上下文、记忆及查询摘要更新不会重置当前阶段时间。模型准备包含上下文读取和可能的识图处理，动作在途从派发许可开始，因此这些时间不能当作实际 HTTP 发出时间、平台执行耗时或 QQ 客户端收取时间。

首次有效停止登记保存 `cancelRequestedAt`，保持当前在途阶段时间。过期版本或未知任务被拒绝时不登记；并发及重复停止保持最早已登记时间，终态及只读核对继续保留。已登记停止并不表示在途请求已中断，原停止语义不变。没有此字段不能证明从未收到停止请求，旧摘要可能未记录；已停止任务缺失时明确提示未知，不计算停止耗时。

`phaseStartedAt` 为当前阶段开始时间，结束阶段与 `endedAt` 相同，只保留当前阶段，不提供完整阶段轨迹。重启恢复的中断任务将结束阶段时间记为新进程打开该账号数据库并发现遗留任务的时间；它不是实际退出时刻，首次停止时间若已保存则保留，旧请求时间不补造。旧终态缺失阶段时间时继续提示未记录。

时间来自服务器时钟，时钟校正可能造成先后时间变化，不提供持续计时、停止时限或自动轮询。接口使用可选 RFC3339Nano UTC 字符串，保留纳秒文字，不转换成编号或累积毫秒。无效或缺失时间单独提示；状态写入失败时隐藏这两项未可靠保存的时间并提示故障，不能将内存记录当作落盘证据。功能需新构建。

## 任务耗时快照

运行新构建，登录后台，在“Agent 会话”读取已连接机器人对应群或私聊的任务列表，或按任务编号核对单条状态。摘要显示任务总耗时；运行中和已请求停止的任务显示截至本次读取时已运行多久、当前阶段已持续多久，有停止请求时同时显示已等待时间。停止接口返回的任务使用同一计算方式，无需新增配置或 QQ 权限。

运行中的计算终点来自服务端响应的 observedAt，并显示准确读取时刻；列表所有条目共用本次响应时间，单条核对和停止回执各自使用本次响应时间。页面不会按浏览器时钟持续计数或自动轮询，须手动重新读取。列表仍保留此前快照，单条最新核对只更新单条结果；筛选、分页、编号、版本和停止规则保持。

已完成、失败或已停止任务按 endedAt 计算总耗时，停止等待按首次 cancelRequestedAt 至 endedAt 计算，不随以后读取增长。当前阶段仅在运行中显示，阶段准备可能包含上下文和识图；这些耗时不等于单次 HTTP、模型生成、平台执行或 QQ 送达耗时。按服务器时钟估算到整秒，显示“约”，不足一秒显示约 0 秒；时钟校正可能影响结果。

缺失或无效时间、参与计算的终点早于起点时，该项显示未知，其他可计算项目保留。旧终态仍可用原起止时间计算总耗时，旧运行摘要缺少 observedAt 时须重读；缺少阶段或停止时间不会补造。状态未可靠保存时不计算耗时；进程中断时实际退出时刻未知，不把重启发现时间当作任务结束耗时。

列表、单条读取和停止接口在原 JSON 根部增加只读 observedAt，格式为 RFC3339Nano UTC；列表项与持久任务内容保持原结构，不写入观察时间、不递增版本或新增存储操作。原认证、CSRF、no-store 与会话范围保持。离开或退出会按原流程清空摘要，迟到响应不回填。真实环境体验待验收。
## 状态与执行边界

| 状态 | 含义 |
| --- | --- |
| 运行中 | 准备上下文、等待模型或执行动作 |
| 已请求停止 | 取消已登记，等待在途请求返回 |
| 已停止 | 已结束本次任务，不再派发后续动作 |
| 已完成 | 流程正常结束；仍需结合动作回执判断实际结果 |
| 失败 | 模型、动作、档案或状态保存失败，或重复动作、设置更新使任务结束 |
| 进程中断 | 上一进程遗留任务，未重放；回执丢失时标为结果未知 |

按“机器人 + 群/私聊会话”原子互斥；同号群与私聊、不同机器人互不占用。新触发不排队，明确提及机器人的忙请求返回提示，概率触发在忙时忽略。普通聊天兜底也占用同一会话并纳入原 Agent 任务的停止边界。

本版没有立即中断已发出的模型/识图 HTTP 请求或 OneBot 调用。单次模型请求沿用 30 秒客户端超时，单次 OneBot 调用沿用 SDK 的一分钟超时；上下文准备可能包含多个识图请求，因此不承诺固定总停止耗时。派发许可与取消登记互斥；已获许可的当前动作视为在途，返回回执后不再执行下一动作。

图片下载另受每张 10 秒和输入容量限制，多张及历史图片仍分别加载；该上限不等于任务总超时或立即停止，具体见[Agent 识图输入](agent-vision.md)。

停止不撤回消息、不逆转已执行操作。在途结果仍保存为成功、平台拒绝或未知；平台动作失败或结果未知时终止流程，不让模型自动重发。普通聊天兜底只在 Agent 正常结束且没有平台动作时使用，执行错误不会再触发另一次模型请求。设置代次变化也会在后续请求和动作前停止旧任务。

同一任务重复停止幂等，旧任务编号不会停止新任务。正常运行阶段变化会递增版本，过期版本拒绝停止；已停止或已结束任务返回现有状态。退出、切换范围或登录过期会清除页面状态，旧响应不能回填新会话；停止提交在途时暂时阻止页面导航与退出。

## 上下文摘要与动作结果

### 模型文本片段与异常输出

新构建支持 Agent 动作模型返回多段纯文本内容。无需新增配置或权限，仍按后台 AI 配置选择的接口协议解析，适用于既有角色、机器人和群/私聊会话；只有 Agent 动作模型采用本规则，识图、普通聊天和 GPT 请求保留原流程。

协议提取出的文本片段按返回顺序直接拼接，不增加标签、换行或分隔符，再进行原有 JSON 动作格式、角色、会话和容量检查。例如一个 JSON 动作跨两个 text 片段、甚至在编号中间分段，拼回后仍按同一个动作解析。文本片段数不是动作数，拼接后仍最多 32 个动作对象；合计文本在分配拼接结果之前检查 1 MiB 字节上限，超限整批拒绝，任务仍显示 model_output_limit，不截断后继续执行。

未提取出任何有效文本片段，或内容混有图片/未知类型时，整个本轮按 model_request_failed 失败，不执行其中看起来有效的保存记忆或发送前缀，也不将缺失输出当作空回复进入普通聊天兜底。OpenAI 兼容格式的缺失/空 choices、缺失/null/空数组 content 等属于这类情况。所选协议确实识别为 text 的空字符串仍保留原无动作处理；本功能不把原生 tool_calls、图片或其他输出类型转换为 JSON 动作。

响应解析或内容提取出现协议转换异常时，在该响应边界内转换为固定故障，不输出异常值或提供商正文；不扩大为存储或平台调用的异常恢复。每次调用先复制协议，避免调用方复用对象时把前轮响应当作本轮结果。已经登记的停止、设置更新及存储故障仍沿用原优先级，不重试、不回滚此前轮次，也不重跑失败任务。

登录后台读取目标会话的任务列表，或按编号核对单条摘要；遇到缺失或不支持的内容，显示“Agent 模型请求或响应解析失败”。核对接口类型并选择能返回文本形式 JSON 动作的模型后，用新消息启动新任务。HTTP 完整返回但输出不合要求时，HTTP 统计仍可完成，任务则失败；应结合任务摘要核对。功能需新构建。

### Agent 模型请求失败

新构建区分 Agent 模型接口故障与其他执行失败，无需新增配置，适用于原有角色、机器人及群/私聊会话。登录后台，读取目标会话的任务列表，或按已知任务编号核对单条摘要。Agent API 返回错误时，任务显示“失败”，原因为“Agent 模型请求或响应解析失败”，类别为 model_request_failed。页面与摘要不输出提供商错误正文、接口地址或密钥，不新增自动重试或重跑按钮。

此类别覆盖网络/超时错误、接口返回非 200 状态，以及 HTTP 完整返回但协议 JSON 无法解析等 API 已明确返回的错误；不凭错误文字区分“密钥错误”或“余额不足”，也不推断所有 HTTP 200 都能正常生成动作。HTTP 200 的空协议体导致 EOF 错误时同样失败，不将它当作 end_action 或据此进入普通聊天兜底。完整合法协议中模型内容为空且 API 没有报错的情况保留原处理。正常 HTTP 响应中的动作格式或数量问题仍用原 model_output_invalid/model_output_limit，图片识别失败继续按原跳过规则处理，不冒充 Agent 模型故障。

模型调用失败后不派发本轮动作、不增加请求/响应/结束动作归档，不自动切换普通聊天兜底；第一轮失败通常为一次模型准备、零动作/查询/兜底，触发事件本身仍正常入档。此前轮次已完成的动作、记忆及累计结果保留，不回滚或重发。已登记停止、设置更新、HTTP 容量超限和状态存储故障仍按原边界及优先级处理；状态未可靠保存时不能把内存错误类别当作落盘证据。旧任务的通用“执行失败”不会重新推断或改写。

遇到此类失败，可在后台 AI 配置中核对接口类型、地址、模型名称及密钥设置状态，再按需修正配置。失败旧任务不能重跑；正常配置或服务恢复后，由新消息启动新任务。此功能不主动探测真实模型或改变 QQ 角色权限，入口仍要求后台登录及机器人当前已连接。

模型统计和任务终态分别核对：HTTP 503 等非成功交换计入请求失败；HTTP 200 且正文完整读取、之后协议解析失败时，请求统计可以是 HTTP 完成，但任务仍失败。网络交换、解析成功和动作执行成功不是同一口径，不能据任务类别计算真实 QQ 送达率。功能需新构建。

### 模型动作回复格式检查

新构建在动作保存和派发前检查当前批次的完整格式，无需新增配置，适用于所有 Agent 角色及群/私聊会话，沿用既有权限和范围隔离。模型须返回连续的 JSON 对象，允许对象之间有空白或直接相接；已有 JSON 代码围栏兼容。不接受数组包装、null、数字/字符串等顶层值、不完整 JSON、多余括号、附加说明或无法解码为动作结构的字段类型。参数数字仍按原精确数字方式解析，不转为浮点编号。

同一 JSON 对象内的字段必须唯一，涵盖动作顶层、参数、嵌套消息和未知扩展字段；重复值相同也拒绝。字段名先按 JSON 转义解码，例如 `group_id` 和 `group\u005fid` 算重复。顶层 action、params、echo 按现有结构解码的大小写别名一并检查，例如同时出现 `action` 与 `Action`，或 `params` 与 `Params`，不能通过后值覆盖或对象合并改变含义。单独使用原本可解析的大小写别名仍兼容。

各对象独立检查：不同动作、不同消息段或兄弟对象可各自包含 `type`、`data`、`text` 等相同字段。普通参数与消息对象的字段名保持大小写敏感；消息文本里展示的 JSON、CQ 字符串或其他引号内内容仍作为文字，不会当作动作重新解析。无需新增权限或开关，新构建对后续模型回复生效，不重新检查或修改旧档案。

若模型返回保存/发送前缀后，又返回含重复 action、目标编号或嵌套消息字段的对象，整个当前批次按同一 model_output_invalid 原因拒绝，前缀也不会执行。不要依赖“最后一个值生效”；修正模型输出要求、确保每个对象字段唯一后，用新消息启动任务。原批次上限、首次有效结束动作后的忽略内容、任务停止及此前轮次结果保留规则不变。

例如模型先返回 save_memory、发送消息，再附一个多余的 `]`：整个当前批次被拒绝，前面的记忆与消息不会执行，请求/响应及结束标记也不入档。旧实现可能忽略这类多余括号。预检只检查格式和单轮容量，不代替动作白名单、会话范围或各工具参数检查；权限错误仍沿用原规则。

登录后台，在目标机器人和会话的任务列表手动刷新，或按任务编号核对最新状态。格式失败显示“模型动作回复格式无效，当前批次未执行”，类别为 model_output_invalid；不会自动重试、派发有效前缀或转入普通聊天兜底。此前轮次已经执行的动作与记忆仍保留，可结合累计结果和档案核对。停止或存储故障仍按原优先级显示。失败任务不能重跑，修正模型动作输出要求后可用新消息启动新任务。

首个 end_action 继续按原协议结束当前轮次，其后内容不执行，也不进行动作结构检查；完整正文仍受容量限制，去除代码围栏后的内容须为有效 UTF-8。空对象不执行但计入 32 个对象上限，纯空白回复保留原无动作处理。格式检查不是动作执行事务，也不提供跨轮回滚。HTTP 完整读取但格式失败仍属于模型 HTTP 完成，任务则失败；页面只显示错误类别，不展示原始坏回复。功能需新构建。

### 单轮模型输出限制

#### JSON 结构上限

使用新构建后，单轮动作回复在既有字节和 32 个顶层动作对象之外，还限制 JSON 对象/数组最多嵌套 64 层，以及整轮累计最多 10,000 个 JSON 值。顶层动作对象为第 1 层，params 对象为第 2 层；标量叶子不增加容器层数。对象、数组、字符串、数字、布尔和 null 各算一个值，对象字段名不另计。例如 `{"action":"end_action","params":{}}` 共 3 个值；字符串中的括号或 JSON 文本只算该字符串一个值，不递归解析。

累计值预算由当前轮次的所有动作共享，包括空对象、未知附加字段和结束动作；每个新模型回复重新开始计数，不限制整项任务的总轮数。第一个通过预检的结束动作之后仍忽略结构内容，完整回复的字节上限保持。此前可解析但超过结构上限的深层或大批小字段输出，新构建会拒绝，不能依赖旧版只限制字节的行为。

结构预检在自动保存和宿主派发前完成；首个有效结束对象之前或该对象自身超出结构上限时，整批拒绝，前面合法的保存、发送也不执行，不新增结束记录；之前轮次已完成的动作不回滚或重发。任务仍归入 model_output_limit，后台显示“模型单轮输出超过容量、动作数量或结构限制”，与 HTTP 请求失败及动作格式错误分别核对；不展示坏回复。完整 HTTP 已读但结构超限时，HTTP 统计可为完成，任务为失败。

登录后台，选择已连接机器人和目标群/私聊，手动读取任务列表或按编号核对。可组合“失败”与“模型输出超限”筛选；没有自动重试、普通聊天兜底或重跑失败任务，调整输出要求后由新消息启动新任务。所有角色沿用原白名单和范围，停止/设置变化/存储故障仍按原规则处理。无需新增配置，普通聊天、GPT、识图及历史查询响应不使用此动作 JSON 预算；真实提供商兼容效果待验收。

新构建为每次 Agent 模型回复提供容量和动作对象上限，无需新增配置，适用于所有角色，既有白名单、机器人/会话隔离和停止权限保持不变。任务不设固定总迭代轮次，正常多轮工具使用沿用原流程；这里限制的是一次模型响应，不能把额度理解为整项任务只能执行 32 个动作。

| 范围 | 限制 |
| --- | --- |
| 宿主 Agent HTTP 响应 | 向解析器最多提供 2 MiB，即 2,097,152 字节，包括协议 JSON、错误正文及透明解压后的内容；未知长度最多多探测 1 字节 |
| 解码后的单轮回复正文 | 最多 1 MiB，即 1,048,576 字节，包含空白和代码围栏；不做截断后继续执行 |
| 单轮 JSON 动作对象 | 最多 32 个，结束动作及空动作对象也计入；首个 end_action 仍按原规则终止解析，之后内容不执行，完整正文容量仍须满足上限 |
| JSON 容器嵌套 | 对象和数组最多 64 层，顶层动作对象算第 1 层 |
| 单轮 JSON 值累计 | 最多 10,000 个，含对象、数组与标量，跨动作共享，字段名不另计 |

未知长度的 Agent HTTP 响应先在 2 MiB 上限内读到结束，再交给协议解码；不会因为已收到一个合法 JSON 就提前采用尚未完成的传输。原 30 秒客户端超时不变，超限、读取或关闭错误仍按模型请求失败处理，不自动重试。完整读取后的 JSON 结构拒绝属于任务输出超限，不能与 HTTP 读取失败混淆，详见[模型统计口径](model-request-statistics.md#统计口径)。

动作数量及正文容量在自动保存或宿主派发前预检。超限时拒绝整个当前批次，当前批内已出现的记忆保存、平台操作或结束标记均不登记；不采用“先执行前 32 个”的做法。模型 HTTP 读取超限同样停止本轮，不能把截断 JSON 当作合法动作。之前轮次已执行的动作与保存的记忆保留，不回滚、不重发，累计结果应结合档案核对。

登录后台，在目标机器人和会话的任务列表手动刷新，或按任务编号读取最新摘要。此类任务显示“失败”，原因为“模型单轮输出超过容量、动作数量或结构限制”，对应 model_output_limit；首轮就被拒绝时通常只有一次模型准备、零动作/查询，不会自动转为普通聊天兜底。若已请求停止或存在状态存储故障，仍优先按原取消/故障语义处理。失败的旧任务不能重跑，新消息可启动新任务；可减少单次要求的动作或回复内容后再触发。

HTTP 200 且完整读取，但正文或动作数超限时，模型统计仍可计为 HTTP 完成，任务则失败；HTTP 响应读取超限计为请求失败。任务失败数与模型 HTTP 失败数不是同一口径，不新增自动重试或固定总停止时间。完整 HTTP 协议体和解码正文分别设限，满足其中一个上限不保证另一个也满足。

单条读取、状态筛选与来源核对保留，页面仅展示错误类别，不输出超长回复或模型内部思考。Agent 模型请求仍沿用 30 秒客户端超时，识图另有[自己的响应和描述限制](agent-vision.md)，普通聊天及 GPT 请求不因本功能改用 Agent 上限。功能需新构建。

### 在上下文与识图准备期间停止

登录后台，在目标机器人和群/私聊的任务列表手动读取最新状态，再点击“请求停止此任务”。新构建会在准备开始、长期记忆读取之后、每个事件预处理之前、每张图片下载前后、识图模型调用前后、Agent 模型调用前后检查本次任务是否仍可继续。权限、会话范围、任务编号及版本校验沿用原流程，没有新增 QQ 命令或停止入口。

例如任务正在下载第一张图时登记停止：已发出的下载按原期限完成或失败，随后检查到停止便不再调用该图的识图模型、不下载下一张图，也不调用 Agent 模型。若正在等待识图模型，当前请求仍可返回，但不为该结果新增描述缓存，也不继续后续图片或 Agent 模型。若 Agent 模型已在途，返回结果在动作解析及登记前丢弃，不派发后续动作；已发出的平台动作仍按原回执规则处理，停止不逆转执行效果。

后台更新全局 AI 配置或重置导致设置代次变化时，同样在这些检查点结束旧准备；未登记停止的任务显示“设置已更新”失败，不能冒充用户取消。检查只属于本次调用，不修改共享 Agent 的检查回调；不同机器人及会话分别使用各自任务状态。

检查点之间仍有执行窗口，不承诺请求发出与后台停止完全原子，也不立即取消在途 HTTP、识图解码、数据库读取或纯文本拼装。任务可能继续显示“已请求停止，等待在途请求返回”，需手动刷新；不新增自动轮询、自动重试、固定总停止时限或任务重放。下载每张最多 10 秒、单次模型请求 30 秒等原限制见[识图输入](agent-vision.md)。模型准备次数仍在准备入口登记，即使实际 Agent HTTP 请求被阻止也可能为 1；在途识图请求仍计入识图 HTTP 统计，不能要求两种计数相等。

内部宿主使用 `NextAgentActionsChecked`，把当前任务及设置代次检查按调用传入 SDK `GetActionChecked`；非空检查要求已配置 `HistoryStore`，避免旧内存日志的共享回调绕过检查。原 `GetAction`、`NextAgentActions` 和空检查调用保留兼容。查看列表、按编号核对、来源阅读及任务存储字段不变。本功能需新构建。

### 查询额度与响应摘要

新构建的任务列表和按编号核对结果显示“本任务历史与记忆查询”。登录本机后台，读取已连接机器人的目标群或私聊任务即可查看，无需新增配置或 QQ 命令，运行中任务仍需手动刷新。

摘要显示三次共享额度已用次数，并分别列出历史检索、历史读取、记忆检索和记忆读取。参数无效的查询也消耗一次额度；第四次请求被拒绝，不增加已用次数，另外登记“超额拒绝”。`save_memory`、普通聊天和平台动作不占用这三次额度。重新创建同任务的内部查询器沿用原额度，其他任务、机器人及群/私聊分别统计。

| 响应统计 | 含义 |
| --- | --- |
| 成功响应 | 合法查询的成功响应已入档；不证明模型收到、理解或采用 |
| 空结果 | 成功响应没有来源或记忆条目；只说明本次查询返回为空 |
| 覆盖不完整 | 成功响应标记 partial，包括扫描/返回预算、片段截断或结果数量限制 |
| 参数或读取错误 | 已占用额度的参数错误、读取错误或请求/响应记录失败 |
| 超额拒绝 | 三次额度已用完后的请求，没有执行新的查询 |

空结果和覆盖不完整可能同时计入同一次成功响应，例如只搜索部分档案而未命中。它们不是互斥状态，也不表示完整历史或所有长期记忆都不存在。修订已变化、记忆停用或范围不匹配的精确读取可成功返回空结果，不能据此确认原记忆从未存在。

执行查询前先保存已用额度，响应成功入档后再更新成功和覆盖计数。若查询尚在途，或进程中断前未可靠保存结束统计，页面提示“查询结果尚未确认”；不根据动作终态或旧响应补造成功。停止后保留已登记查询的真实结果，不再开始后续查询。额度或摘要保存失败会停止流程并明确显示“未可靠保存”，不能把旧计数当作当前成功。

新任务已统计的零次与旧记录未统计分开，非法摘要不显示有效计数。摘要随任务持久化，模型下一轮准备不会清空；列表、筛选和按编号读取均保留，只读查看不调用模型、执行查询或改变额度。切换范围和退出按原规则清理页面，正文和关键词不保存在任务摘要内。

接口新增 `queries`：`available/used/limit/searchHistory/readHistory/searchMemory/readMemory/successful/empty/partial/errors/denied`。此处记录查询响应，不等于上下文中的历史/记忆来源片段计数；成功响应后来仍可能被上下文容量裁剪，也不计入直接长期记忆装载条数。旧字段缺失表示未统计，不自动扫描历史补齐。功能需新构建。

### 累计动作结果

新构建的任务列表和按编号核对结果显示“本任务累计动作结果”，分别累计成功回执、平台拒绝、结果未知和本地失败。登录后台，读取已连接机器人的目标群或私聊任务后即可查看，无需新增配置；运行中任务仍需手动刷新。计数贯穿本次任务，不被下一轮模型准备或最近动作覆盖。

| 项目 | 计入条件 |
| --- | --- |
| 成功回执 | 宿主登记本地动作成功，或 OneBot 返回成功状态和成功码 |
| 平台拒绝 | 宿主登记平台失败回执 |
| 结果未知 | 宿主不能确认结果；已登记的在途动作结束或进程中断时没有可靠保存的回执 |
| 本地失败 | 检索、读取、记忆保存或其他本地处理未完成 |

一个动作只有取得任务派发许可后才可登记结果，且最多结算一次。动作仍在途时不计入任何结果，页面另行提示；同一动作的重复结算被拒绝。模型准备或模型请求失败不计为动作结果，权限校验阶段排除的动作也不会计为已执行。平台失败或未知结果仍沿用停止流程、不自动重发的原行为。

停止请求不会抹去在途动作的回执：取消后返回成功时，终态可同时为“已停止”和“成功回执 1 次”。重复取消、重复结束和再次打开数据库不会重复计数。若动作已登记但结束时没有回执，计为未知；重启时只依据最后可靠保存的记录恢复，未保存的成功不能补造。新任务从零开始，其他机器人及群/私聊分别统计。

旧任务没有这项测量时显示“没有可核对的累计动作结果”，不把零值当作实测；新任务已统计的零次与旧摘要有明确区别。状态未可靠保存时隐藏计数并提示故障，仍须核对存储。保存后的计数随单条读取、列表及状态筛选返回，不包含正文、动作参数或思考。

接口任务对象新增 `results`：`available/ok/rejected/unknown/localErrors`。它和 `activity` 的登记次数分别统计；在途结果未结算或旧摘要缺失时两者总数可能不同。成功回执包含本地动作，不能解释为发送成功次数，也不证明 QQ 客户端收到或已读。来源和动作尝试仍可在会话档案核对，停止不会撤回或逆转已执行的动作。功能需新构建。

### 执行登记与上下文取用

读取任务状态后，每个新任务显示累计执行摘要：Agent 模型准备次数、普通聊天兜底准备次数、本地动作登记次数和平台动作登记次数。计数贯穿同一任务，不随每轮上下文摘要清空；新任务从零开始。无需新增配置，仍要求后台登录并选择已连接机器人与会话，手动重新读取即可更新。

模型计数在进入准备阶段时增加，准备可能在 HTTP 请求发出前因读取记忆、处理图片或其他错误而失败；因此不等于模型统计页面的 HTTP 调用数。`search_history`、`read_history`、`search_memory`、`read_memory`、`save_memory` 归入本地动作，其他派发动作归入平台动作；动作登记不等于成功执行或消息送达。结束标记不是派发动作，不计入。被取消阻止的后续阶段不增加计数，在途动作的后续回执也不重复计数。

累计值与任务状态一起保存，重启遗留任务标为中断并保留已保存的计数，不自动重放。旧版本任务没有该摘要，显示未统计而不是零次；状态存储失败时隐藏累计值并提示未可靠保存。接口任务对象新增 `activity`，包含 `available/modelPreparations/fallbackPreparations/localActions/platformActions`，没有正文、动作参数或模型思考。

页面显示阶段、最近动作名和结果、起止时间、脱敏错误类别，不显示模型思考、动作参数或回复正文。完整动作尝试及响应继续在会话档案查看；结果只对应最近一次动作，不代表每个动作都成功。

最近一次 Agent 上下文准备记录装入的历史条数、历史检索及按序号读取响应所含来源片段数、历史正文 UTF-8 字节数、历史预算及截断标志。另显示记忆检索/读取响应中的片段数，来自实际装入且仍可解析的 `memories` 数组；它与上述历史来源分开计数。重复检索和读取可能重复计数，不代表唯一记忆数或当前仍启用的条目数；保留的旧响应仍属于当时的历史资料。未检索到条目时记录零，旧任务未保存这个字段时明确显示未统计。

计数在实际拼装时产生；请求随后失败仍只表示已准备输入，不证明模型收到或理解。超预算时舍去更早记录或截取单条内容，最近重置之前的历史记录默认不进入输入；响应被截断到无法解析原数组时不计片段，因此零值也不能证明本任务没有发起查询。每轮与普通聊天兜底准备均清空上一轮摘要，新摘要随任务状态持久化。

接口 `context.memorySources` 为可选整数：缺失表示旧摘要未统计，零表示本次实际可解析的记忆响应数组没有条目。该计数不会增加直接长期记忆装载摘要的条数；查询响应仍计入历史正文容量。

历史字节数不含人物设定、工具协议、长期记忆和后续图片描述，不是完整请求字节数、token 数或模型阅读证明。普通聊天兜底使用不同上下文，当前不提供其取用计数。任务数、模型调用数和消息发送数沿用独立口径。

长期记忆另显示最近一次准备的启用条数、UTF-8 字节数、30,000 字节预算及 100 条上限。字节数包含每条的编号和版本标签，不含条目间换行、人物设定或工具协议。按最新记忆编号优先选择，容量不够时舍去更早条目；页面区分条数限制和字节限制。恰好 100 条且没有更多启用条目时不标为截断；停用条目不计入。未达到限制只表示本次读取范围的启用记忆已准备，不证明模型收到或理解。

每轮 Agent 模型请求前清空上一轮摘要，在实际读取记忆时记录，再与历史摘要分别保存。读取失败明确提示，不当作空记忆；摘要写入失败也会停止本轮准备。旧文件模式只显示“尚未统计最终输入”，已归属其他机器人的旧文件明确标为未装入。旧任务、尚未准备或普通聊天兜底没有记忆摘要，不能把缺失字段解释为零条。已完成任务保留当时摘要，后续修订记忆不会改写旧任务计数；重新读取任务页即可查看，无需新增配置。

## 存储、故障与恢复

任务存入 `data/aichat/history/<机器人QQ>.sqlite` 的 `agent_tasks` 表，随机任务 ID 与进程实例区分新旧运行。首次打开账号数据库时，把其他进程遗留的运行任务标为中断，不自动恢复执行。

状态无法保存时停止派发并显示“状态未可靠保存”；该会话暂停新任务，检查磁盘/权限后重启。不能把内存终态当作已落盘的证据。数据库不可读取时接口报错，不显示为空列表。

备份前停止服务并保留数据库及 SQLite 辅助文件；配置备份不包含任务。旧程序不识别新表，回退不会重放任务。单进程约束仍适用，不支持两个程序共享运行目录。

接口为 `GET /api/agent/tasks` 和 `POST /api/agent/tasks/cancel`。两者携带 `botId/type/id`，停止额外携带 `taskId/version` 字符串。读取响应含 `items/more/next/limit`；有更早任务时，将 `next` 原样作为下一次 GET 的 `before` 字符串参数，首次读取省略 `before`。不把序号转成 JavaScript Number。分页位置始终在请求的机器人和会话范围内查询；无更早任务时 `more=false`、`next` 为空。每页上限 50，共用 Agent 后台两路并发限制；未知任务 404，版本冲突 409，存储不可用 503。
