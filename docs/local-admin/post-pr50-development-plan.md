## 1 目标与边界

当前任务视图同时展示有有效会话/任务标识的任务组，以及缺少有效关联标识的独立请求。次数筛选可以找出单次组，但不能区分“具备关联标识、窗口内恰好一次”的任务和“缺少标识、逐条展示”的请求。

下一批新增“请求关联类型”筛选，帮助分别核对两类数据。直接使用modelTaskUsage已生成的grouped布尔值，保留原有分组、风险/结果/次数条件、输出量排序与请求覆盖统计。不根据次数、kind、结果或Token推断关联类型，也不尝试补造标识或重新归档。

本批作为一项完整功能交付，不把两个选项或其测试拆成多个QQ验收项。历史预算900000、[既有待验收及暂缓项](remaining-acceptance.md)保持；后续未授权目标不自动开始。不增加关联质量评分、身份查询、持久化筛选、后端参数或报告字段。

## 2 操作与筛选契约

计划入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量。沿用后台登录权限，无额外角色配置；实现后需构建部署并刷新后台生效，无保存配置动作。本轮使用说明只增加规划入口，不将新选项描述为已可使用。

新控件使用原生select，标签“请求关联类型”，ID为`model-task-association`。放在次数条件之后、排序之前，Tab顺序与视觉顺序一致。

| 选项值 | 显示文字 | 匹配规则 |
| --- | --- | --- |
| all | 全部关联类型 | 默认，保留现有全部分组 |
| linked | 有效会话/任务关联 | g.grouped为true；一条或多条请求均可 |
| independent | 独立请求（缺少有效关联） | g.grouped为false；沿用逐条成组 |

只有会话和任务标识都通过已有规则，才属于有效关联。任一缺失或无效均归入独立请求；不在筛选器再次执行标识正则。有效标识按已有精确分组行为处理，不做大小写归一化或跨会话合并。

四类条件按组取交集：风险、结果、次数、关联类型；随后使用当前排序，包括PR #50的output。风险与结果仍可能由组内不同请求命中，展开保留完整匹配组。独立请求与“至少2次请求”的交集为空，这是有效结果，不自动更改其他选择、不禁用该组合、不新增警告。

计数仍显示匹配组数X/Y与完整匹配组请求数N/M，Y/M为完整当前窗口，不随关联类型变化。无匹配显示0/Y和0/M及原无匹配提示；有效空窗口、未知窗口保留原空态，不添加虚构0/0行。关联有效不证明任务完整或成功，独立请求不等于失败或数据损坏。

### 固定样例

A组有有效关联且1次请求，B组有有效关联且2次请求，C和D各缺少有效关联且1次请求，原窗口共4组5次。

- 全部：4/4组、5/5次；linked：2/4组、3/5次；independent：2/4组、2/5次。
- linked与single：只保留A，1/4组、1/5次；linked与multiple：只保留B，1/4组、2/5次。
- independent与multiple：0/4组、0/5次；恢复全部次数后重新出现C、D。
- B中一条命中风险、另一条命中结果时，交集保留B的两条请求，覆盖仍为2/5；切换输出量排序不改变这些计数。

## 3 生命周期与兼容范围

改变关联类型只触发本地重绘，不新增网络请求。手动/自动刷新保留选择，按新快照重新分组、筛选和排序。仍可见的同键任务保留展开和摘要焦点；筛掉后再出现默认收起，不保留跨条件隐藏组的展开缓存。

关联标识在后续快照变为有效时，按现有分组结果进入linked；不把此前独立条目的展开状态迁移到新任务。跨启动不继承旧展开，控件选择沿用现有刷新契约。窗口淘汰只依据最近最多256条已结束请求，不补查更早轮次，不重放模型调用。

费用阈值草稿不改变结果；应用或恢复默认阈值后重新计算风险交集，关联选择保持。重置任务视图将关联类型恢复all，同时恢复既有条件/原顺序并收起明细，保留已应用阈值和草稿。

读取失败清空旧内容并禁用关联控件，恢复后按保留选择计算；有效空窗口继续允许选择条件。离页、退出及认证失效按现有重置流程恢复all，迟到响应不能带回旧内容。整页刷新回默认，不使用localStorage保存状态。

完整JSON导出不受关联类型筛选影响，继续含整个快照及既有grouped字段，格式保持version=1；报告校验器保持独立。固定快照下，除导出时间外，筛选前后完整报告内容一致。报告中的grouped不是本次新增字段，不另行变更格式。
