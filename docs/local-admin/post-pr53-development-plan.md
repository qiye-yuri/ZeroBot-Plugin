## 1 目标与范围

当前任务视图已能按风险、结果、次数、关联类型和输出已知情况筛选，但匹配任务的输入及缓存量仍须逐组查看。下一批补齐“匹配任务”和“全窗口”的已知输入、缓存命中、缓存未命中小计，便于比较当前关注范围与窗口总量。保留原输出小计，这是一个完整功能，不把三个字段拆成三个QQ验收项。

复用modelTaskUsage已产生的g.totals中input/hit/miss/output及known，不读取原始usage重新校验，不增加请求、后端接口、存储、费用估算、缓存率或报告字段。历史预算900000及[其他待验收项](remaining-acceptance.md)保持。输入与缓存分项可能不一致，各字段独立相加，不推导、不补齐、不相互覆盖。

## 2 计划入口与显示契约

入口为登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量，沿用后台登录权限。未来实施、构建部署后刷新页面生效，无新增设置或保存动作；本轮使用指南只提供计划链接，不把功能写成已上线。

在现有匹配组数和请求覆盖摘要之后，以input、hit、miss、output固定顺序显示四对文本行，每一对先匹配任务、后全窗口：

- 匹配任务已知输入：X Token（已知k/n次）。
- 全窗口已知输入：Y Token（已知j/m次）。
- 缓存命中、缓存未命中使用同样格式，标签分别为“匹配任务已知缓存命中”“全窗口已知缓存命中”和“匹配任务已知缓存未命中”“全窗口已知缓存未命中”。
- 最后保留现有“匹配任务已知输出”“全窗口已知输出”两行的含义和格式。

k/j为当前字段的有效值次数，n/m为匹配整组/完整窗口的请求次数，不能借用输出字段的known。已知值0显示0 Token；known为0显示未知，不能把未知写成0 Token。无匹配显示各字段未知、已知0/0次；全窗口仍显示完整快照数值。有效空窗口、无效窗口沿用现有简短提示，不添加八行空统计。

共用说明调整为：“各字段仅合计已返回的有效Token值，已知次数分别计算；未知不补零，缓存分项不反推输入，不代表完整用量或费用。”不输出跨字段总和，不将命中与未命中相加充当输入。沿用可换行文本和textContent，暂不引入表格、折叠开关或新控件；仅在实测布局问题存在时局部修改样式。

A为有效关联组，两条请求；B为有效关联组，一条请求；C为独立请求。未知表示沿用既有字段规则判定无有效值。

## 3 生命周期与导出边界

五类筛选按现有完整组交集计算，先筛选再排序；排序只改变显示顺序，不改变小计。阈值草稿不改变范围；应用阈值、恢复默认阈值时重算风险交集并更新小计。重置恢复全部范围和原始顺序，保留既有阈值与草稿行为。

手动/自动刷新使用新快照重新计算，不累计上一次小计；保留现有筛选和可见同键组的展开/焦点。跨启动、256窗口淘汰、读取失败、恢复、离页、退出及认证失效沿用现有渲染清理流程，不能残留旧的小计。空态与无匹配需分别验证。

导出仍是version=1完整快照与taskBreakdown，不新增筛选状态、小计字段或局部导出。固定快照和阈值下筛选前后除exportedAt之外报告一致；实际下载使用独立校验器核对。输出已知情况仅筛输出字段，不能解释成输入/缓存也全部已知。
