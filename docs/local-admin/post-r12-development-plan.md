## 3 R13 会话插件入口设计

### 用户流程与范围

登录后台，读取 Agent 会话并成功核对配置后，群会话显示“设置此群插件”，私聊显示“设置全局插件”。群入口读取已加载 `agentScope.id` 对应的群，不读取尚未提交的会话输入框；私聊入口明确读取全局 `group=0`，旁边说明“此页不能编辑私聊覆盖；全局设置会影响所有群和私聊”。

来源机器人只解释从哪里进入。插件设置沿用实例共享规则，同群不同机器人进入相同插件范围；同编号私聊不能进入该群设置。入口不自动启用插件、调整响应、保存配置或发送消息。

有插件草稿时复用一次插件丢弃确认；取消保持来源页、草稿和范围，且不发读取请求。原记忆等离页检查继续生效，取消也不读取插件。全部确认通过后读取目标，读取成功才替换范围并丢弃旧插件草稿。其他页面草稿保持原有规则，不引入跨页缓存。

### 读取与失败语义

复用 `/api/plugins?group=...`，每次有效点击最多一次该接口 GET。若导航自动读取与目标读取冲突，只给既有导航增加最小可选控制，默认行为保持。来源群号始终使用字符串，沿用有效群号边界，不转为 JavaScript Number。

读取期间沿用 `pluginScopeBusy` 禁用编辑和重复操作。成功后显示目标范围及共享说明；失败沿用原插件页规则：旧范围、列表和草稿可保留，但必须明确显示“目标范围读取失败，当前仍为原范围”，不能把旧列表标成新群。首次无列表时显示失败和重读入口，不伪造空群状态。

沿用 `pluginListRequest`、`pluginGeneration` 和登录生命周期处理失效请求。若新入口需要限制离页后的结果更新，在现有流程内补充判断或失效处理，不另建请求调度器，也不顺带改变原插件页普通刷新行为。重读由用户手动触发。

### 验收矩阵

| 场景 | 验收断言 |
| --- | --- |
| 群 A 的核对结果，插件页先前为全局或群 B | 一个GET读取群 A；成功后范围、列表及后续保存目标一致 |
| 私聊 A，与群 A 同编号 | 入口说明明确全局；只读 `group=0`，不请求群 A |
| 同群不同机器人、超过安全整数范围的合法编号 | 群目标相同；完整编号不丢精度；没有机器人维度覆盖 |
| 会话输入改为 B 但未加载 | 仍使用已加载 A；换范围重读后才使用 B |
| 插件草稿取消、确认；记忆离页确认取消 | 取消零GET、零写入且草稿保持；确认一次；读取成功才清插件草稿 |
| 目标GET失败、重新读取成功 | 明确目标失败及保留范围；草稿仍属于旧范围；重读后正常切换 |
| 读取中重复点击、退出、离页或新的范围请求 | 沿用在途限制；失效响应不覆盖新目标或恢复失效页面 |
| 插件控制不可用或目标无插件 | 沿用原只读/空列表提示，不显示可误用的保存操作 |
| 恢复后首次进入插件页 | 自动重读与目标读取合并为一次GET |
| 原插件手动范围、刷新、逐项及批量保存 | 范围与修订行为保持；新入口本身无POST、模型、Search或QQ请求 |
| 键盘、320px窄屏、浅色与深色 | 入口可操作，范围和失败说明不遮挡；截图不替代行为断言 |

## 7 不过度防御性编程的实施约束

- 复用认证、CSRF、修订校验、草稿确认及请求代次；在可信边界校验目标，不逐层重复校验完整对象。
- 只提取表单和快捷入口确实共用的逻辑，不设计通用导航框架、通用状态机或新配置存储。
- 失败直接说明并允许手动重读，不自动改目标、补默认配置、换服务或吞掉异常。
- 保留作用域和数据隔离规则，不能为简化代码把私聊映射到同号群。
- 测试关注可观察的目标、草稿、请求次数和保存副作用，不逐字复制静态文案来编写测试。
- 独立业务故障另立修复项；达到验收出口后交付，不顺带重构无关模块。
