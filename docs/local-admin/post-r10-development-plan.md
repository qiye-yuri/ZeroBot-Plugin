## 3. R11：会话摘要进入全局模型配置

### 用户流程与范围

1. 登录后台，读取Agent会话，点击“核对会话配置”。
2. 在摘要现有操作区增加“设置全局模型”。仅在已加载会话且核对成功后显示；模型引用无效的摘要仍可使用此入口修复配置。
3. 点击后说明“模型配置由本实例共享，修改会影响使用该配置的所有会话；此入口不创建会话模型覆盖”。来源会话只作为返回核对时的上下文，不改变模型配置的作用范围。
4. 读取最新已保存AI配置。旧字段模式定位全局模型表单；命名模式继续读取并定位命名模型表单。以本次读取结果决定模式，不沿用之前摘要的模式。
5. 用户按既有表单编辑和显式保存。返回Agent会话后按现有流程读取并核对，不自动保存、测试、返回或刷新摘要。

本批只提供一个全局入口，不为五个模型卡片分别新增跳转，不自动选中、创建或迁移配置。识图等入口沿用原有表单能力。

### 开发步骤

| 工作包 | 实施步骤与代码落点 | 完成条件 |
| --- | --- | --- |
| R11-01 | 在 `assets/index.html` 的会话核对操作区增加按钮及共享范围文字；在 `assets/agent-archive.js` 接入已有可用性与已加载范围规则 | 未加载、读取中、未登录时不可触发；从已成功摘要可进入，包括模型引用错误的摘要 |
| R11-02 | 在 `assets/ai.js` 为新入口复用 `confirmAIDiscard`、`resetAI`、`loadAI`；使用 `showWorkspaceView` 的 `autoLoadAI:false` 避免双重读取 | 先处理草稿，再导航读取；取消不发请求、不清表单、不切页 |
| R11-03 | 将命名模型按钮现有GET处理提为供两个入口调用的函数，保持原按钮行为；按最新 `aiState` 的配置模式定位表单 | 每次点击最多一次AI读取；仅命名模式额外一次命名模型读取；不重复确认，不触发POST或诊断 |
| R11-04 | 为新入口补充浏览器回归，更新 `conversation-check.md`、`named-models.md`、`user-guide.md`；纳入既有统一验证入口 | 通过下述矩阵；使用文档明确共享范围和手动保存、重读 |

以上 `assets/` 均指 `internal/localadmin/assets/`。`loadAI` 当前会重置命名模型、人物和搜索表单，因此本入口须提前用现有总草稿确认明确提示受影响的表单，不承诺这些草稿自动保留；确认后只放弃明确提示的现有草稿。无需为这一个入口引入跨页面草稿缓存。

读取失败时显示失败，不继续显示可误认成本次目标的旧表单。沿用 `aiGeneration`、登录状态和现有页面生命周期丢弃迟到结果；提取函数若需报告成功与否，用简单返回结果，不建立新的请求调度器。诊断正在进行时沿用既有设置页交互规则，导航不代表撤销已发出的外部调用。

### 验收矩阵

| 场景 | 预期行为 |
| --- | --- |
| 旧字段/命名模式各一次 | 正确表单可见且定位；文字明确全局共享；只读请求数分别为1/2，无保存、模型、Search或QQ请求 |
| 摘要读取后模式被其他窗口改动 | 跳转按最新读取的模式定位，不按旧摘要误导；无自动迁移 |
| 已加载群、同号私聊、另一机器人及表单中未提交的范围草稿 | 来源说明来自已加载范围；全局模型作用域一致，不生成会话覆盖；原人物/参数/搜索快捷入口回归通过 |
| 全局、命名模型、人物、会话参数、搜索任一有草稿 | 总确认覆盖实际被重置的草稿；取消零请求且原值保持；确认只出现一次，随后正常读取 |
| AI读取失败、命名读取失败、读取中离页或退出 | 无错误目标残留可编辑；明确失败；迟到结果不恢复页面；重新点击可正常读取 |
| 已知模型缺项或引用错误、正常模型配置 | 均可到设置页；不把字段错误当成永久禁止修复的条件 |
| 键盘及320px窄屏、浅/深色 | 可用Tab/Enter操作；按钮与范围说明可读，不遮挡错误信息 |

验收以行为断言和实际GET/POST调用记录为准，不为新增一行按钮编写复制实现逻辑的测试。部署后的页面验收只需读取和导航，不能为演示修改日常模型或调用付费服务。

## 4. R12：模型及搜索诊断结果读法

### 呈现契约

直接显示：入口名称、通过/失败/无结果结论、现有服务端说明、测试时间、耗时、已有HTTP状态；搜索同时显示合法结果数。历史结果提示及“未保存草稿不参与”始终在折叠区外。保持当前“成功仅代表本次基础调用”的范围说明。

完整配置修订移入原生 `details`，标题为“完整测试配置修订（展开核对或复制）”。每次新测试结果默认收起；同一结果因控制按钮更新不反复折叠。模型和搜索分别保留自己的结果；不将缺失HTTP状态显示为0或200，不从未知类别推测提供商错误原因，不新增错误映射规则。

### 开发步骤及出口

| 工作包 | 开发步骤 | 验收标准 |
| --- | --- | --- |
| R12-01 | 修改 `ai-probe.js` 的 `renderAIProbeResult`、`renderAISearchProbeResult`，统一结果字段顺序 | 聊天/GPT/群总结/Agent及搜索结论准确；搜索空结果与失败可区分 |
| R12-02 | 使用原生details装载完整修订；保持版本状态元素在折叠区外 | 完整字符串不截断，可选择复制；键盘展开/收起正常；重新渲染新结果默认收起 |
| R12-03 | 保留 `renderAIProbeControls`、共享在途限制、版本比较、清理与错误路径，按实际重复量决定是否提取一个小渲染函数 | 保存/重读导致修订变化时旧结果明确标为历史；编辑未保存草稿不伪造新测试版本；离页/退出清理保持 |
| R12-04 | 扩展 `scripts/test-ai-probe-ui.mjs`、`scripts/test-search-probe-ui.mjs`；同步 `model-probe.md`、`search-probe.md`、使用指南 | 测试覆盖通过、空结果、HTTP拒绝、无HTTP状态、历史结果、在途互斥、迟到清理；320px及两主题可读 |

新增交互只展开本地结果，不发网络请求。`/api/ai-test`、`/api/ai-search-test` 的请求与响应格式、30秒/10秒期限、容量和共享在途规则不变。无持久化诊断历史、结果导出、轮询、自动重试或费用估算。离线合成结果足以验证本批显示变化，不把真实付费调用作为交付门槛。

## 5. 条件性验收与暂缓方向

以[未恢复功能清单](unresolved-features.md)、[插件测试结果](feature-test-results.md)的最新记录为准，历史失败不覆盖用户后来确认通过的结果。本次规划不发QQ消息，不重新启动此前已结束的测试批次。

| 事项 | 启动条件及验收证据 | 当前安排 |
| --- | --- | --- |
| B站动态/开播通知 | 用户提供可控制的测试账号及实际事件，明确测试范围；核对实际通知与重复拉取表现 | 等条件具备再单独安排；接口成功或模拟推送不等于真实通知通过 |
| 成功的视频总结 | 提供网页确有总结的有效样本；区分上游业务失败、解析成功和QQ显示 | 保留未验收，不添加无限重试或替代服务 |
| 钓鱼、真实好友申请及入群邀请 | 用户重新安排真实交互或事件；核对完整结果而非单个发送回执 | 沿用指定待验收状态 |
| 更新监控实际更新、其他角色权限 | 有真实更新或相应测试角色 | 不恢复用户已取消的角色验收，不伪造通过 |
| P010本地AI画图、定时整合 | 明确部署条件和新的独立需求 | 继续暂缓 |

会话模型覆盖、自动选模、诊断历史、向量库、多Agent、定时自主发送及批量权限编辑继续不排期。会话摘要前后差异比较可作为候选，但目前缺少明确使用需求；不预存快照，不安排R13。若以后出现可复现业务故障，先独立修复并验证，不用本规划扩展其范围。

## 6. 验证、交付与部署

每批先做相关页面回归，再执行既有统一验证 `scripts/test-agent.ps1`，完成最终构建与隔离整机。新增测试接入原入口，不新增平行测试框架。示例命令中的R11输出名在R12实施时替换为对应批次：

```powershell
go generate main.go
pwsh -File scripts/test-agent.ps1 -OutputName zerobot-r11-validation.exe
git diff --check
```

R10的18步、183项页面及151项冒烟标记是历史结果，不作为未来批次自动通过数量。报告当批实际运行、失败修复和复验结果，记录最终程序SHA256。界面改动验收合成数据与实际页面；真实提供商、QQ效果分别标记，不混记。

按仓库[AGENTS.md](../../AGENTS.md)约束，付费模型及需用户配合的真实AI测试只安排在北京时间空闲时段，执行前核对时间及适用日历；本规划不安排调用或自动定时任务。未涉及付费请求的本地检查正常执行。

功能完成时同步使用入口、权限、共享范围、草稿影响、生效方式及限制。中文提交、`codex/`分支、用户origin和独立PR；显式暂存当批文件，核对远端SHA。合并部署按后续明确请求执行：停机备份并验证，只替换已验收程序，保留配置、数据库及OneBot登录；部署后核对进程、接口、数据和实际页面，记录回退程序位置。不要将旧数据库整体覆盖回日常目录。

本次只有规划文档，按仓库约定检查源码落点、方案一致性、链接、UTF-8、围栏、差异和上传清单即可，不重跑机器人测试、不重启服务。

## 7. 不过度防御性编程的具体约束

- 复用现有登录、CSRF、修订检查、草稿确认及页面代次；不新增重复字段验证或第二套状态中心。
- 只在命名模型读取出现第二个真实调用点时提取函数；不为两个入口设计通用导航/表单框架。
- 明确读取失败并允许用户重读，不自动修复配置、补默认值、换模型或吞掉错误。
- 不增加数据库表、迁移、后台任务、诊断队列、自动请求或额外订阅。
- 测试关注范围、草稿和请求副作用等真实行为；达到本批验收出口即交付，其他想法另列。
