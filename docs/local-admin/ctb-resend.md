# FTB 已下载文件重发

新增QQ命令：

~~~text
FTB重发 ctb-135-123456789
~~~

编号是示例，请复制下载完成或发送失败消息里的实际任务编号。此入口仅机器人主人可用；群里仍须@机器人，且该群的响应、ctb插件和FTB群聊权限必须允许使用。群管理员和普通成员不能重发，即使他们有下载权限。

## 操作与发送目标

1. 本版本下载成功并完成ZIP校验后，会保存重发记录并在回复中给出编号。需要路径修复时只登记最终 -windows.zip，不把原包一起重发。
2. QQ上传失败后先处理群文件权限、空间或好友关系，再由主人发送一次 FTB重发 编号。不要重新执行FTB下载。
3. 主人私聊发起时发给主人自己；在群里发起时，按当前FTB配置发送到当前群文件，或私聊本次发命令的主人。不会自动发给原下载者或原来的群；主人选择命令所在会话即选择本次目标。
4. 看到“QQ接口已接受重发”后，在对应位置确认实际收件。接口回执不等于用户已收到；失败可修复原因后手动再试，不自动重试。

工具与文件发送开关都须开启。设置沿用[FTB工具](ctb.md)既有入口，不新增页面或开关。部署新版程序后命令生效，无需修改原配置。配置变化从下一条命令读取，重发执行时复用原任务忙碌锁，期间不能开始新的查询/下载/重发或保存FTB配置。

## 范围、次数与存储

- 重发不启动下载器，不重新访问FTB服务，不扣群下载次数；群下载额度用尽后仍可重发已有文件。
- 当前下载目录中的每个成功任务保存 delivery.json，只包含最终ZIP文件名与SHA256。重发前核对文件仍存在且内容与下载校验后相同；全部通过后才开始发送。
- 文件及记录保留时，机器人重启后仍可重发。更改下载目录后只查新目录，不跨目录找旧任务。
- 只支持本版本成功登记的下载。旧版本已下载目录、半成品、没有记录的文件不会自动导入；继续按原方式由主人手动处理。
- 命令不接受绝对路径或任意文件名；任务目录不能被目录联接/符号链接替换，记录中的ZIP必须为任务目录内的普通文件。文件缺失、改动或记录损坏时停止并说明原因。
- 多文件任务依次发送，遇失败即停止；前面已发送的文件无法撤销，再执行会重发整批，可能重复，不提供逐文件进度或自动补偿。
- 不自动清理文件、迁移历史下载或导入重发记录，不改变现有下载计次规则。记录保存失败会明确报告下载任务失败并保留已下载文件，不宣称具备重发能力。

## 验证与限制

自动化核对真实生产下载流程生成的修复包记录、重启读取、群/私聊目标、普通成员拒绝、缺失/改动文件拒绝、失败后可重试及额度不变。整机使用合成下载器、独立数据目录和假OneBot，无真实下载、付费模型或真实QQ发送。

新部署QQ实际收件仍待集中配合；任务入口、测试结果、部署与队列见[本批开发及验收](ctb-resend-acceptance.md)。
