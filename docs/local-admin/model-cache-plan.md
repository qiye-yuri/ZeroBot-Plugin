2026-10-23：已实现用量统计和Agent请求重排，本地回归通过；尚未进行付费对照测试，不宣称实际命中率已提高。

用户提供的一小时统计：输入命中62,720 Token、输入未命中5,808,480 Token、输出373 Token，输入合计5,871,200 Token，输入命中率约1.0683%。不能从该汇总推算请求数或断言每个请求均未命中。

## 修改前确认的本地因素

修改前，`third_party/go-onebot-agent/prompt.go`每次构造系统提示时注入当前时间、Unix时间、聊天类型和迭代轮次；系统提示位于历史之前。`third_party/zbputils/chat/history.go`的历史输入预算为900,000字节（不是Token），按近期记录装载，超预算时滑动裁剪。时间和轮次变化会缩短共同前缀，后面的长历史难以复用。角色、权限、联网开关及记忆变化也影响共同前缀。不能据此计算各因素的实际费用占比。

## 实施顺序

1. 先增加每次模型请求的用量记录：提供商、模型、匿名会话标识、任务/轮次、耗时、prompt_tokens、prompt_cache_hit_tokens、prompt_cache_miss_tokens及completion_tokens。统计字段缺失时标为未知；不记录密钥、聊天正文或完整请求。应同时覆盖Agent和普通聊天，并保持原有响应大小限制及异常处理，不能为读取usage引入无限制缓冲。
2. 调整请求排列：稳定规则和当前实际权限保持稳定前缀；历史事件保持原顺序；每轮变化的时间、轮次等运行状态移至历史之后，作为本轮临时上下文，不写入历史档案。先保留原记忆载入规则以缩小变更面。需适配普通system及userSystem模式和各协议，避免第二次System调用覆盖既有系统规则。权限仍由宿主校验，不以缓存复用替代权限检查。
3. 分别比较固定规则、历史和动态部分的大小与共同前缀长度。若上下文成本仍偏高，再评估降低900,000字节预算、稳定分块或摘要；不直接清空历史，不盲目降低到可能丢失未完成任务的长度。较早原始记录继续留在本机，通过已有检索获取。预算调整单独验收，不与首轮排列修改混在一起。

## 本地验证

- 使用本机合成模型捕获同一会话连续两轮请求，确认只改时间/轮次时固定规则和历史前缀不变；新消息只追加，运行状态不重复落档。
- 验证权限变化、联网许可、记忆更新、群/私聊隔离、历史检索、停止动作及不同协议序列化；不能为了命中使用过期权限或遗漏最新记忆。
- 验证usage有值、缺失、错误类型以及超限响应；统计故障不应掩盖原模型错误或暴露内容。

## 付费对照

严格执行AGENTS.md中的北京时间空闲时段约束。使用同一模型、角色、权限和合成上下文，对修改前后各做少量请求；先测首轮及连续追加，再测工具返回后的下一轮。每次调用前检查时段，不批量重跑整套实机验收。记录实际usage，按累计命中Token/累计输入Token计算，而非按请求数量平均。预先设请求数和Token上限，未获足够证据时报告不确定，不承诺具体命中率。

DeepSeek缓存由服务商按前缀复用，属于尽力而为；参考 https://api-docs.deepseek.com/zh-cn/guides/kv_cache/ 。模型账单缓存不同于本地图片缓存、档案查询或长期记忆去重。

## 已实现的使用方式与边界

登录本机管理后台，进入总览的“模型接口请求”，可查看最近请求的Token加权缓存命中率，并展开“最近模型用量”查看最新20条。后台接口保留最近256次已结束请求，按结束顺序淘汰；重启清空。原有请求次数仍为本次进程累计，两者窗口不同。此页面只读，无需修改机器人配置。

记录输入、输出、命中、未命中Token，类别、模型、提供商主机名、时间、耗时、传输结果和请求编号。Agent主请求带匿名任务标识；聊天/Agent/识图入口有匿名会话标识，其他入口无法取得会话时明确为空。匿名标识使用进程随机盐，重启后不可关联。客户端请求序号仅表示该HTTP客户端的传输次序（含重定向），不是Agent迭代轮次；任务/会话未知时不猜测。

只提取已正常传输的JSON响应usage，不读取请求正文，不持久化聊天正文、密钥、完整URL或响应原文。最多临时缓存2MiB已消费的响应字节，超限立即丢弃统计缓冲，不额外读取、不改变原有响应及错误边界。非JSON、流式、缺字段、损坏、失败或提前关闭时相应用量为未知；零Token与未知不同。支持DeepSeek命中/未命中字段及OpenAI cached_tokens，未返回的miss不通过减法推算。

缓存率只按命中和未命中字段都完整的请求汇总：sum(hit)/(sum(hit)+sum(miss))，同时显示覆盖请求数；并非全账户账单，不包含其他程序请求。接口完成不代表模型内容有效或QQ发送成功；完整传输后的语义错误仍可能有有效usage。

Agent实际顺序为稳定系统规则（角色、当前权限）→原历史→当前会话记忆和宿主运行状态（时间、聊天类型、迭代轮次）。运行状态临时注入，不写档案；system/userSystem及OpenAI、Ollama、GenAI均已做离线请求捕获。历史预算仍为900,000字节，记忆选取、历史裁剪和权限检查保持原规则。记忆、角色、权限或历史裁剪变化仍会影响缓存。

本地验证覆盖：统计响应透明性、未知/零值、异常字段、缓存上限、失败与并发；跨协议请求顺序与稳定前缀；Agent及聊天存储回归；后台展示加权比例、未知值与文本转义。真实缓存命中及对话理解需要空闲时段少量实测，不能用本地测试替代。

补充输入格式优化：记忆仍按原规则读取和裁剪，但移到历史之后，与运行状态一起明确标为宿主参考上下文；记忆更新不再打断固定规则及历史前缀。历史JSON使用既有编码和顺序，不重写档案。角色、权限变化以及历史滑动裁剪仍会造成必要的前缀变化。
