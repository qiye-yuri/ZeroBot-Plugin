## 1 目标与选择依据

当前任务视图将匹配任务的全部请求一次拼接为长文本，最多256条，每条又包含风险原因。用户可以筛选任务，但仍需穿过大量明细才能比较各任务。下一批让用户先看到任务摘要，再展开关注任务的全部窗口内请求，保留PR39的风险原因和原始上下文。

本批只做任务呈现调整。沿用当前登录权限、筛选、排序、阈值与导出，不增加任务搜索、复制按钮、图表、批量展开、分页、历史账本或模型请求。它解决阅读问题，不承担完整任务审计或费用计算。

## 2 产品契约

入口保持“运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量”。首次读取时每组默认收起，窗口说明与匹配组数始终可见。每组是一项原生details，summary可用鼠标、Tab及Enter/空格操作。

收起时显示：匿名会话/任务标识（独立请求则显示请求编号）、窗口内请求数、四项Token已知小计及覆盖次数、有效缓存条数与加权命中率。摘要继续明确“窗口内”，未知不显示成零，小计不称为费用。保留完整匿名标识并允许换行，不使用省略后无法区分的标题。

展开后显示该组全部窗口内请求，顺序和PR39逐请求编号、类别、模型、状态、时间、Token及风险原因保持。筛选命中一个请求时仍保留整个任务；收起只隐藏正文，不从快照或导出中删除请求。任务摘要不再增加一套风险数量或成功状态，避免新增统计语义。

窗口无请求、当前条件无匹配、数据不可用沿用原来的三种提示，不创建空任务折叠项。读取失败时清空旧内容并按原逻辑禁用控件和导出，不用空报告代替失败状态。

### 展开状态与刷新

展开状态仅属于当前页面，不写localStorage、配置或服务端。无需新增全局缓存：重绘前从当前任务DOM读取已展开键，重绘后只恢复仍在当前视图中的项。

| 场景 | 明确行为 |
| --- | --- |
| 同一统计起点的自动刷新或手动刷新成功 | 仍可见的同一任务保持展开，正文更新为新快照 |
| 排序、应用阈值、恢复默认阈值 | 仍匹配的任务保持展开；使用已应用阈值刷新原因 |
| 改变筛选使任务消失，再切回 | 返回的任务默认收起，不保存隐藏任务状态 |
| 新任务或独立请求首次出现 | 默认收起 |
| 重启导致统计起点变化 | 全部默认收起，即使请求编号重用也不继承 |
| 空窗口、数据无效、读取失败、离页、退出或认证失效 | 清除旧明细和展开状态；下次读取从默认开始 |
| 仅编辑阈值草稿 | 不重算原因、不重绘任务，不改变展开状态 |

分组键使用已有数据组成：关联任务为统计起点、session、task；独立请求为统计起点和请求id。用JSON元组编码避免拼接歧义，不把匿名标识作为CSS选择器。若请求id不能稳定标识独立项，该项刷新后收起，不以数组下标关联旧项，也不新增编号修复机制。

焦点也要验收：自动刷新时如果焦点位于任务summary，且同键仍可见，恢复到该summary，避免键盘用户每次刷新失去位置；若该项被筛掉，不跳往其他任务。筛选、排序或阈值按钮触发重绘时不抢走控件焦点。不引入全页焦点管理框架。

## 3 实现边界与简洁原则

保留modelTaskUsage、selectModelTaskGroups、modelRequestRisk及modelRequestRiskText作为现有计算来源。渲染用createElement、textContent和replaceChildren，不拼接包含模型名的HTML。已有文本格式化按窗口、摘要、正文的实际复用需要拆分，移除被替代的重复循环；不为保住旧测试而长期维护第二套渲染器。

展开状态从DOM读取即可，最多处理现有256条窗口。优先一次渲染所有正文并用原生details隐藏，不预先实现懒加载、虚拟列表、缓存淘汰或通用组件库。只有发现可复现卡顿或焦点问题时才在本批范围内修正。

报告仍由buildModelUsageReport生成，格式version=1、requests、taskBreakdown和白名单保持，折叠状态不进入报告。独立校验器保持独立复算。无新增Go接口、依赖、数据库表、迁移、后台任务、重试或全局异常兜底；未知字段继续使用既有校验，不扩大到无关输入的全面加固。
