# 耳机和鼠标低电量私聊提醒

2026-10-16 已完成本机接入和部署。阈值与持久化自动化测试、整机编译通过；实际设备读取成功；部署后监控启动、程序哈希、OneBot 登录和后台 HTTP 200 已核对。没有模拟低电量向真实 QQ 发消息，低电量实际送达待自然触发验收。

机器人启动后每 60 秒读取 EDIFIER Fit900NB 蓝牙耳机和 Razer DeathAdder V2 X HyperSpeed 鼠标的电量。仅向启动配置 `zero.super_users` 中唯一的主人发私聊，不向群发送。没有聊天命令，也不调用模型。

- 首次低于 10%（整数 9% 及以下）提醒一次；到 5% 或以下再提醒一次。10% 不触发。
- 如果首次读到的电量已在 5% 或以下，只发一条紧急提醒。
- 每台设备分别去重；恢复到 10% 或以上才开启下一轮提醒。5% 附近波动不重复报警。
- 未连接、休眠、读取失败或未知电量不报警，也不清除已提醒状态。
- 发送成功后将状态保存在 `.local/battery-hub/state-<主人账号>.json`，重启后继续去重。发送失败下一轮重试；发送成功但回执丢失，或发送后进程在保存前中断，仍可能重复。状态损坏或写入失败暂停监控并记录日志。

安装（项目根目录，需要 .NET 9 SDK 和项目 Go 工具链）：

```powershell
.\scripts\build-battery-hub.ps1
.\scripts\build-windows.ps1
```

按[服务部署步骤](operations.md#已验收程序部署与回退)备份并重启 ZeroBot 后生效。读取助手位于机器人可执行文件旁 `battery-hub/BatteryProbe.exe`，需要 .NET 9 运行时。缺少助手时不启用；主人不是唯一一个时暂停，避免发给其他账号。移走助手并重启 ZeroBot 可停用。无需独立启动原电量盒子窗口。

读取实现来自用户提供的 battery-hub/Native.cs；仅集成设备查询，原桌面应用的 20% 托盘通知不用于机器人。若另行运行原桌面应用，其自身托盘通知仍按原规则。

耳机电量是 Windows 最近上报值，鼠标休眠可能暂时读不到；仅支持上述两款设备。运行日志搜索 `[battery-hub]`；运行 `.local/bin/battery-hub/BatteryProbe.exe` 可以检查实际电量，不发送消息。自动化测试用 `go test ./internal/batteryhub`，涵盖阈值、跨级、波动、断连、失败重试、设备独立状态及重启去重。真实低电量私聊送达需要实际降到阈值时验收。
