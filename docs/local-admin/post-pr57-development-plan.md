## 1 问题与目标

现有最近请求区域和完整报告已有milliseconds，但展开任务后的逐条明细只列类别、提供商/模型、结果、时间、Token及用量提示。排查某个任务中哪一次接口较慢时，需要跳转另一处查找。下一批在每条任务请求明细中显示已有接口耗时，与该请求的其他信息放在一起。

直接读取g.requests中每条请求的milliseconds，不重新计时、不按时间戳相减、不从全局平均/最大值推导，不改变采集或统计窗口。仅增加明细文本，不增加耗时筛选/排序、任务耗时总和、平均值、百分位、首字节指标、告警阈值、后端接口、存储或报告字段。历史预算900000及[其他待验收/暂缓项](remaining-acceptance.md)保持。

## 2 操作入口与显示契约

未来入口：登录后台 → 运行概览 → 模型接口请求 → AI费用风险提示 → 按任务查看用量 → 展开任一任务。沿用后台登录权限，实施并部署后刷新页面生效，无保存动作。本轮说明入口只链接规划，不宣称新行已经上线。

在每条请求的身份/类别/模型/结果/开始时间行之后、Token行之前，增加独立一行“接口耗时：N ms。”或“接口耗时：未知。”。原请求顺序和各字段保持，组摘要及四字段汇总表不加耗时。例：

```text
#1 · 客户端请求序号1 · gpt · example.invalid / demo-model · completed · 2026-10-28T12:00:00Z
接口耗时：1200 ms。
输入 100 / 命中 60 / 未命中 40 / 输出 10
提示：未触发当前用量提示
```

沿用完整报告的有效值口径：Number.isFinite(value)且value>=0为已知，其他为未知；不对字符串、null或空值调用Number进行转换。有效0必须显示0 ms，不能按truthy判断。展示使用toFixed(0)四舍五入到整数毫秒，与现有最近请求的毫秒显示精度一致；不修改原始精度或报告值。

小于0.5的有效值显示0 ms属于舍入，并非确认没有耗时。单个有效极大有限值沿用JavaScript toFixed的表示（可能为科学计数法），不人为封顶、不转BigInt、不在生产中加入额外量程校验。负数、NaN、Infinity、缺失、null、数字字符串统一显示未知，不能产生NaN ms或Infinity ms。

在任务区域共用帮助中补一句：“接口耗时来自单次模型接口记录，含响应读取、不含QQ发送；显示值四舍五入到毫秒，不代表首字节延迟或任务总耗时。”避免每条明细重复长说明。不把接口完成解释为业务成功，也不把失败/提前关闭请求的有效耗时隐藏；结果与耗时是否已知互相独立。

## 3 固定样例和边界

A为有效关联任务，包含下表前三条；B/C为独立请求。所有身份和模型使用合成值。

| 请求 | 结果 | milliseconds原值 | 页面明细 |
| --- | --- | --- | --- |
| A1 | completed | 1199.6 | 接口耗时：1200 ms。 |
| A2 | failed | 0 | 接口耗时：0 ms。 |
| A3 | incomplete | 缺失 | 接口耗时：未知。 |
| B1 | unknown | 0.4 | 接口耗时：0 ms。 |
| C1 | completed | null | 接口耗时：未知。 |

另用-1、NaN、Infinity和字符串“1200”验证未知，用1e21验证有限极大值可读且不溢出页面。这些异常值只在离线夹具出现，不修改日常数据。

筛选命中A时，展开仍显示A1/A2/A3三条耗时，包括失败的0和提前关闭的未知；不能只展示命中类别或结果的那条。切换排序只改任务顺序，不调整组内请求或耗时。现有输入/缓存/输出值及known不受影响。以完整报告原值为依据核对展示舍入，不要求报告也变成整数毫秒。

无匹配时没有任务明细，不生成孤立耗时行；空窗口、无效窗口及读取失败沿用原提示，不显示“0 ms”占位。有效组只有部分请求有耗时时逐条展示，不统计“任务已知耗时总和”，避免误把并行请求之和当墙钟时间。

## 4 生命周期、布局和报告

复用renderModelTaskView及modelTaskRequestsText。手动/自动刷新按新快照生成新明细；仍可见同键组保持展开和summary焦点，不另存耗时状态。窗口淘汰、跨启动、无匹配、失败、离页、退出和认证失效继续清理旧内容，迟到响应不能恢复旧耗时。

标识、类别、风险、结果、次数、关联、输出已知情况及排序语义保持。阈值草稿不生效，应用后按原规则重绘；重置恢复视图并收起明细，保留阈值和草稿，不因新增文本增加按钮或Tab焦点。

沿用任务明细p的white-space:pre-line和overflow-wrap:anywhere，用textContent写入。验证320/640/768/1280px明暗主题、多请求、长模型名、长标识与极大值，确保行间可辨、无水平溢出，不改字号或全局样式。只有实际发现局部裁剪时才调整CSS，不为新增一行整体改版。

完整报告仍为version=1，requests中的milliseconds保持原值或现有null归一化，taskBreakdown不新增字段。固定快照和阈值下展开/收起/筛选/排序/重置前后报告除exportedAt外一致；实际刷新checkedAt变化单独说明。用独立报告校验器验证下载，不使用显示文本重新写回报告。页面操作不增加网络、模型或QQ请求。
