# MC服务器查询与订阅

P060支持Java版服务器的状态查询。私聊或群聊、插件启用且会话允许响应时使用以下命令，将`mc.example.org:25565`换成实际地址：

- `mc服务器状态 mc.example.org:25565`：读取版本、在线人数和延迟，有图标时附带图标；连接超时会明确报错。
- `mc服务器添加订阅 mc.example.org:25565`：保存到当前私聊或群，立即发送一次状态。
- `mc服务器订阅列表`：查看当前会话订阅。
- `mc服务器取消订阅 mc.example.org:25565`：只删除当前会话的对应订阅。
- `mc服务器全局订阅列表`：仅主人私聊，生成节点使用机器人身份。
- `mc服务器订阅拉取`：手动检查已保存订阅的状态变化，未变化时可能无回复；不能把无变化等同推送失败。

订阅记录本身不会启动定时轮询。定时整合仍按用户要求暂缓，本轮不新增job定时任务。实际周期监听需待后续明确启用轮询后生效。

订阅成功、取消、列表和错误提示统一使用标准消息链，修复单个消息段直接发送导致平台兼容性问题。

### 状态变化与通知重试

状态变化的判断包括版本、描述、图标以及可达/不可达切换；仅在线人数或普通延迟数值变化不单独触发通知。0毫秒是合法可达状态，不会作为不可达保存。

每次 `mc服务器订阅拉取` 会检查状态并尝试投递待发通知。状态基线和各订阅的通知在同一数据库事务中保存；只有QQ回执同时为成功、错误码为0且包含非零消息编号时，才删除对应待发记录。发送失败时保留记录，重启后也保留，下次手动拉取可继续重试；同一收件人当前待发失败时，后续通知等待以保持顺序。已成功的收件人不会因其他人失败再次收到同条通知。

取消订阅、或群内关闭MC插件后，下次拉取会清理对应待发记录，不再投递；新订阅不继承旧订阅的待发通知。如果QQ实际已发送但回执丢失，或程序恰好在收到回执后、删除待发记录前中断，重试仍可能重复通知。该机制不新增轮询任务；定时整合继续暂缓。


### 关机时的查询与通知

服务器关机或端口不再监听时，`mc服务器状态 地址` 可能返回“连接被拒绝”（`actively refused`）或连接超时。这表示本次状态读取失败，不能仅凭提示认定机器人故障；连接被拒绝也可能由端口配置或网络规则造成。

直接状态查询不更新订阅离线计数。订阅拉取有防抖：通常连续3次连接失败后才记录并通知离线；从首次失败起超过30分钟后的拉取也可触发离线判断。成功拉取会清除未确认的失败计数。已记录离线后继续失败不重复发送同一离线变化；恢复可达时下一次拉取通知恢复，之后未变化保持静默。进程重启保留已保存的在线/离线基线和待发通知，但未确认的失败计数会重置。

实机验收可利用服务器日常关机时手动拉取，收到离线通知后再拉取确认无重复；服务器按日常安排开机后再验收恢复通知。无需为了测试开关服务器，也不启用暂缓的定时轮询。
