## 2 页面行为与状态含义

在“最近运行状态”区域新增“刷新运行状态”按钮，放在配置表单之外。已登录并成功读取配置后可用；点击只发送一次GET /api/updatewatch，不触发表单提交或必填校验。没有自动轮询、自动重试或自动检查来源。

成功响应只消费lastCheck、baseline、pending、lastError和sourceErrors。不得替换updateWatchState、revision、config、owners、bots、models，不重建下拉选项或账号候选列表，不更新未保存提示及配置错误区域。旧草稿之后保存仍使用原revision；若其他会话已保存配置，应得到原有409冲突，而不是悄悄采用新修订号覆盖他人修改。

| 内容或情况 | 显示规则 |
| --- | --- |
| lastCheck为零时间 | 显示尚未检查，沿用现有时间解释 |
| 最近检查时间 | 显示后端记录的时间，不用本次点击时间替换 |
| baseline | 当前已初始化来源数，即len(Initialized)；不解释为事件数或所有来源均成功 |
| pending | 待发通知条数，即len(Pending)；零不等于收件人已收到或新一轮检查成功 |
| lastError、sourceErrors | 保留错误含义，用纯文本展示；新快照为空时清除旧错误文本 |
| 忙碌409、网络错误或读取失败 | 保留上次运行摘要，明确“刷新未完成，显示上次读取结果”，展示接口原因，可手动重试 |
| 退出登录或会话失效 | 使用现有认证处理并清空页面会话，旧响应不能恢复旧内容 |

按钮旁说明“仅读取已记录状态，不立即检查来源或发送通知”。界面不新增运行中百分比、倒计时或正在执行任务字段，因为现有快照没有这些信息；也不通过解析错误文案推断调度状态。

| plugin/updatewatch/admin_test.go | 补只读状态/配置/备份保持、旧修订冲突、忙碌锁释放后可重试的断言 |

| README.md、progress.md、self-test.md、github-delivery.md和本计划 | 同步开发、验证、上传、合并和部署状态 |

复用updateWatchBusy、updateWatchGeneration及resetUpdateWatch，最多增加一个状态刷新在途标记。状态刷新与配置读取/保存互斥，在途时只禁用相关操作按钮；状态刷新期间输入仍可编辑。入口函数也拒绝重复请求，按钮禁用不能成为唯一约束。

离开更新监控页时使在途状态请求失效并释放本页操作状态；返回不自动重发，草稿保持。只让仍属当前代次的响应及finally改变页面，防止旧请求释放新请求的按钮。已有配置重读和保存逻辑保持，不为此更改页面导航或引入AbortController框架。

保留现有TryLock和409语义，不增加后端接口、服务端缓存、锁等待、任务历史或状态数据库。请求失败不补默认配置、不吞掉原因、不触发写操作。不照搬FTB的busy/last字段到更新监控；只借鉴其交互方式，不抽取跨插件通用模块。

## 5 验收矩阵

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 已加载配置后刷新 | 一次GET /api/updatewatch，无POST及其他业务请求，仅更新规定的运行字段 |
| A02 | 所有输入及选项已编辑 | 复选框、间隔、每日时间、模型、主人、机器人、仓库和公告原始文本保持；revision、候选选项、未保存提示和配置错误均保持 |
| A03 | 快照含新revision/config/models/owners/bots | 不应用这些字段；之后保存仍携带旧revision，409后草稿保留 |
| A04 | 空账号或非法数值草稿 | 独立刷新可用，不触发浏览器表单校验或保存 |
| A05 | 重复点击及并发操作 | 在途仅一请求；刷新时保存/重读不可用但输入可编辑，配置请求时刷新不可用 |
| A06 | TryLock忙碌409、网络错误、状态读取失败 | 旧摘要保留并标明旧结果，错误原因可读，表单及配置错误不被覆盖，结束后可手动重试 |
| A07 | 离页后返回、退出后旧响应及旧finally | 不覆盖当前页面或新会话，不错误解锁新请求；返回不自动重复刷新 |
| A08 | 零时间、来源数、待发数、错误更新 | 用后端数据展示；成功后过期错误清除，恶意HTML按纯文本显示；不虚构进度或通知送达 |
| A09 | 原配置功能回归 | 成功保存、冲突、重读覆盖草稿、切页保留、退出隔离均保持；R16 FTB页面回归也通过 |
| A10 | 接口与核心只读 | 未登录401；GET委托nil配置；临时配置、state文件（含计划/基线/队列/历史）及备份清单不变，不调用抓取/判断/发送；旧revision保存仍拒绝 |
| A11 | 视觉及操作 | 1280px/320px、明暗主题不横向溢出；按钮、错误反馈可读，键盘可操作 |
| A12 | 文档及上传 | 全量链接/锚点零错误，状态一致，原条件性清单保持；无私有数据，远端SHA一致 |

页面测试使用可控延迟响应完成顺序，不依赖固定睡眠猜测异步结束。插件测试使用独立临时路径，构造带基线、待发和历史的状态，并核对GET前后文件字节与备份清单；忙碌用显式持锁模拟并验证返回，不等待真实调度触发。来源、模型及发送一律使用桩或现有隔离设施；若不能隔离调用，则先补夹具，不调用日常实例来凑测试。
