## 1 当前状态与选择依据

更新监控目前将最近检查时间、基线来源数、待通知条数、最近错误和所有来源错误拼接到一个段落。多个来源同时失败或错误较长时，用户需要在一段文字中辨认字段及错误归属；R18部署截图中的320px页面也体现了这一问题。

现有接口已提供全部所需字段，无需新增请求或后端数据。R19仅将这些字段整理为可扫描的明细，保持R17刷新与R18草稿行为。来源真实更新、FTB私聊投递和其他条件性实机验收仍按原清单，不以界面调整替代真实验收。

依据：[运行渲染代码](../../internal/localadmin/assets/updatewatch.js)、[页面结构](../../internal/localadmin/assets/index.html)、[快照类型](../../internal/updatewatch/admin.go)、[后端快照组装](../../plugin/updatewatch/admin.go)。部署与验证基线见[R18验收](self-test.md#r18-合并部署验收)。

## 2 用户界面与字段契约

入口仍为后台“更新监控”→“最近运行状态”，原“刷新运行状态”按钮及请求反馈保持。用一个简洁的定义列表展示时间与计数，最近错误单独一段，来源错误单独列表。沿用现有面板和主题，不引入卡片组件库、图表、状态灯或折叠层级。

| 显示项 | 数据及规则 | 不作出的推断 |
| --- | --- | --- |
| 最近检查（浏览器本地时间） | lastCheck；Go零时间显示“尚未检查”，其他时间沿用zh-CN、24小时格式 | 不是点击刷新时间，不据此计算下次检查时间 |
| 已初始化来源数 | baseline，保留零值，单位“个” | 不是事件数、启用来源数或本轮成功数 |
| 待发通知 | pending，保留零值，单位“条” | 零条不等于收件人已收到 |
| 最近错误 | lastError非空时原样展示；为空显示“未记录最近错误” | 不改写为“全部正常”或“全部来源成功” |
| 来源错误 | sourceErrors中的每个键及其错误文本各一项；空或null显示“未记录来源错误” | 未列出的来源不自动标为健康，关闭来源的历史错误不擅自隐藏 |

来源键保留后端原值，不维护新的来源白名单或翻译字典；按键的JavaScript默认字符串排序固定顺序，不依赖对象插入顺序。只做展示排序，不修改返回对象。每项明确分开来源与错误正文，重复读取替换当前列表，不追加历史条目。

所有来源名和错误值用textContent等纯文本写入。保留完整文本、显式换行和长URL的可读性，使用局部换行样式防止横向溢出；不截断、不生成可点击错误链接、不自动识别解决方案或复制/导出。现有后端字段类型契约保持，不新增通用JSON校验、异常格式修复或容错框架。

## 3 状态与生命周期

| 场景 | 运行区域 | 配置表单及请求 |
| --- | --- | --- |
| 首次进入未读取 | 只显示“尚未读取”，不显示虚假的零计数或无错误结论 | 沿用原配置GET |
| 首次读取成功、保存成功、显式配置重读成功 | 用完整快照的5个运行字段替换当前内容 | 仍走原配置渲染和基线更新流程 |
| 点击独立刷新成功 | 一次替换5个运行字段，旧错误按新快照清除 | 仅原GET，不写config/revision、选项、草稿基线和摘要 |
| 忙碌409、网络或读取失败 | 保持上次完整内容，由原刷新反馈说明旧结果 | 不额外重试、不清除配置错误、不保存配置 |
| 刷新期间编辑或结束后本地撤销 | 不受草稿操作影响 | 保留R18的输入可编辑、撤销暂不可用和零请求撤销 |
| 切页及迟到返回 | 按R17 generation规则拒绝已失效结果 | 不增加请求；另一页草稿保持 |
| 退出及新会话 | 清空运行字段与来源列表，恢复“尚未读取”；旧响应不能重新填入 | 保持认证与R18基线清空行为 |

保留uw-runtime为运行内容根容器，便于现有测试定位；可增加少量子元素ID。若采用固定子节点，reset不能继续直接设置根容器textContent而删除这些节点，应明确隐藏/清空子区域；若采用每次重建子树，读取成功与reset共用清晰的单一渲染入口。实施时选择一种简单方式，不混用两套状态模型。仍以响应快照为输入，不增加另一份运行状态缓存。

只让现有uw-runtime-status承担请求反馈的role=status，避免给每个数字、错误条目都增加live区域造成重复播报。字段名称与数值用语义化结构关联，错误区有清楚标题；信息不依赖颜色区分。

## 5 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 未读取与首次成功 | 未读取时不出现假零值；成功后5类信息在正确位置，时间/计数有标签和单位 |
| A02 | 零时间、零计数、空错误 | 分别为“尚未检查”、0个、0条及未记录错误；空对象和null来源错误均可呈现，不写全部正常 |
| A03 | 多来源及列表替换 | 不同插入顺序产生同样键顺序；下次只剩一项或为空时旧项消失；不重复累计条目、不丢失未知来源键 |
| A04 | 长文本、换行和HTML样式字符串 | 文本完整可读；来源名和错误正文不创建HTML节点，不执行脚本；长URL不溢出，无截断或错误链接 |
| A05 | 时间和计数语义 | 固定浏览器时区夹具核对本地时间格式及标签；数字来自快照，不根据开关、待发数或浏览器时间推算健康和下次检查 |
| A06 | 完整配置加载与保存 | 成功读取/保存/重读均更新运行分项，原配置渲染及R18基线更新保持；失败不覆盖上次内容 |
| A07 | 独立刷新与草稿 | 修改全部11项字段后刷新含不同config/revision的快照，只更新运行分项；原revision、候选项、基线、摘要及配置错误保持 |
| A08 | 刷新失败与重试 | 409/网络/读取错误保留全部上次字段和列表；现有反馈注明旧结果，手动成功重试后替换并清除旧错误 |
| A09 | 请求在途与页面离开 | 请求互斥及刷新期间可编辑保持，撤销暂不可用；旧响应与finally不影响新请求，返回不自动发请求 |
| A10 | 退出与本地撤销 | 退出清空所有运行子项，新会话无旧错误；本地撤销零请求且保留新运行内容，另一页草稿不变 |
| A11 | 可用性 | 1280px/320px、明暗主题、多来源长错误无横向溢出；刷新按钮键盘可用，字段与数值语义关联，状态反馈不重复播报 |
| A12 | 构建、文档和交付 | 新旧专项零失败零跳过，语法与Windows构建通过，变更资源与产物一致；文档本地链接/锚点零错误、旧标题和状态一致，上传后本地/远端SHA一致 |

保留已有26项回归的行为覆盖，现有断言如“基线来源：4；待通知：2”应改为检查对应字段和值，不再依赖旧拼接标点，也不为凑数量拆出同义测试。多来源/空状态/重置和时间夹具按用户行为增加专项，不镜像实现算法。异步用例等待可观察状态或受控响应，不加固定延时猜测完成。
