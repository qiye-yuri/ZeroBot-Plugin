## 3. R5：命名模型独立请求参数

### 使用行为与取值

命名模型卡片增加“请求参数”原生折叠区。三个参数分别选择继承或自定义，默认全部继承；显示当前有效值及其来源。配置被多个入口共用时，自定义参数同时作用于这些入口，页面给出引用入口说明；需要不同参数可复用现有新增配置操作，不增加配置继承树。

| 参数 | 首版约定 |
| --- | --- |
| 最大输出长度 | 未设置时使用现有全局 MParams；自定义为 1～131072，沿用当前程序的数值上限，不承诺提供商接受整个范围 |
| TopP | 未设置时继承；自定义为大于 0 且不超过 1，有限数值。全局 0 仍按旧逻辑取默认值 |
| 推理设置 | 未设置时继承全局；自定义空串表示使用现有协议的模型默认行为；其他文字继续由现有协议适配处理，例如已有 none 关闭约定，不推断所有提供商均支持 |

温度仍来自聊天/GPT各自会话参数；系统提示词、人物、分隔符、HTTP期限、Agent动作限制、上下文预算和识图响应/描述上限保持各自现有规则。本批不引入任意 JSON 参数、厂商能力注册表或自动纠正模型参数。

### 实现与兼容

1. 在 ModelProfile 增加可选参数对象，字段缺失或 null 表示继承；数值与显式空字符串保留区别。旧配置无需迁移，读取不写库；旧模式继续使用原全局参数。
2. 复用 `ConfigRepository.UpdateModels` 的整组修订、校验和写前备份；后台视图返回参数及来源，不返回密钥。新增字段只在持久化和 HTTP 输入边界校验，内部传递已解析值。
3. 在现有 chat/modelconfig 代码中提供小型参数合并函数，运行和 R1 脚本共用；按入口解析出地址、模型、凭据和参数的一次快照。不要为了携带参数增加第二套模型客户端或额外解析整个配置。
4. 聊天、Agent、识图与 GPT/群总结各请求点使用对应所选配置参数。识图协议缓存也必须随现有配置更新失效，不能继续使用旧参数；依照已有设置代次处理在途 Agent，不增加自动续跑或重放。
5. R3 手动诊断仍固定短输出上限 128，不使用业务 MaxN；TopP 与推理设置按所选配置生效，界面/说明明确诊断输出上限是特例。R1 预检显示有效参数，隔离运行保留每个入口的独立设置，不能又映射成一组全局值。

### 工作包与验收

| 编号 | 工作与主要落点 | 完成条件 |
| --- | --- | --- |
| R5-01 | `third_party/zbputils/chat/models.go`、`cfg.go`、`modelconfig/`：结构、合并与仓库校验 | 旧/命名模式、缺省继承、空推理设置、不同入口互不串值；保存失败保持原配置 |

## 4. R6：GPT 与群总结独立模型入口

### 选择规则

命名模型入口从三类扩展为聊天、GPT、群总结、Agent、识图。GPT 和群总结新增可选配置引用，默认“继承聊天模型”；可以显式选同一配置或不同配置。不提供额外的“禁用 GPT”开关，原插件开关继续控制可用性。

| 情况 | 行为 |
| --- | --- |
| 旧配置模式 | GPT、群总结继续使用旧聊天配置和原全局参数 |
| 命名模式中 GPT/群总结字段缺失或为空 | 继承聊天入口，显示实际配置与“继承聊天”来源 |
| 显式选择有效配置 | 使用该配置及 R5 参数，不改变普通聊天或 Agent 模型 |
| 显式引用丢失或内容无效 | 保存拒绝；已有异常配置按现有错误流程报告，不以继承规则掩盖坏引用 |
| Agent/识图引用为空 | 保持原停用语义，与新增入口的继承语义区分 |

原聊天入口仍必选；删除配置前检查五个入口的显式引用，继承不额外存一份凭据或冗余引用。GPT 与群总结继续共用原 LLM 会话温度和每会话30秒额度，沿用现有系统提示词、权限、回复长度和 GPT 业务统计分类，不追加统计类别或费用估算。

### 工作包与验收

| 编号 | 工作与主要落点 | 完成条件 |
| --- | --- | --- |
| R6-01 | `modelconfig/routes.go`、`chat/models.go`：可选引用及入口解析 | 老 JSON 读写兼容；返回明确的实际配置和继承来源；无隐式失败切换 |
| R6-02 | `ai_models.go`、`ai.js`：两个下拉选择与引用检查 | 一次备份保存整组列表/路由；无迁移写入；草稿和修订行为保持 |
| R6-03 | `plugin/llm/main.go`、`request.go`：分别绑定 GPT/总结请求 | `/gpt` 只用 GPT 入口，群总结只用总结入口；引用内容、权限及额度规则保持 |
| R6-04 | `ai_probe.go`、`assets/ai-probe.js`：增加两个显式诊断入口 | 测试实际所选模型；仍只发固定短文字，不读取群历史、不执行群总结或QQ收发 |
| R6-05 | R1 脚本、模拟服务、最终构建和文档 | 预检列出五类入口；GPT用例跟随GPT引用；新增可显式选择的群总结用例验证业务链路 |

保留 CurrentConfig/EnsureConfig 的既有快照约定，增加按入口选择时不要先把聊天配置的有效参数误当作 GPT/总结覆盖值。优先在现有解析函数增加入口参数或小函数，不复制一套配置读取和回退逻辑。

R1 脚本旧的默认用例列表保持，新增 `summary` 用例须显式选择。模拟群历史使用合成文字；真实模型脚本即使使用真实提供商，也只在隔离 OneBot 中生成这组资料。对于同时选择聊天和 GPT 且路由不同的运行，隔离配置必须保留这两个选择，不能继续折叠为同一个旧字段。

验收至少包含五个不同配置指向不同模拟地址/凭据/模型及参数、两类继承、同一配置多入口、删除引用拒绝、保存后重启、旧三入口 JSON 的往返与备份恢复。核对诊断与业务统计口径；模型错误不自动重试或切换。

交付同步[命名模型](named-models.md)、[真实模型测试](real-model-test.md)、[手动测试](model-probe.md)、[会话参数](ai-conversations.md)、[模型统计](model-request-statistics.md)、[使用指南](user-guide.md)、维护及依赖补丁说明。

## 5. R7：已加载会话的配置只读核对

### 最小界面

“Agent 会话”已加载机器人和群/私聊后，增加“核对会话配置”按钮。点击读取保存状态，按项显示，不创建一个保证会回复的绿色总状态灯：

- 范围：机器人、群/私聊和编号，读取时间。
- 响应：全局、当前会话和实际来源，保持“全局或会话任一开启”规则；私聊使用运行时实际规则，不能按同号群解释。
- 相关插件：普通聊天/Agent、GPT/群总结的注册及有效开关；仅展示可确认的配置状态。
- 会话：当前 Agent 模式、@规则、概率及温度；另列 GPT/群总结共用的 LLM 温度；提示这些参数由本实例机器人共享。
- 模型：五类入口的实际模型、继承来源、参数来源和本地字段完整性；不自动调用 R3 诊断。
- 人物：继承全局或当前机器人会话覆盖，仅显示来源，不重复铺开人物正文。

在结果内复用 R2 人物/参数入口及已有 AI、插件页面导航。草稿仍由原入口处理；按钮不保存、启用插件、打开响应、调用 OneBot 或模型。不读取历史、记忆正文和密钥，不提供可分享诊断压缩包。

### 工作包与边界

| 编号 | 工作与落点 | 完成条件 |
| --- | --- | --- |
| R7-01 | 核对 `control/rule.go`、控制层 Handler、响应读取及 AI 会话取值，整理对应表 | 群和私聊标识、插件开关与响应来源同运行时一致；不凭截图推断权限 |
| R7-02 | `internal/localadmin/` 新增一个薄的只读接口，复用已有配置仓库、控制读取与入口解析 | 仅接收 botId/type/id；沿用认证、已连接机器人及会话校验；返回脱敏字段和读取版本/时间 |
| R7-03 | `assets/agent-archive.js` 及页面卡片，复用原已加载范围与请求生命周期 | 输入尚未读取不改变目标；读取中/失败/旧结果明确；切范围/退出不显示迟到结果；保留时间线和草稿 |
| R7-04 | 对应 Go/Chrome 与隔离回归，新增操作说明 | 读操作零写入/零备份/零外部调用；大整数与机器人、群/私聊隔离正确 |

控制库和 AI 配置不是跨接口事务快照：本卡显示这次读取时的值，不承诺一直最新或跨存储原子。已有读取错误应如实返回，不将失败当作关闭或零值；不为卡片新增聚合缓存、长期状态或自动轮询。实现时复用现有可用读锁，不设计跨模块全局事务。

不根据卡片判定具体发言者角色、群管理动作权限、@实际消息、命令优先级或提供商连通性。群总结仍仅适用于群；非主人私聊 Agent 的发送权限沿用原限制。若查具体消息为何未回复，继续使用现有任务与日志入口。

测试覆盖全局响应与会话响应四种组合、插件默认/覆盖来源、私聊与同号群、继承/自定义人物和模型参数、断开机器人、配置读取失败及导航草稿。第一步若发现原控制层没有可靠只读入口，仅补所需小型读取方法，不用模拟消息触发 Handler 来探测状态。

## 6. 每批测试与交付

1. 先运行对应 Go 和浏览器专项；以合成参数核对实际请求，避免只验证新增结构能序列化。将有行为价值的新增用例接入 `scripts/test-agent.ps1`，不为文档排版写镜像测试。
2. 完成源码后执行 `go generate main.go`，再运行下列统一入口；数量以本次实际结果为准，不照抄 R1～R4 的通过项。

   ```powershell
   pwsh -File scripts/test-agent.ps1 -OutputName zerobot-next-batch-validation.exe
   git diff --check
   ```

3. 保存命令、退出码、最终程序 SHA256、隔离整机结果与失败后复验记录，更新自测、进度和使用文档。三种协议的请求差异、业务统计与诊断统计、旧配置回归按实际范围记录。
4. 真实提供商/真实QQ与模拟验收分开，凭据只在本机读取；已取消的历史验收不重开。真实调用仅按已明确的用例执行，缺少凭据不妨碍离线实现与交付，不将未测写成通过。
5. 按[交付约定](github-delivery.md)显式暂存代码、测试、依赖补丁和公开说明，用中文提交到用户 origin，核对远端及PR。`.local/`、原始证据、私有配置、data 子模块运行变化及其他已有改动保留本机；上传不自动合并或部署。
