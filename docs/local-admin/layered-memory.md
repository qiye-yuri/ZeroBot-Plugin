## 使用范围与入口

适用于已启用 Agent、允许响应的群聊与私聊。普通聊天及 Agent 的普通聊天兜底仍使用原来的短上下文。本批不改变核心人物设定；可在后台原人物设置入口维护。旧文本文件必须先通过[记忆迁移](agent-memory.md#旧文件归属与迁移)明确归属，才支持分类保存；不自动迁移旧文件。

| 层次 | 内容与作用范围 | 保存方式 |
| --- | --- | --- |
| 永久知识 | 同一机器人跨会话共享的稳定知识或风格；仍可修订、停用，不覆盖核心人物规则 | 主人在当前会话明确要求共享，由 Agent 使用 `permanent` 保存；宿主拒绝普通用户保存共享层 |
| 长期记忆 | 当前群或私聊的事实、约定 | 原 `save_memory` 默认 `long`，旧托管条目仍为长期记忆 |
| 个人记忆 | 当前发言者的偏好、称呼及角色对他的关系描述 | `personal`，绑定当前触发消息作者的 QQ；事实与角色态度用不同属性记录，仅本会话可用 |
| 短期摘要 | 较早事件、承诺、待办和状态变化的有损概括 | 上下文达到软阈值后后台生成，保留最近原文；不把摘要自动升级成永久事实 |

可以在正常对话中说“记住我喜欢红茶，作为我的个人偏好”“把我喜欢的茶改成绿茶”；主人可以说“这条是所有群通用的知识，请保存为永久知识”。是否提取、使用哪个属性及语义是否准确由模型决定，口头说记住不等于成功。后台“会话档案 → 读取记忆”可在原保存会话查看类型、个人 QQ、属性、正文、修订与来源，沿用修订、启停、历史版本和来源读取操作。后台手工新增仍为普通长期记忆，本批没有分类转换表单。

永久知识的共享是显式扩大使用范围。模型被要求不共享个人事实、私聊细节或未经主人明确要求的内容；宿主硬性验证主人权限，内容是否确实是群无关知识仍依赖模型判断。共享条目的管理与修订在原保存会话进行；其他会话可召回、搜索和读取共享正文，但不会因此取得原会话聊天档案的访问权限。不同机器人始终隔离。

## 保存、更新与去重

原调用 `{"action":"save_memory","params":{"text":"本群周末讨论活动安排"}}` 保持兼容。分类示例（QQ仅为示例，必须匹配实际触发消息作者）：

```json
{"action":"save_memory","params":{"text":"该用户喜欢红茶","kind":"personal","subject":"12345678","attribute":"preference.tea"}}
```

分类保存的 `kind` 为 `long`、`personal` 或 `permanent`；带分类属性时，`attribute` 必须为小写 ASCII 字母开头、其后仅小写字母/数字/点/下划线/连字符，最长80字符。`subject` 仅个人记忆需要，使用正整数字符串。新建不传 `revision`，修改同一属性须先核对当前版本并传入它的正整数字符串。返回实际编号、修订和是否新建。

同一范围、类型、个人和属性代表同一事实槽位。正文相同复用；正文改变且版本匹配则保留编号、新增修订并更新来源，版本不匹配拒绝覆盖。停用后可以新建该属性；已有其他启用条目占据属性时，恢复旧条目被拒绝。属性名和分类在条目生命周期内固定，避免历史版本被重新解释。后台修改正文同样保留历史修订。

这是“稳定属性更新＋完全相同文本去重”，不是任意句子的语义去重器。模型给同一事实使用不同属性名、旧无结构记忆与新分类记忆重复，仍可能产生语义重复或矛盾；不能保证自动发现所有矛盾。没有自动数值好感度系统，角色态度目前保存为文本，提示要求保守变化。

## 回复前的召回

每次 Agent 模型准备阶段，从当前会话及主人已共享的永久知识中，扫描最新最多1,000条启用条目。按当前最新事件的文字词项/中文相邻双字匹配排序，当前发言者的个人条目优先、永久知识有固定加权，同分保留新条目优先。选出最多100条、总正文包装不超过30,000 UTF-8字节，排除相同范围/属性/正文重复；超长候选跳过后继续考虑能放入的条目。

本批采用本地词项相关性，不使用向量服务，不额外发出召回模型请求。它不保证理解同义词，也不扫描全部历史记忆；超过扫描窗口的条目仍可按原检索工具查询。搜索/读取会返回分类与当前版本，共享查询仍受每任务三次额度约束。停用条目不召回。旧未归属文件仍沿用原加载方式。

## 异步滚动摘要

模型请求前检查未概括记录的UTF-8字节量加既有摘要。达到历史输入预算的60%时尝试启动后台摘要；保留至少最近八个原始事件段及其后动作/响应，摘要切口落在事件段边界。每轮最多提交48,000字节的新历史、最多扫描2,048条前缀记录，并带上上一版摘要；有积压时后续请求继续推进，不跳过未概括部分。摘要使用现有 `Summary` 模型路由，未独立配置时按原路由规则继承；输出上限2048 tokens，本地拒收空白、无效UTF-8或超过8192字节的结果。

同一机器人/会话只允许一个摘要任务，结束后一分钟内不再次启动；只有后续 Agent 请求触发下一轮，没有额外常驻定时器。后台模型HTTP请求最长60秒，费用计入现有GPT/总结类别及会话统计。模型失败、超长输出、配置重载、重置或存储失败不会覆盖旧摘要，也不会删除原始档案。失败写入不含正文的日志。

成功摘要只替换其明确覆盖前缀在模型输入中的位置；生成期间新增记录仍保留。摘要持久化，重启后继续使用；上下文重置后旧摘要不再注入，旧在途结果无法复活它。完整聊天档案仍保留，检索权限与重置边界不变。

硬阈值沿用历史字节预算：超出时只加载能容纳的近期原文，并保留有效摘要、标注缺口。摘要未完成时不等待，不把被裁掉但尚未摘要的内容假装记得。字节预算是保守容量代理，不是精确token统计；现有DeepSeek地址采用900,000字节，其他地址65,536字节，人物设定、记忆与输出另外占用上下文。异常超大单个事件可能阻塞摘要前缀推进，仍回退到原有裁剪及检索。

## 存储、备份与回退

在每机器人现有历史SQLite库新增 `agent_memory_layers` 和 `agent_summaries`，不删除或重写旧记忆表。分类正文与修订使用既有事务及来源；摘要按会话保存覆盖序号、重置序号和时间。部署前按[运行维护](operations.md)停机备份程序及完整 `data/aichat`（含WAL/SHM），核对文件哈希。不能仅备份配置。

旧程序可忽略新增表并继续读取旧格式记忆正文，但不会使用分类、共享和摘要；回退程序保留新数据，勿用旧数据库覆盖部署后新增聊天。若旧版本修改了正文，新版本重新启用时仍按保留的分类解释，需由所有者核对。
